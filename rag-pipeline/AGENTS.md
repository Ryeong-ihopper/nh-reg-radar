# NH 광고심의 RAG 작업 불변 원칙

이 저장소에서 새 세션을 시작하는 모든 에이전트는 작업 전에
`docs/handoff-current.md`, `docs/decisions.md`,
`docs/evaluation-splits-current.md`를 읽는다.

## 1. 규칙 출처

2026-09-09 사용자 결정이 아래 과거 v2 단일 입력 제한보다 우선한다. 지정된 일반
템플릿 HWPX 자체를 주 심의 기준으로 사용하며, 항목은 v2 매핑 없이 독립 ID·원문
참조·필수여부·기재요령을 가진다. v2는 세부 조건과 법령 근거를 보강한다. 예시문구의
완전일치를 의무화하지 않고, 심의사례 1~3의 개별 판단·판단근거는 운영에 넣지 않는다.
출처 동결에는 템플릿과 v2를 모두 포함한다. 사례별 하드코딩·답지 누수 금지는 유지한다.

- 판정 규정의 단일 입력은 `NH_광고심의_에이전트_규제목록_v2.xlsx`다.
- 실행 코드는 v2의 적용상품·점검문구·판정기준·입력요건·판정유형을 읽어 일반
  판정 조건을 구성한다.
- 광고 ID, 파일명, 상품명, 특정 광고의 숫자·문장, 농협 사례 정답, 연구원 O/X를
  판정 규칙이나 검색 사전에 하드코딩하지 않는다.
- 연구원·수요사 피드백이 v2 문언을 바꾸는 해석이라면 코드부터 고치지 않는다.
  먼저 v2의 새 버전에 일반 기준으로 반영·승인된 뒤 그 버전에서 규칙을 다시 만든다.
- v2 `신규규칙후보` 시트의 T 항목은 사용자가 판정 규칙으로 사용 가능하다고
  확정했다. `O`는 적용 템플릿의 필수 규칙, `△`는 기재요령의 조건이 확인될 때만
  필수인 조건부 규칙으로 처리한다.

## 2. 사례 피드백 처리

실제 사례는 일반 규칙을 발견하는 개발 자료로 사용할 수 있다. 단, 피드백마다 아래
네 유형 중 하나로 먼저 분류한다.

1. **정답 매핑 오류**: 해당 사례 gold만 수정한다. 런타임 코드는 바꾸지 않는다.
2. **규정 해석 보완**: 규제목록 v2의 일반 문언을 연구원·수요사가 수정·승인한 뒤
   모든 해당 사례에 같은 조건으로 적용한다.
3. **일반 구현 오류**: v2에 이미 적힌 조건을 코드가 잘못 실행한 경우에만 공통
   파서·검색·판정 함수를 고친다.
4. **근거 불충분/해석 불명**: 규칙을 추측해 만들지 않고 `UNDETERMINED` 또는 사람
   검토로 보낸다.

일반 코드로 반영하려면 규정 근거, 적용 범위, 일반 술어, 반례, 필요한 외부입력을
기록한다. 출발 사례 외의 양성·음성·경계 테스트를 함께 만들어야 한다. 출발 사례만
통과시키는 수정은 금지한다.

예: 특정 사례의 대표 정답 규칙을 `D-177`에서 `T-113`으로 고치는 것은 그 사례의
gold 수정이다. 모든 광고나 모든 `D-177`을 `T-113`으로 치환하는 코드는 금지한다.

## 3. 답지·운영·평가 분리

- 공통 판정기는 항상 `광고 증거 + 규칙 → 적용성·판정·근거` 계약을 사용한다.
- 답지 생성은 적용 가능 규칙을 넓게 전개하는 silver 생성 절차다. 사람 O/X 전에는
  gold가 아니다.
- 운영 검색은 정답 item_id를 받지 않고 규칙을 발견해야 한다. 답지 생성의 전수
  전개 결과로 검색 Recall을 대신 측정하지 않는다.
- 운영은 미해당 음성 표본을 추가 수집하지 않는다. 후보의 적용조건을 검사해 확인된
  미해당은 본판정·운영 결과에서 제외하고 이유만 감사 기록에 남긴다. 적용성 미확정,
  입력 부족, 모델 오류는 미해당이 아니므로 숨기거나 정상 완료로 치환하지 않는다.
- 답지 생성에는 적용성 분류의 오류를 확인하기 위한 미해당 표본을 유지할 수 있다.
- 예측을 먼저 저장하고 해시를 고정한 뒤 별도 평가기가 gold와 조인한다. 검색·판정
  프로세스는 gold·O/X·사례 사유 경로를 읽지 않는다.
- 사례 피드백으로 코드가 바뀌면 그 사례와 같은 답지 세트는 즉시 dev/regression이
  된다. 수정 효과는 그 세트에서 회귀 확인하고, 일반화는 새 holdout에서만 잰다.

## 4. 10건 피드백 반영 절차

10건의 X를 한 줄씩 코드 조건으로 옮기지 않는다. 먼저 오류를 정답 매핑·규정 해석·
일반 구현·불확실성으로 묶고, 같은 원인의 반복만 일반화 후보로 만든다. v2 근거가
없는 후보는 질문으로 돌린다. 일반 변경을 적용한 뒤 10건은 회귀셋으로만 사용하고,
성능은 별도 미관찰 광고에서 확인한다.
