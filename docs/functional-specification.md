# 기능명세서

## 템플릿 단독 심의 — 2026-09-17

신규 웹 심의는 선택한 일반 템플릿 전체 항목만 사용한다. v2 적재·검색·판정·법령 보강과 ES 준비 대기를 제외하고 BGE 원문 검색·Gemma 판정은 유지한다. --source-policy의 기본값은 template-only이며 템플릿이 없거나 선택 항목이 없으면 거부한다. 구 실행 재현은 template-plus-v2를 명시한다. 작업에 정책을 저장해 재시도 시 기준을 유지한다. 원본 기재요령과 등록일 기준 심의, 전체 항목 처리 감사는 유지한다. 선택적인 근거 법령 칼럼은 제공된 참조만 보존하며 새로운 의무를 생성하지 않는다.

## 산술 검증과 비용 고지 의무의 구분 — 2026-09-16

일반 구현 오류: 수수료 면제 고지 규정의 계약기간 `합산`을 산술 불일치 의무로 취급하면, 계산 오류를 주장하지 않은 고지 누락 응답에도 수치 증명을 요구하여 유효한 판정을 거부한다. 산술 증명 검증은 선택된 O 의무(없으면 규정 판정기준)에 수치 연산과 정합성·일치·검산 등 수치의 정확성 확인이 함께 명시된 경우에 적용한다. 기간 합산 제한, 산식 기재, 면제 대상 고지 자체에는 계산 불일치 증명을 요구하지 않는다. 실제 산술 불일치 주장은 인용 수치와 재현 가능한 검산을 계속 요구한다.

출처는 규제목록의 비용 고지 의무와 별도 수치 정합성 의무다. 범위는 모든 광고의 원문 주장 검증이며 광고·상품·항목 ID를 분기 조건으로 사용하지 않는다. 반례는 명시적인 합계 정합성 검사, 경계는 하나의 규칙에 분리된 복수 O 의무다. 추가 외부 입력은 없다. 수정 이전에 잘못 거부한 응답은 원응답과 오류 기록을 보존하고 전체 출력 계약을 다시 검증한 별도 사본으로만 복구한다. 이미 유효한 다른 판정은 변경하지 않는다.

## 검색·판정 전 단계 장애 복구 — 2026-09-16

운영 실행기는 파싱 전과 RAG 제출 전에 Elasticsearch, BGE, Gemma의 준비 상태를 확인한다. 직접 HTTP endpoint와 DGX SSH 폴백을 모두 지원하며, BGE는 CUDA·모델명·벡터 차원·최대 길이 계약을, Gemma는 설정된 모델 ID를 확인한다. 일시 중단은 최대5분 동안 취소 가능하게 기다리고 잘못된 응답·모델 불일치는 즉시 설정 오류로 처리한다.

Gemma 전송 오류는 JSON·판정 계약 오류와 분리한다. 동일 논리 요청을 최대3회까지만 재시도하고 auto-split하지 않는다. 일시적인 ES/BGE/Gemma 연결 장애는 같은 RAG job의 다음 attempt로 자동 재큐잉한다. 이전 Gemma 체크포인트는 입력, 모델, runner와 판정 관련 코드 해시가 모두 일치할 때만 사용한다.

웹 프로세스가 재시작되면 진행 중 review와 기존 RAG job에 다시 연결한다. 동일 review의 파서 결과는 광고 ID, 사용자 선택 템플릿, 저장 원본 체크섬이 모두 일치할 때만 재사용한다. 최종 결과는 운영 결과 계약이 유효하고 요청한 모든 쌍의 판정이 있을 때만 통계·보고 단계 실패에서 완료로 보존한다. 입력 오류와 출력 누락은 성공으로 승격하지 않는다.

## 완료 후 통계 장애와 제목만 인용한 판정 — 2026-09-16

물리 모델 호출에는 독립 call_id를 기록하며 재시도·분할·원문 분리 검토가 같은 request_id/attempt를 사용해도 충돌하지 않는다. 복제된 조상 호출은 한 번만 집계한다. 예전 기록의 동일 키에 서로 다른 내용이 있으면 원기록은 보존하고 통계 정확도를 미확정으로 표시한다. 이미 검증·저장한 판정은 통계 계산/저장 오류 때문에 실행 실패로 바꾸지 않는다. 실제 모델 출력·근거·스키마 오류는 이 경계에 포함되지 않는다.

`scripts/repair-operational-metrics.py`는 중지된 로컬 웹의 실패 기록이 해당 통계 충돌이고, 저장된 결과의 광고·요청 쌍이 모두 일치할 때만 상태 백업 후 완료 표시와 결과 투영을 복원한다. 검색·파서·모델 호출이나 원판정 변경은 없다. 기본 실행은 읽기 전용 점검이며 `--apply`가 있어야 반영한다.

템플릿 본문 의미요소를 요구하는 항목이 출처 구분명 또는 짧은 명사 접두어가 붙은 제목만 인용하면 충족/위반 관찰의 근거로 인정하지 않는다. 다른 본문 표현은 예시 완전일치 없이 허용한다. 제한된 재시도 후에도 제목뿐이면 판단불가로 격리하며 독립적으로 검증된 다른 위반은 유지한다. 저장 결과의 제목 단독 인용도 화면 투영에서 보류하고 원래 모델 판정은 보존한다. 이것은 의미 판정 전체를 보증하는 검사가 아니다.

## 검색 연결 사전 확인 — 2026-09-16

운영 웹 실행기는 파싱 시작 전과 RAG 요청 직전에 설정된 Elasticsearch 주소를 확인한다. 연결 거부·일시적 게이트웨이 오류는 즉시 실패로 끝내지 않고 최대 5분 동안 취소 가능한 복구 대기로 표시한다. 다른 서비스의 응답이나 인증 거부는 검색 정상으로 인정하지 않는다. 대기 한도 초과는 검색 연결 오류로 명시하며 기존 파싱 결과와 실패 기록을 보존한다. 부모 검토의 유효한 파싱 결과는 재분석에서 재사용한다.

모델의 제한된 계약 재시도 후에도 관찰 주장과 인용 원문 줄이 일치하지 않으면 해당 요건을 판단불가·사람 확인으로 격리한다. 유효한 다른 판정과 독립적으로 검증된 위반은 보존한다. 스키마 오류·미등록 항목·실행 오류는 판단불가로 바꾸지 않고 실패로 유지한다. 호출 통계는 일반 판정과 별도 원문 확인 호출을 서로 다른 물리 호출로 집계한다.

## 템플릿 기재요령 보존과 관측 매체 분류 — 2026-09-16

표시방식 택일 통합은 각 방식의 예시와 기재요령을 함께 criterion 및 의무 계약에 전달한다. alternative_members 감사 필드에만 보존하고 실제 의무에서 생략하지 않는다. 선택한 한 방식의 요건을 확인하며 서로 다른 방식의 조건을 모두 강제하거나 예시를 완전일치 의무로 바꾸지 않는다.

관측 매체 분류에서 `대비`는 배경·명암 등 시각 문맥이 있을 때만 레이아웃으로 본다. `부대비용`이나 `전년 대비` 같은 텍스트를 부분문자열만으로 시각 항목으로 제외하지 않는다. 실제 색상·글자 크기·줄배치 요건은 계속 사람 검토다.

오류 분류는 일반 구현 오류이며 근거는 템플릿 원문 보존 및 사용자 좌표 전용 계약이다. 모든 템플릿에 적용하며 광고별 ID·수치·정답 조건은 없다. 일반 술어는 명시 방식 구성원의 기재요령 보존 및 시각 문맥을 가진 대비다. 반례는 서로 다른 방식의 안내, 빈 안내, 일반 비용·수치 비교 및 실제 배치 안내다. 외부입력은 기존 템플릿 원문뿐이다. 검토 기준일 전달·복합 텍스트/시각 요건 분리·조건 의미 검증까지 해결한 변경은 아니다.

## 모델 조건 점검 배열의 구조 계약 — 2026-09-16

원문 condition_contract의 적용조건/검토조건 개수를 구조화 출력 JSON Schema의 배열 하한·상한에도 반영한다. 묶음 내 최소~최대 개수 범위로 제한하므로 조건0개와 여러 조건이 섞인 요청도 유효하다. 단일 규칙 재처리에서는 정확한 개수를 요구한다. 조건 ID/순서/근거의 최종 검증은 유지하며, UNDETERMINED와 빈 의무 점검을 허용한다. 의미 판정이나 누락 조건의 내용을 코드로 만들어 넣지 않는다.

## 빈 파서 산출물과 재사용 경계 — 2026-09-16

파서 산출물 존재와 심의 가능한 원문을 구분한다. P1/P3 계약·줄 소유권 검증을 통과하고 최종 선택 원문이 있는 영역이 하나 이상 있어야 성공 자산 또는 부모 재사용 대상으로 인정한다. 빈 원문·공백 원문·영역 없는 산출물은 실패 자산 단독 재시도 대상이며, 부모 재사용은 중단하고 새 파싱을 수행한다. 일부만 읽혔거나 좌표가 없는 유효 원문은 기존 판독/시인성 가드와 함께 유지한다.

일반 구현 오류 수정이며 광고 ID·확장자·상품명별 예외나 새 판정 규정은 없다. 근거는 기존 광고 원문→규칙 판정 입력 계약이다. 일반 술어는 검증된 선택 원문 영역의 존재, 반례는 부분 판독 또는 좌표 없는 디지털 원문, 외부입력은 P1/P3뿐이다. 파일만 생성된 unreadable 산출물을 성공으로 넘기던 동작을 고친다.

## 판독 가드 이후 활성 근거 — 2026-09-16

판독 가드가 철회한 판단의 인용은 활성 근거의 텍스트·ID·줄·bbox에서 함께 제외한다. 적용성 게이트 보류는 해당 결론의 인용을 제거하고, 일부 요건 보류는 나머지 독립 관찰 근거를 유지한다. 가드 없는 판단불가의 인용을 일괄 숨기거나 검색 후보로 대체하지 않는다. 기존 저장 판정·원응답·가드 이전 결과는 그대로 보존하고 조회 시 비변경 투영을 적용한다.

오류 분류는 일반 구현 오류다. 규정 근거는 일반 템플릿/v2 의무와 기존 원문 근거 계약이며 해석을 추가하지 않는다. 적용 범위는 가드 이슈가 있는 모든 규칙이다. 일반 술어는 가드가 철회한 게이트/요건의 인용 여부이며 반례는 독립 위반 근거·가드 없는 판단불가다. 외부입력은 기존 가드 이슈·요건별 인용·정본 줄/좌표뿐이다. 추가 모델 호출이나 파서 라벨 재심사는 하지 않는다.


## 명시 표제와 단순 언급의 구분 — 2026-09-16

항목명으로 시작한다는 이유만으로 일반 문장·메뉴를 명시 표제로 확정하거나 모델의 다른 라벨을 삭제하지 않는다. 선택 템플릿의 항목명/기존 별칭과 정확히 대응하는 표제, 단위가 붙은 표제, 명시 구분자 뒤 값이 이어지는 필드만 기존 표제 우선 경로에 들어간다. 심의번호는 기존 표식 바로 뒤 식별 숫자가 이어지는 형식을 보존하며 번호의 유효성이나 심의 적합성을 확정하는 규칙으로 사용하지 않는다. 단순 언급은 의미 모델에 맡기며 이 수정이 모델 의미 정확도를 보증하지 않는다.

이는 기존 사용자 템플릿·원문 접지 계약을 잘못 실행한 일반 구현 오류 수정이다. 특정 광고의 이름·숫자·정답을 추가하지 않는다. P1/P3의 원문·줄·좌표와 사람 검토 경계를 유지한다. 양성 표제/단위/번호와 음성 일반 문장/메뉴, 모델의 다른 유효 라벨 보존을 합성 검사한다. 현행 재사용 정책은 `user-template-labeling-v5`이며 v4 이하 부모 P1/P3는 재사용하지 않는다. 독립 평가는 미관찰 광고와 사람 확정 정답을 확보한 뒤 수행한다.


## 복수 표제의 하위 라벨 보존 — 2026-09-16

선택 템플릿의 구분값을 원문 줄에 붙이는 기존 계약에서, `|`·전각 세로줄·세미콜론으로 나뉜 한 줄에 여러 명시 표제가 있으면 해당 라벨을 모두 보존한다. 첫 표제 하나만으로 다른 유효 라벨을 지우지 않는다. 각 필드는 기존 표제 인식 기준으로 확인하고, 근거 없는 라벨·저신뢰 원문을 허용하지 않는다. 공개 P1/P3는 동일한 줄 참조를 여러 라벨이 사용할 수 있으며 원문을 새 줄로 분할하거나 좌표를 추정하지 않는다. 사용자 확정 템플릿과 ADR-0085의 근거 보존을 실행하는 일반 구현 수정이다. 특정 광고·회사·상품을 새 사전으로 추가하지 않는다. 재사용 정책 v4는 이전 후처리의 P1/P3를 새 심의에서 재사용하지 않는다.

## 라벨 의미·원문 품질 보완 — 2026-09-16

하위 라벨 모델에 줄별 OCR source/confidence와 기존 저신뢰 판독 기준의 사람 확인 표시를 전달한다. 명확한 디코딩 손상 또는 기존 설정 기준 미만 OCR 줄에는 모델 신뢰도가 높거나 명시 표제가 있어도 라벨을 확정하지 않는다. 원문과 독립적으로 읽을 수 있는 다른 줄의 라벨은 보존한다. 템플릿 기재요령의 240자/2항목 절단을 제거하고 모든 기재요령을 전달한다. ### 운영 결과 투영·호출 계측

- ADR-0085에 따라 파일 병합은 줄·셀·표·관계 ID와 명시 참조를 자산별로 함께 변환하고 문서/페이지 관계, 원본 파일·페이지를 보존한다. 관계 대상이 없으면 새 줄을 만들지 않고 검색 감사에 보류한다.
- 판정 입력은 표 구조와 원문 관계를 보존한다. 모델에는 제공된 정본 줄에 연결된 셀 좌표·병합 범위·헤더/각주와 관찰 관계만 전달한다. 미연결 셀 OCR은 인용 원문으로 승격하지 않고 사용 불가 구조 수를 기록한다. 자산 별칭은 파일별 범위를 구분하며 상품/시점 동일성을 추정하지 않는다.
- 규칙→광고 근거 검색은 두 글자 한국어 핵심어를 보존한다. 기존 검색 근거와 명시 관계를 먼저 회수한 뒤 출처 조건·의무·비고별 질의로 근거를 보충하고 추가 관계를 한 차례 확장한다. 전체 추가량은 기존 context 문자 예산 안에 둔다. 문장별 검색 질의는 새 의무 ID가 아니며 예시·예외를 의무로 바꾸지 않는다. 매칭 없음/예산 보류는 부재 판정이 아니다.
- 보완 규칙 재정렬은 중복을 제거한 모든 발견 문맥을 각각 평가하고 최고 점수로 후보를 재정렬한다. 문맥별 점수와 근거를 남기며 임계값으로 후보를 삭제하지 않는다. 서버 점수 누락/비정상 수치는 실패로 처리한다. 호출량 증가와 장문 입력 제한은 별도 측정 대상이다.
- 적용성·개별 의무의 의미 판단과 전체 결론 검증은 분리한다. 모든 범주에서 확정 VIOLATED 의무가 있으면 다른 의무 UNKNOWN만으로 전체 위반을 숨긴 응답을 거부한다. 해당 의무 자체의 조건·예외 불확실성은 계속 판단불가이며 충족·위반을 새로 만들어 보정하지 않는다.


- 검색 근거 문맥은 명시적으로 관찰된 표·조건·각주 관계를 추가 회수 문서에서도 이어서 검사한다. 같은 광고/상품 범위와 기존 문자 예산을 유지하고, 추정 관계·다른 상품·누락/모호한 참조는 보류한다. 예산이 모자라면 연결 그룹 전체를 보류하고 원래 검색 근거를 보존한다. 순환은 중복 회수·중복 비용 없이 종료하며 전체 의미 근거를 다 찾았다고 승격하지 않는다.

- `rag/evaluation/retrieval_separation.py`는 검색 산출물 두 파일을 먼저 봉인하고 해시 검증 후 별도 참조를 읽는다. 템플릿/매핑 열거와 보완검색, 요청과 예산/입력 보류를 구분한다. 근거 평가는 해당 규칙 evidence_scope 안의 줄 ID·문장·판독 확인 상태를 따로 확인한다. 다른 규칙의 배치 문서, 같은 ID의 오독, 다른 출처의 같은 문장을 정확 근거로 세지 않는다. 진단 추가 줄은 새로운 출처이므로 기존 입력과 ID 회수율을 직접 비교하지 않는다. 고객 gold/holdout 또는 판정 정확도 평가가 아니다.

- 판정 출력은 기본 요청별 JSON Schema로 필수 필드·응답 수·허용 별칭을 제한한다. 적용조건/의무의 의미 검증과 판독 품질 가드는 별도 유지한다. 미지원 서버는 `NH_JUDGE_RESPONSE_FORMAT=json_object` 명시 설정만 허용하며 자동 강등하지 않는다. 모드·출력 계약 해시를 체크포인트에 포함하고 실제 모드를 호출 감사에 남긴다. Spark 검증과 고객사 H200 미검증을 구분한다.

- 부분 읽기는 전체 부재/완전성 주장을 제한한다. 선행조건 확정 및 해당 필수 요소의 명확한 직접 근거가 있는 경우, 다른 영역이 PARTIAL이라는 이유만으로 문구 존재 판정을 금지하지 않는다. 의존 근거 자체가 불확실하거나 필요한 레이아웃/외부 입력이 없으면 사람 검토한다. 프롬프트도 이 범위를 명시하며 빈 결과 객체 대신 유효한 기권 계약을 요구한다. 모델 준수율 완전 확보를 뜻하지 않는다.

- 적용조건 계약 v2는 규칙 원문 기준과 승인 가이드의 명시 의무에 O ID를 부여한다. 적용성 확정 후 의무별 검사 누락·중복을 거부하며 일부 UNKNOWN인 상태를 전체 충족으로 확정하지 않는다. 원문 비고의 적용범위를 조건 계약에 보존한다. 복합 문장의 완전한 의무 분해나 의미 정확도 보장을 뜻하지 않으며 구 계약 결과를 자동 승격하지 않는다.

- 판독 검수 표시·읽기 미완료는 법규 위반이 아니다. 해당 불확실성에 의존한 확정은 `UNDETERMINED`와 사람 검토로 전환하고 원래 모델 응답·변경 사유를 감사 기록에 보존한다. 독립적으로 확인된 위반은 유지한다. 이 조치는 잘못된 ID/형식 검증을 우회하지 않으며 재시도와 구분한다.
- 미기재 확정에는 전체 읽기와 전체 검색 문맥이 필요하다. 다른 규칙의 명확한 관찰 근거는 광고 일부의 검수 표시만으로 일괄 차단하지 않는다.

- 템플릿 동명 항목의 예시를 각각 표시하고 미기재 주장과 원문 참조 실패를 구분한다. 판정 의미는 바꾸지 않는다.
- 원본/규정 독립 스크롤·확대·페이지 이동·자동이동 제어는 새 모델 호출 없이 동작한다.

- 저장된 판정·요청의 광고/상품 범위로 화면과 JSON 내보내기를 동일 투영한다. 처리 실패를 모델의 판단불가로 생성하지 않는다.
- 원문 ID와 실제 좌표를 사용하며, 줄 정렬이 입증되지 않은 VLM 선택문은 `REGION`으로 명시한다. 미배정 줄 좌표도 보존한다.
- 결합 광고의 전역 페이지와 개별 파일의 원본 페이지를 분리한다. 좌표가 없거나 잘못된 경우 다른 파일의 유사 문장으로 대체하지 않는다.
- 다른 템플릿 범위, 입력/구조 보류, 보완검색 실행 한도 보류를 구분해 표시·내보낸다.
- 모델 호출 횟수·누적 처리시간은 재시도와 분할 전 실패 호출까지 포함한다. 최종 응답 행 수와 실제 호출 수를 구별한다.

### 운영 임베딩 무결성

검색 목록과 판정 규칙 정의의 ID 집합은 일치해야 한다. 원래 fine 질의를 유지하면서 동일 출처의
전체 부모 문맥을 예산 안에서 추가 검색할 수 있으며, 합성 질의는 원문 인용 대상으로 사용하지 않는다.
카테고리별 검색/재정렬/최종 후보 자리를 보장하고 잔여 자리를 순위대로 배분한다. 최종 예산 탈락은
미해당과 구분해 감사 기록한다. 예산 배분은 적용조건이나 위반 판단을 대신하지 않는다.

운영 규칙 검색은 예금·대출·전체 적용 범위에서 시인성 항목도 발견할 수 있어야 한다.
입력 부족은 검색 전 삭제가 아니라 후속 관측 준비 게이트에서 보류한다. 현재 작은 규칙
집합은 BM25와 정확 코사인 검색에 같은 범위 필터를 적용한다. 내용/벡터가 바뀌면 별도
인덱스를 사용하고, ES 일부 적재·시간초과·shard 실패를 정상 검색으로 처리하지 않는다.

운영 BGE 서비스는 실제 차원과 최대 입력 길이를 보고하고 클라이언트 계약과 일치해야 한다.
벡터의 행수·차원·유한수·정규화를 검증하며, 손상 캐시는 기록 후 재생성하고 무효 모델 응답은
저장하지 않는다. 캐시의 원문·행순서·벡터 해시와 원자적 저장을 확인한다. 동일 문구의 계산만
중복 제거하고 서로 다른 원본 위치·규칙 ID는 보존한다. 상세 검증 범위는
[설계 검토](pipeline-design-review-current.md)의 임베딩 절을 따른다.

### 템플릿 원문 기반 심의 전환 (2026-09-09 사용자 확정)

독립 RAG는 일반 템플릿 HWPX를 주 기준으로 사용하고 v2는 일반 규칙·법령 근거를 보강한다.
`review-template-catalog-v1` 항목은 v2 ID 매핑 없이 source SHA·표·행·셀 참조를 가진다.
구분·필수여부·기재요령·예시를 별도 필드로 제공하며 예시의 완전일치를 강제하지 않는다.
중첩 표의 부모 연결, 셀 병합, 반복 문단, 스타일 참조를 보존하고 구조 오류 행은 보류한다.
고객은 상세 상품군만 선택한다. 내부 템플릿은 시스템이 연결하며 고객용 선택란을 추가하지 않는다.
`--template-hwpx`/`NH_TEMPLATE_HWPX_PATH` 경로는 독립 TPL 항목을 모델 요청과 결과에
전달한다. v2 C/D의 보완 검사는 유지하며 v2 T행과 원문 항목을 중복 전개하지 않는다.
기존의 v2 전용 설명은 템플릿 미설정 호환 경로에 한정한다. 원본 표의 일부 구조 보류와
실제 Gemma 실행 검증은 [인수인계](handoff-current.md)의 현재 상태를 따른다.

### RAG 코드 기능 경계

RAG 내부 구현은 `rag/contracts`, `rag/parsing`, `rag/templates`, `rag/judgment`, `rag/api`로
분리한다. 실행 가능한 CLI는 `rag-pipeline/tools`에 유지하되 업무 구현을 중복 보유하지
않는다. `rag-pipeline/legacy`는 운영 코드에서 import할 수 없다. 바깥 저장소의 구형
`rag/`와 `schemas/`도 현행 파이프라인의 import·스키마 탐색 대상이 아니다.

본 기능명세서는 PoC 시스템 구축을 위한 기능 범위를 정의한다.

현재 별도의 화면기획서가 확정되지 않았으므로, 본 문서에서는 화면의 상세 UI 배치가 아니라 다음 사항을 중심으로 정의한다.

## 1.3 권한 매트릭스

인증/인가 방식은 [ADR-0036: PoC 자체 JWT 인증 및 SSO 전환 가능 인가 구조](adr/ADR-0036-jwt-auth-sso-ready-authorization.md), [ADR-0055: API 인가 범위 및 부서 Scope 판정 기준](adr/ADR-0055-api-authorization-scope-policy.md), [ADR-0056: JWT 세션 및 토큰 수명 정책](adr/ADR-0056-jwt-session-token-lifetime-policy.md), [ADR-0057: 브라우저 보안 정책, CORS/CSRF 및 보안 헤더 기준](adr/ADR-0057-browser-security-cors-csrf-headers.md), [ADR-0058: 로그인 실패 제한, 계정 잠금 및 비밀번호 정책](adr/ADR-0058-login-failure-lockout-password-policy.md)을 따른다. PoC는 자체 로그인 + JWT를 사용하고, 권한은 role + department scope 기준으로 검증한다.

| 기능 | 상품부서 담당자 | 준법감시 담당자 | 기준 관리자 | 시스템 관리자 |
| --- | --- | --- | --- | --- |
| 광고물 등록 | 가능 | 가능 | 불가 | 가능 |
| 광고물 삭제 | 불가 | 불가 | 불가 | 가능 |
| AI 검토 요청 | 가능 | 가능 | 불가 | 가능 |
| AI 검토 결과 조회 | 본인/부서 건 | 전체 또는 권한 범위 | 불가 | 전체 |
| 수정 권고 확인 | 가능 | 가능 | 불가 | 가능 |
| 심의 의견 초안 생성 | 제한 | 가능 | 불가 | 가능 |
| 검토 리포트 출력 | 가능 | 가능 | 불가 | 가능 |
| 기준 DB 등록/수정 | 불가 | 제한 | 가능 | 가능 |
| 검증 데이터셋 관리 | 불가 | 가능 | 가능 | 가능 |
| 사용자/권한 관리 | 불가 | 불가 | 불가 | 가능 |
| 시스템 로그 조회 | 불가 | 제한 | 불가 | 가능 |

권한 범위 밖 데이터 처리 기준은 다음과 같다.

| API 유형 | 처리 기준 |
| --- | --- |
| 목록 조회 | 권한 범위 밖 데이터 숨김 |
| 단건 조회 | 권한 없으면 `403 FORBIDDEN` |
| 다운로드/미리보기 | 권한 없으면 `403 FORBIDDEN` 및 감사 로그 기록 |
| 기준자료 변경 | 기준 관리자 또는 시스템 관리자만 허용 |
| 사용자/권한 관리 | 시스템 관리자만 허용 |

세션과 토큰 처리 기준은 다음과 같다.

| 항목 | 처리 기준 |
| --- | --- |
| 로그인 | access token 발급, refresh token hash 저장 |
| 토큰 갱신 | refresh token cookie 검증 후 access token 재발급 및 refresh token rotation |
| 로그아웃 | 현재 refresh token revoke |
| 권한 변경 | refresh token 전체 revoke 및 `auth_token_version` 증가 |
| 사용자 비활성화 | refresh token 전체 revoke, 이후 보호 API 접근 차단 |

브라우저 보안 처리 기준은 다음과 같다.

| 항목 | 처리 기준 |
| --- | --- |
| CORS | 환경별 허용 origin만 허용하고 wildcard origin 금지 |
| Cookie 기반 인증 API | refresh/logout 요청의 Origin 또는 Referer 검증 |
| Cookie 속성 | refresh token cookie에 HttpOnly, Secure, SameSite 적용 |
| 일반 업무 API | Bearer access token 기반으로 호출 |
| 보안 헤더 | 공통 미들웨어 또는 reverse proxy에서 기본 보안 헤더 적용 |

로그인 보호 기준은 다음과 같다.

| 항목 | 처리 기준 |
| --- | --- |
| 비밀번호 | `password_hash`만 저장, 최소 10자 이상, 사용자 식별정보 포함 금지 |
| 로그인 실패 | 계정별 연속 5회 실패 시 15분 잠금 |
| 잠금 해제 | 시간 경과 후 자동 해제 |
| 오류 메시지 | 계정 존재 여부와 잠금 여부를 직접 노출하지 않는 일반 메시지 |
| Rate limit | 로그인 API에 IP 단위 rate limit 적용 |
| MFA | PoC 필수 범위 제외, 본사업 전환 시 재검토 |

## 4.3 M1 API/Worker 실행 경계

M1은 이후 기능 구현이 의존할 실행 경계만 제공하며 F-001 이후의 업무 capability를 선행 구현하지 않는다.

| 경계 | M1 기준 |
| --- | --- |
| Backend | 설정 로딩과 `/health`만 제공하고 runtime DSN만 주입받음 |
| Worker | queue adapter interface와 `/health`, `/ready`만 제공하며 실제 분석 enqueue/consume은 후속 기능에서 구현 |
| Queue readiness | Redis 연결 설정과 adapter 준비 상태를 별도 확인하며 DB 상태를 queue 상태의 원천으로 대체하지 않음 |
| 상태 원천 | Job/Step의 업무 상태와 이력은 PostgreSQL을 원천으로 유지하고 Redis에는 최소 식별자만 전달 |
| 환경 격리 | dev/prod의 DB, bucket, Qdrant collection, OpenSearch index, Redis queue/cache prefix를 서로 다르게 구성 |
| 자격증명 | API/Worker에는 bootstrap/admin/migration 자격증명을 주입하지 않고 runtime identity만 사용 |

M1 readiness 성공은 프로세스와 의존 경계가 준비되었음을 의미하며, 광고 분석 capability가 완료되었다는 의미가 아니다. 실제 enqueue, retry, heartbeat, `review_jobs`/`review_steps` 상태 전이는 F-002 구현과 해당 수용 테스트에서 활성화한다.

### M2 인증·광고물 입력 구현 경계

| 경계 | M2 기준 |
| --- | --- |
| 인증 | 30분 access JWT, 7일 refresh cookie rotation/hash/revoke, 사용자 role/disable 시 사용자별 active refresh 전체 revoke |
| 로그인 보호 | 실패 5회/15분 잠금, 일반화된 401, IP rate limit, refresh/logout Origin allowlist |
| 인가 | 목록은 role+department scope filter, 단건/preview/download는 scope 밖 403과 redacted 감사 기록 |
| 광고 파일 | jpg/jpeg/png/pdf/hwp/hwpx, 최대 50MiB, 확장자/MIME/크기/손상/중복 검증 |
| Object Storage | private S3-compatible bucket에 저장하고 DB에는 `storage_provider`, `bucket`, `object_key`, `checksum_sha256`을 보관 |
| 파일 응답 | backend proxy preview/download만 제공하며 object key, bucket, 내부 경로, presigned URL은 API/로그/감사 응답에서 제외 |
| 감사 | actor/action/target/result/reason/trace 메타데이터만 노출하고 token/hash, 비밀번호, 광고 원문, 내부 storage 필드는 redaction |
| 사용자 흐름 | 로그인 → multipart 광고물 등록 → scope-filtered 목록 → 허용된 상세/preview 확인 |

M2는 `reviews`, Parser/OCR, 기준자료 검색, 검토 결과/Annotation, 리포트와 평가 capability를 구현하거나 OpenAPI에 선설계하지 않는다. 실제 PostgreSQL과 MinIO를 사용하는 통합 검증에서는 M2 owner migration clean upgrade, common/dev seed 중복 실행, private bucket 저장/조회/권한 거부를 함께 확인한다.

### M4 Parser/OCR·비동기 Job entry gate

| 경계 | M4 계약 기준 |
| --- | --- |
| Review API | 요청/이력/상태/재분석 4개 operation과 중복 활성 요청 409 계약 |
| 상태 원천 | Redis는 최소 식별자 전달만 담당하고 Job/Step 진행·retry·heartbeat·dead-letter는 PostgreSQL이 원천 |
| Delivery claim | Worker는 `review-job-v1`의 정확한 6개 필드만 수용하고 `idempotencyKey == jobId`를 실행 전에 검증하여 교차 Job delivery를 거부 |
| Parser 출력 | 모든 adapter는 `normalized-document-v1`을 반환하고 후속 업무는 provider raw 구조를 읽지 않음 |
| 라우팅 | PDF/복합 PDF `opendataloader-pdf`, 이미지/스캔 PDF `PaddleOCR`, HWP/HWPX `hwp-hybrid` |
| 품질/재시도 | 기술 retry(1/3/10분, 최대 3회)와 정책 기반 품질 재처리를 분리한다. 품질 재처리 사유와 허용·구성된 보조 adapter가 함께 있을 때만 보조 엔진을 실행하고 OCR `<0.50`은 자동 retry하지 않음 |
| 후보 선택 | 1차·보조 결과를 confidence, 필수 필드, Text IR/Coordinate 완전성, warning 수, 판정 문구 판독성을 순서대로 비교하고 동률은 앞선 시도를 선택하여 재현 가능한 단일 결과를 확정 |
| 위치/신뢰도 | PNG/JPEG/PDF Coordinate는 실제 전체 raster canvas 기준 원본/정규화 값을 보존한다. PDF preview는 PaddleOCR와 같은 200-DPI raster를 사용하며 HWP/HWPX는 raw/normalized offset과 SVG 텍스트 일치 결과를 보존한다. |
| Raw artifact | 모든 1차·보조 시도의 engine, 재처리 사유, confidence, raw artifact 참조와 선택 여부를 기록한다. HWP/HWPX는 rhwp·document-processor 구성요소를 미선택 `PARSER_RAW`, 병합 결과를 선택 `NORMALIZED_DOCUMENT`로 보존하고 Text/Layout block은 정확히 하나의 선택 산출물만 영속화한다. bucket 본문과 DB metadata/checksum을 분리하고 일반 사용자 접근 금지, 예외 접근·삭제 redacted audit, retention hold/승인 삭제 적용 |

공유 계약·migration·synthetic fixture는 entry gate로 유지한다. M4 delivery는 이 경계를 변경하지 않고 Review 요청/이력/상태/재분석 handler, PostgreSQL claim/idempotency/heartbeat/retry/dead-letter/stale recovery, Redis 최소 delivery, 품질 재처리 전체 시도의 raw artifact metadata와 선택 산출물만의 Text/Layout 영속화, raw artifact checksum·권한·감사·retention lifecycle을 구현한다. claim 이후 persist/retry/complete/final transition은 `RUNNING`과 `locked_by`를 함께 비교하고, 동일 checkpoint 재실행은 idempotent no-op, 충돌 checkpoint와 예상외 처리 오류는 무한 stale loop가 아닌 최종 실패/dead-letter로 닫는다. 보조 adapter의 transient 오류도 품질 결과로 채택하지 않고 기존 기술 retry 경계로 전파한다. 실제 provider 엔진은 구성되지 않은 상태에서 성공을 가장하지 않으며 deterministic fixture adapter는 contract/integration 검증에만 명시적으로 사용한다.

private Parser/OCR 서비스는 `NH_PARSER_SERVICES_ENABLED=true`일 때 외부 AI와 독립적으로 PDF·이미지·HWP/HWPX를 `NormalizedDocument` v1로 정규화하고 결정적 Rule 검토에 전달한다. 실제 OpenAI 기반 근거 검색·구조화 판단 결과 확인은 개발 환경에서만 명시적으로 `NH_EXTERNAL_AI_ENABLED=true`, `OPENAI_API_KEY`, `OPENAI_EMBEDDING_MODEL`을 함께 설정한 경우에 허용한다. `/reference-documents`로 읽기 전용 마운트한 ADR-0002 승인 규정·가이드라인 PDF/HWP/HWPX는 private parser service로 먼저 정규화한다. 정규화 텍스트만 OpenAI Responses API에 전달해 기준자료 메타데이터를 추출하고, 원문/파서 구조는 provider에 직접 전달하지 않는다. 표준 버전·근거 chunk로 적재한 뒤 실제 embedding을 Qdrant에 저장하고 OpenSearch에도 재색인한다. parser 이름·버전·rule/IR 버전·text/layout/table block 수·구조 경로는 standard version metadata에 보존한다. worker는 DB 스캔 fallback 없이 두 검색 결과를 함께 요구하는 hybrid 근거 검색을 사용한다. 설정 누락·검색 backend/embedding·parser 오류는 성공으로 가장하지 않고 fail-closed 오류 또는 `SEARCH_UNAVAILABLE`로 끝낸다. 이 경로는 ADR-0002가 허용한 현재 저장소의 고객 승인 샘플에 한정되고 신규·운영·민감 자료는 별도 승인이 필요하다.

live opt-in의 문서 추출은 private engine service와 worker adapter로 수행한다. PDF/복합 PDF는 `opendataloader-pdf`, 스캔 PDF·PNG/JPEG는 `paddleocr`를 사용한다. HWP/HWPX는 `rhwp` service의 기준 텍스트와 Python 3.11 `document-processor` service의 문단·표 구조를 `HwpHybridParserAdapter`가 공백 차이를 허용해 결정적으로 정렬한다. 비공백 미정렬 범위는 `UNALIGNED` TextBlock과 warning으로 보존하고, 구조 서비스는 최대 `HWP_STRUCTURE_ATTEMPTS`회 호출 후 rhwp 기반 `UNSTRUCTURED` 저신뢰 결과로 닫는다. worker는 두 구성요소를 미선택 raw artifact로, `hwp-hybrid` 병합본 하나를 선택 산출물로 저장한다. 기준자료 HWP/HWPX 적재도 같은 aligner를 사용한다. 모델 서비스는 중간 DGX와 최종 H200에서 동일 계약을 사용하며 범용 `NH_GPU_*` endpoint로 선택한다. engine service는 내부 URL로만 연결하고 local dev에서만 loopback 포트를 선택적으로 공개한다. Review 요청은 backend와 worker가 동일 Redis URL/queue 이름을 사용해야 하며, 결과 근거 source는 DB 계약의 `KEYWORD`/`VECTOR`/`HYBRID`/`RULE_METADATA`만 저장하고 score는 0~1 범위로 정규화한다.

### M5 근거 기반 결과·Annotation entry gate

| 경계 | M5 계약 기준 |
| --- | --- |
| Thin slice | M5a 결정적 Rule → M5b M3 Hybrid Search 근거 → M5c provider-independent structured mock 순서 |
| 판정 불변조건 | 모든 item은 정책 버전, 사유 코드, 구조화 score detail, source engine/version을 포함 |
| 근거 불변조건 | evidence 연결 또는 `NOT_REQUIRED`/`INSUFFICIENT`/`SEARCH_UNAVAILABLE` 명시 상태를 반드시 포함 |
| 실패 분리 | 정상 검색의 근거 부족과 `RAG_SEARCH_UNAVAILABLE`/`RAG_SEARCH_FAILED` 기술 장애를 분리 |
| Rule 보존 | M5b/M5c 실패가 M5a Rule 결과를 무근거 정상이나 덮어쓰기 상태로 변경하지 않음 |
| Structured output | PR 자동 Gate에서는 `review-structured-output-v1` fixture만 사용한다. 승인된 수동 개발 lane에서는 OpenAI Responses JSON schema를 동일 shape로 검증하되 Rule 최종 판정을 덮어쓰지 않는다. |
| Parser/OCR opt-in | `NH_PARSER_SERVICES_ENABLED=true`이면 private service가 PDF·이미지·HWP/HWPX를 정규화하며, external AI 활성화와 독립적이다. |
| Live provider opt-in | `NH_EXTERNAL_AI_ENABLED=true`, non-empty `OPENAI_API_KEY`, `OPENAI_EMBEDDING_MODEL`, 승인 샘플 PDF/이미지 및 적재된 기준자료가 모두 필요하다. 키워드·vector search 및 provider 오류·미구성·비지원 형식은 fail-closed이고 PR CI는 호출하지 않는다. |
| Annotation | 이미지/PDF BOX는 preview와 같은 raster canvas를 기준으로 표시하고, HWP/HWPX TEXT_HIGHLIGHT는 변환 SVG의 텍스트가 정확히 일치할 때만 표시하며 그 외는 LIST_ONLY/UNAVAILABLE |
| Snapshot | effective date, standard/evidence/chunk version, rank/score/match source를 결과와 함께 고정 |

이 entry gate는 OpenAPI v0.5.0, additive 0005 migration, synthetic fixture와 실제 `TC-RES-*`, `TC-ITEM-*`, `TC-RAG-*`, `TC-EVD-*`, `TC-ANN-*` 실행 node를 잠근다. M5 backend 실행은 이 계약을 소비해 `NormalizedDocument`에서 결정적 Rule item을 만들고, 주입된 M3 검색 경계가 RRF로 순위를 정한 Top-3을 그대로 선택한다. 검색 부족/장애와 structured schema 오류에도 기존 Rule 판정·위험도를 유지한다. worker는 parser 선택 산출물 이후 result bundle을 0005 owner table에 원자적으로 저장하고 결과 단계 완료 전에 source/version, risk rationale, evidence 명시 상태, Annotation 표시 정보를 확정한다. PR 자동 Gate의 structured 경계는 fixture callable만 허용한다. 승인된 수동 개발 lane은 OpenAI adapter를 구성할 수 있으나, provider 출력은 schema-valid advisory score로만 보존하고 Rule 판정·위험도를 변경하지 않는다.

backend의 summary/items/detail/annotations handler는 기존 Review 부서 scope를 재사용하고 위험도 우선 정렬, evidence 필터, frozen standard version, BOX/TEXT_HIGHLIGHT/LIST_ONLY 정보를 반환한다. frontend runtime은 같은 frozen 계약을 소비하는 별도 lane이며 backend 구현은 OpenAPI, migration 또는 기존 M0~M4 revision을 재작성하지 않는다.

### M8 릴리스 후보 실행 경계

M8 수정 비교 화면은 사용자가 임의 revision ID를 입력하지 않는다. 수정 광고 파일을 먼저 `/advertisements/{advertisementId}/revisions`에 등록하고 서버가 반환한 `revisionId`만 비교 요청에 전달한 뒤, 기준 검토를 새 회차로 재검토한다. Backend는 광고물 row lock 아래 revision 번호를 배정하여 같은 광고물의 동시 등록을 직렬화하고, 저장된 revision이 해당 광고물 소유가 아니면 비교를 거부한다.

M6 추천 판단·Q&A·의견 초안·리포트·비교는 PostgreSQL 원천으로 재시작 후에도 유지한다. 리포트 다운로드 bytes는 process memory가 아니라 저장된 canonical `report_payload`에서 결정적으로 복원하며, `snapshot_hash`는 불변이고 PDF는 동일 snapshot의 HWPX source report를 참조한다. 생성·판단·다운로드·비교는 기존 부서 scope/역할 권한과 감사 추적을 유지한다.

Worker runtime은 supervised `JobRunner` 시작/종료, truthful readiness, 처리 중 heartbeat, `PENDING`/`STALE`/기한 도래 `RETRY_PENDING` DB lease reconciliation을 수행한다. Redis publish 실패 시 DB lease를 보존하고 만료 후 정확한 6-field delivery를 재발행하며, parser adapter 미구성은 성공으로 가장하지 않고 `PARSER_ADAPTER_NOT_CONFIGURED` 최종 실패로 정리한다. 실제 PostgreSQL 16.9·Redis 7 회귀가 publish lease 복구와 stale RUNNING 복구를 검증한다.

반복 Compose up에서 `db-bootstrap`은 활성 `$PGDATA/postmaster.pid`가 있으면 별도 postmaster를 시작하지 않고 이미 실행 중인 PostgreSQL과 NOLOGIN bootstrap/product-role 상태를 검증한 뒤 종료한다. 검증 실패는 fail-closed이며, 같은 volume에서 bootstrap 컨테이너만 재생성해도 데이터·role/ACL·PostgreSQL identity가 보존되고 PANIC/invalid checkpoint/interrupted recovery 흔적을 허용하지 않는다.

M8 구현 증거의 실제 경로는 backend `apps/backend/src/nh_ad_backend/main.py`와 capability별 `*_api.py`, worker `apps/worker/src/nh_ad_worker/main.py`·`runtime.py`·`postgres.py`, frontend `apps/frontend/src/App.tsx`·`api/client.ts`·`api/generated/openapi.ts`, migration `apps/backend/migrations/versions/0001`~`0010`이다. 원천 `openapi/openapi.yaml`의 현행 metadata version은 `0.8.0`이며 generated client는 이 계약과 clean diff를 유지한다.

자동 릴리스 판단은 `.github/workflows/release-readiness.yml`의 provider-free Gate만 사용한다. 이 Gate는 외부 provider credential, live inference, 고객사 원문 없이 고정 fixture와 G009 trace, deterministic E2E/release 회귀를 실행한다. `.github/workflows/external-ai-evaluation.yml`은 승인 환경에서 credential과 `external_ai` marker를 사용하는 별도 수동 평가이며, 실행 여부나 결과를 provider-free 성공으로 대체하지 않는다.

AC-18은 1차 구현 후 명세와 일정/Kanban을 실제 결과에 맞게 동기화하는 완료 기준이다. 이는 실제 외부 AI 품질, 고객 피드백, 시연 환경 배포, P0/P1 전체 pass 집계 또는 Critical 0건을 새로 증명하는 기준이 아니며, 별도 증거가 없는 항목은 잔여 dependency로 유지한다.

| --- | --- | --- |

| 검토 상품군 | 필수 | 기준 DB 매칭에 사용 |
| 검토 항목 | 선택 | 필수 문구, 위험 표현, 금리 표시, 시인성, 정합성 등 |

### 3) 처리 규칙

1. 상태가 `UPLOADED`인 광고물만 분석 요청할 수 있다.
2. 사용자가 검토 항목을 선택하지 않으면 기본 검토 항목 전체를 적용한다.
3. 시스템은 분석 요청 ID를 생성한다.
4. 광고물 상태를 `ANALYSIS_REQUESTED`로 변경한다.
5. 분석 파이프라인은 다음 순서로 실행된다.
6. 비동기 Job은 ADR-0059 기준 전체 timeout 30분, 단계별 timeout, 최대 retry 3회, backoff 1분/3분/10분을 적용한다.
7. 엔진 timeout, 일시적 실행 오류, Object Storage 오류, AI provider 응답 오류 등 기술 일시 오류는 `RETRY_PENDING`으로 표시하고 최대 3회(1분/3분/10분) 자동 재시도한다. worker heartbeat 장애는 `STALE`로 표시한 뒤 복구 대상으로 관리한다.
8. 파일 손상, 미지원 파일, OCR 판독 불가, 상품조건 불명확, 기준자료 미제공, 권한 오류, 요청값 검증 오류는 자동 retry하지 않고 담당자 확인 또는 최종 실패로 처리한다.
9. Job이 `COMPLETED`이면 진행 상태 응답의 모든 정의된 단계는 `COMPLETED`로 표시하며, worker는 이를 영속 상태에도 반영한다.
10. Worker는 `FILE_PREPROCESSING`(5%), `OCR_EXTRACTION`(25%), `LAYOUT_ANALYSIS`(50%), `RULE_REVIEW`(65%), `RAG_REVIEW`(80%), `RESULT_GENERATION`(95%) 전환을 PostgreSQL Job/Step 원천에 기록하고 완료 시 100%로 전이한다. 화면 이동·브라우저 탭 전환은 Redis 전달·PostgreSQL lease·worker 실행을 취소하지 않는다.
11. S-004/S-005/S-006/S-008은 권한 검증된 광고 원본 미리보기를 검토 입력·진행·결과와 함께 표시한다. 지원 형식의 원본은 자동으로 private preview proxy를 호출하며, 실패 시 원본 다운로드 안내를 표시한다.

```
파일 전처리
→ OCR/VLM 텍스트 추출
→ 레이아웃 분석
→ Rule Engine 검토
→ RAG Engine 검토
→ Multimodal Engine 검토
→ 결과 통합
→ 리포트 생성 대기
```

## F-003 OCR/VLM 텍스트 추출

### 1) 기능 개요

| 관련 요구사항 | FR-002 광고 텍스트 추출 |
| 주요 사용자 | 시스템, 준법감시 담당자 |
| 목적 | 광고물 내 문구를 자동 추출하여 후속 검토에 활용한다. |

---

### 2) 입력 항목

| 항목명 | 필수 여부 | 설명 |
| --- | --- | --- |
| 광고 파일 | 필수 | jpg, jpeg, png, pdf, hwp, hwpx |
| 페이지 번호 | 선택 | 다중 페이지 파일의 경우 |
| 분석 해상도 | 시스템값 | OCR 품질 확보용 |

---

### 3) 처리 규칙

1. 시스템은 광고물에서 텍스트 영역 또는 문서 구조 내 텍스트 블록을 탐지한다.
2. 이미지, PDF, 모바일 화면, 배너, HWP/HWPX 내 문구를 추출한다.
3. Parser/OCR 엔진 라우팅은 ADR-0079 기준으로 적용한다. PDF와 복합 PDF/표/다단 문서는 `opendataloader-pdf`, 이미지와 스캔 PDF는 `PaddleOCR`, HWP/HWPX는 `HwpHybridParserAdapter`를 사용한다.
4. 추출 결과는 ADR-0065 기준 `NormalizedDocument` v1으로 정규화하고, 텍스트 위치는 ADR-0052 기준 Text IR로 관리한다.
5. 이미지/PDF/OCR 결과는 ADR-0066 기준 Coordinate를 함께 저장하고, HWP/HWPX parser 결과는 `textPath`와 raw/normalized offset을 함께 저장한다.
6. 각 문구별 추출 신뢰도, 신뢰도 상태, 신뢰도 정책 버전, parser 버전을 저장한다.
7. OCR text confidence는 ADR-0053 기준 `>= 0.80` 정상, `0.50~0.79` 판독 확인 필요, `< 0.50` 판독 불가로 처리한다.
8. Parser/OCR 기술 실패와 품질 미달은 ADR-0073 기준으로 분리한다. 기술 실패는 ADR-0059 기준 retry하고, 품질 미달은 조건 기반 보조 엔진 재처리 후보로 처리한다.
9. HWP/HWPX는 `rhwp export-text`를 raw/normalized 텍스트의 기준 원천으로 사용하고 `document-processor`의 문단·run·표·셀·스타일·페이지 구조를 해당 텍스트에 정렬한다. private SVG는 원본 미리보기 전용이며 glyph SVG 좌표로 검토 텍스트를 복원하지 않는다.
10. 구조에 정렬되지 않은 rhwp 텍스트도 별도 TextBlock과 warning으로 보존하고, 후속 ReviewPipeline에는 `parserName=hwp-hybrid`인 하나의 병합 `NormalizedDocument` v1만 전달한다.
11. HWP/HWPX 검토 입력은 페이지 전체 `BODY` 한 개가 아니라 정렬된 문단·표 셀 TextBlock과 LayoutBlock을 사용한다. parser는 금융 규정 위반을 판단하지 않고 후속 금융광고 항목 분할에 필요한 구조만 제공한다.

| 구분 | 데이터 |

## F-013 광고 화면 근거 매핑

### 1) 기능 개요

| 항목 | 내용 |
| --- | --- |
| 기능 ID | F-013 |
| 기능명 | 광고 화면 근거 매핑 |
| 관련 화면 | S-007 광고 화면 검토 UI |
| 관련 요구사항 | FR-008 RAG 기반 근거 검색, FR-012 광고 화면 렌더링 및 영역 표시 |
| 목적 | 광고 화면 내 문제 위치와 관련 근거를 시각적으로 연결한다. |

---

### 2) 처리 규칙

1. 시스템은 ADR-0065 기준 `NormalizedDocument`의 좌표 또는 ADR-0052 기준 Text IR 위치 정보를 기반으로 문제 문구 위치를 표시한다.
2. 이미지/PDF는 Bounding Box로 표시하고, HWP/HWPX는 `textBlockId + normalized offset` 기준으로 텍스트 뷰에서 하이라이트한다. HWP/HWPX는 browser가 원본을 직접 해석하지 않으며, 인증된 backend proxy가 private `rhwp` 변환 서비스에서 생성한 sanitize된 SVG 페이지를 descriptor/content 계약으로 표시한다. 변환 실패·서비스 미가용은 terminal 오류와 원본 다운로드 안내를 표시하며 무한 진행 상태로 남기지 않는다. HWPX의 초기 변환 화면은 문서 구조 텍스트를 페이지형 SVG로 배치한 검토용 표현이며, 원본 레이아웃의 완전한 재현을 보장하지 않는다.
3. 일부 문구만 특정된 경우 특정된 부분만 표시하고 “일부 표시” 상태로 관리한다.
4. 위치를 특정하지 못한 검토 항목도 목록과 상세 패널에 표시하며 “위치 확인 필요” 또는 “문서 전체 이슈” 상태로 관리한다.
5. Annotation 위치 신뢰도는 ADR-0053 기준 `>= 0.80` `LOCATED`, `0.50~0.79` `LOW_CONFIDENCE` 또는 `PARTIALLY_LOCATED`, `< 0.50` `NOT_LOCATED`로 처리한다.
6. 사용자가 Annotation 또는 목록 항목을 선택하면 상세 검토 결과를 표시한다.
7. 상세 정보에는 원문, 문제 유형, 위험도, 판단 근거, 수정 권고가 포함되어야 한다.
8. 하나의 문구에 복수 근거가 연결될 수 있다.

---

### 3) 출력 항목

| 항목명 | 설명 |
| --- | --- |
| 광고 렌더링 화면 | 원본 광고물 표시 |
| 문제 영역 | 이미지/PDF Bounding Box, HWP/HWPX 텍스트 하이라이트, 위치 미확정 목록 표시 |
| 문제 유형 | 필수 문구 누락, 위험 표현, 시인성 등 |
| 근거 연결 | 관련 법령·매뉴얼·심의사례 |
| 상세 팝업 | 선택 영역의 상세 검토 결과 |

---

### 4) 수용 기준

- 사용자는 광고 화면에서 문제 영역을 직관적으로 확인할 수 있어야 한다.
- 문제 영역 선택 시 관련 근거와 수정 권고를 확인할 수 있어야 한다.

## F-014 보완 문구 추천

### 1) 기능 개요

| 항목 | 내용 |
| --- | --- |
| 기능 ID | F-014 |
| 기능명 | 보완 문구 추천 |
| 관련 화면 | S-009 문구 추천 |
| 관련 요구사항 | FR-013 보완 문구 및 대체 문구 추천, UR-002 상품부서 대체 문구 확인 |
| 목적 | 부적정하거나 위험한 광고 표현을 실무적으로 수정할 수 있도록 대체 문구를 제공한다. |

---

### 2) 처리 원칙

1. 광고의 마케팅 목적과 가독성은 가능한 유지한다.
2. 소비자 오인 가능성을 낮춘다.
3. 법령, 내부 매뉴얼, 과거 심의사례에 근거한 표현만 제안한다.
4. 확정적·절대적 표현은 조건부·범위형 표현으로 완화한다.
5. AI 추천 문구는 최종 문안이 아니라 담당자 검토 대상 초안으로 제공한다.
6. 담당자는 ADR-0039 기준 채택, 미채택, 수정 후 사용 중 하나로 판단을 저장한다.
7. 수정 후 사용 시 담당자가 입력한 최종 문구를 필수로 저장한다.
8. 추천 문구 판단 이력은 누적 저장하고, 리포트에는 AI 추천 문구와 담당자 최종 판단을 구분 표시한다.
9. Rule Engine은 위험 유형·원문·연결 근거를 입력으로 안전한 기본 추천을 결정적으로 생성한다. 연결 근거가 없으면 문구를 단정 추천하지 않고 담당자 확인으로 남긴다. LLM이 설정된 환경에서는 동일 근거 범위 안에서만 문장을 보강하며, LLM 실패·미설정 시 기본 추천을 유지한다.
10. 검토 요청의 `includeSuggestion=false`이면 추천 생성 단계를 건너뛴다. 재시도는 같은 추천 ID를 사용해 중복 row를 만들지 않는다.

---

### 3) 출력 항목

| 항목명 | 설명 |
| --- | --- |
| 원문 표현 | 광고물 내 문제 표현 |
| 문제 유형 | 과장, 오인, 조건 누락 등 |
| 수정 방향 | 완화, 조건 추가, 고지문구 보완 등 |
| 추천 문구 | AI가 제안한 대체 문구 |
| 추천 근거 | 관련 기준 또는 심의사례 |
| 담당자 검토 여부 | PENDING / ACCEPTED / REJECTED / MODIFIED_AND_USED |
| 최종 사용 문구 | 수정 후 사용 시 담당자가 입력한 문구 |

---

### 4) 수용 기준

- 위험 표현에는 최소 1개 이상의 수정 방향 또는 대체 문구가 제공되어야 한다.
- 추천 문구에는 관련 근거가 연결되어야 한다.
- `MODIFIED_AND_USED` 상태에는 최종 사용 문구가 반드시 저장되어야 한다.

| 종합 검토 결과 | 전체 위험도, 문제 항목 수 |
| 항목별 검토 결과 | 필수 문구, 위험 표현, 금리 표시, 시인성 등 |
| 문제 문구 | 광고물 내 원문 |
| 판단 사유 | 위험 또는 보완 필요 사유 |
| 관련 근거 | 법령, 내부 기준, 심의사례 |
| 수정 권고 | 대체 문구 또는 보완 방향 |
| AI 사용 유의문구 | 최종 판단은 담당자가 수행한다는 안내 |
| 오류 및 확인 필요 항목 | OCR 실패, 기준자료 부족, 상품정보 부족 등 |

---

### 3) 처리 규칙

1. 검토 완료 상태의 광고물만 리포트 생성이 가능하다.
2. 사용자는 전체 리포트 또는 선택 항목 리포트를 생성할 수 있다.
3. 리포트에는 생성일시와 생성자를 표시한다.
4. 리포트 생성 이력은 저장한다.
5. 리포트 출력 형식은 ADR-0038 기준 HWPX를 기본으로 하며 PDF도 선택할 수 있다.
6. 리포트 내용은 ADR-0054 기준 `report_snapshot`으로 먼저 고정하고 `snapshot_hash`를 저장한다.
7. HWPX는 기준 리포트 산출물로 생성한다.
8. PDF는 생성된 HWPX를 HWPX-to-PDF converter adapter로 변환해 생성한다.
9. HWPX 생성 실패와 PDF 변환 실패는 분리해 기록한다.

---

### 4) 수용 기준

- 사용자는 광고물별 검토 리포트를 조회할 수 있어야 한다.
- 리포트에는 검토 결과, 판단 근거, 수정 권고가 포함되어야 한다.
- 사용자는 HWPX 리포트를 기본으로 다운로드할 수 있고, PDF 출력도 선택할 수 있어야 한다.
- HWPX와 PDF는 동일한 `snapshot_hash`를 참조해야 한다.

4. 기준자료 변경 시 변경 이력을 저장한다.
5. 삭제보다는 비활성화 처리를 기본으로 한다.
6. 기준자료 등록/수정 시 ADR-0050 기준 자료 유형별 필수 메타데이터를 검증한다.

### 5) 수용 기준

- 기준 관리자는 광고심의 기준자료를 등록·수정할 수 있어야 한다.
- 기준자료는 상품군, 광고유형, 기준 유형별로 검색 가능해야 한다.
- 변경 이력이 저장되어야 한다.

# 11. 결론

## 11.1 독립 RAG 파이프라인 정본

`rag-pipeline/`은 기존 제품 Worker 구현과 자동 결합하지 않는 독립 실행 정본이다. 기존 서비스의 검색·판정 코드를 암묵적으로 호출하거나 기존 결과를 정답으로 재사용하지 않는다.

처리 계약은 다음과 같다.

1. 파서의 `nh-ad-review-evidence-v6`와 영역·라벨 산출물 `nh-ad-review-region-input-v1`을 동일성 검증 후 `nh-ad-review-integrated-input-v1`로 결합한다.
2. 영역 전체를 coarse 청크로 보존하고, 불릿·길이 기준 fine 청크를 별도 검색 뷰로 생성한다. 같은 라벨이라는 이유로 서로 다른 영역을 합치지 않는다.
3. 검색 규정 원천은 사용자가 지정한 규제목록 v2 한 파일로 제한하며 C/D/T 항목을 규칙 후보로 사용할 수 있다.
4. 확정된 상품군 메타데이터만 검색 범위를 좁힌다. 추정값·충돌값·미상값은 후보를 제거하는 근거로 사용하지 않으며, 운영 API는 상품군 확인 입력을 요청하고 모델 실행을 시작하지 않는다. 개발 전용 명시 옵션에서만 양 상품군 fail-open을 허용한다.
5. Elasticsearch BM25와 BGE-M3 벡터 결과를 RRF로 결합한 뒤 Gemma가 버전 고정 구조화 계약으로 적용성·판정을 반환한다.
6. 답지·연구원 피드백·광고 ID별 사후 교정값은 운영 검색·판정 입력에서 읽지 않는다. 답지는 동결된 실행 결과를 별도 평가할 때만 사용한다.
7. 입력·검색 문서·Gemma 응답·최종 결과는 `rag-pipeline/schemas/`의 JSON Schema로 검증한다.
8. T 규칙은 확인된 템플릿 또는 세부상품과 정확히 일치하는 섹션만 판정하고, 확인 전 규칙은 보류 목록으로 남긴다.
9. 각 규칙에는 rule-to-ad BGE-M3 근거 창을 전달하고 짧은 광고는 coarse 전문도 함께 제공한다. 근거 창이 광고 전체가 아니거나 파싱이 불완전하면 문구 부재만으로 위반을 확정하지 않는다.
10. 심의필 자리표시, 불릿 종류, 날짜 표면형식은 광고 전체 텍스트의 결정론적 관측값으로 모델에 제공하고 관측값과 모순되는 누락 판정을 계약 오류로 거부한다.
11. 모델 신뢰도는 보정된 확률로 간주하지 않으며 모든 위반·판단불가 결과는 연구원 확인 전 확정 결과로 게시하지 않는다.
12. 규칙의 실제 요건을 TEXT/PARTIAL/EXTERNAL로 구분한다. PARTIAL은 확인 가능한 문구 요건만 검사하고 전체 충족 확정을 금지하며, EXTERNAL은 추가 입력과 함께 보류한다.
13. 운영 요청은 비동기 job으로 파일 원자 저장한다. 프로세스 재시작 중이던 작업은 같은 job의 다음 attempt로 자동 재큐잉하고 계약이 같은 체크포인트를 이어 쓴다. 출력 계약 실패는 정상 쌍을 보존한 채 누락 쌍만 한 차례 소배치 재시도한다. 동일 광고의 복수 파일 파싱은 최초 묶음 실행 후 성공 자산을 보존하며, 누락·실패 자산만 단독으로 한 차례 재시도한다.
14. 운영은 답지용 미해당 표본을 추가 검색하지 않는다. 기본 경로는 규제목록 v2의 입력요건으로 검사 가능한 후보를 가른 뒤 Gemma가 적용성과 판정을 한 번에 수행한다. 별도 Gemma 1차 적용성 검사는 비교실험 옵션으로만 사용하며 그 결과만으로 후보를 제거하지 않는다. 본판정의 미해당은 화면에서 제외하고 이유·원출력은 감사 기록에 보존한다.
15. 심의 단계·협회 사전심의 여부는 제작부서의 필수 입력으로 요구하지 않고 업무 시스템에서 확인된 경우에만 출처와 상태를 보존해 적용조건에 사용한다. 확인되지 않으면 해당 조건부 규칙을 보류한다. 사전심의가 확인된 경우에는 최종 심의필 번호 미발급을 누락으로 단정하지 않고 자리표시 형식도 존재로 인정한다.
16. A4 이상 여부·8pt·대비 등 시인성 수치는 파서/OCR이 계산한다. RAG는 `regions[].visibility`와 줄별 `style` 측정값을 재계산하지 않고 전달한다. `declared`와 `fontbox` 크기를 같은 절대 pt 기준으로 혼용하지 않으며, 색상만 있고 측정 대비가 없으면 대비를 추정하지 않는다. bbox·글자크기·대비 등 해당 규칙에 필요한 관측값이 없으면 사람 검토로 보낸다.
17. 다상품 광고는 상품명별 `products[]`와 상품 전용 증거, 공통 증거를 분리하고 상품마다 서로 다른 템플릿을 허용한다. 실행 결과는 `(ad_id, product_id, item_id)` scope로 분리하며 미배정 영역이 있을 때만 입력 보완으로 중단한다.
18. 여러 광고는 광고별 카드와 독립 job으로 즉시 접수한다. 각 카드는 독립 상품군·상세 상품군·매체와 동일 광고 복수 파일을 가지며, 최대 20개 카드를 한 번에 등록·심의 요청한다. DGX 용량 안에서 worker와 vLLM 동적 배칭으로 병렬 처리하되 서로 다른 광고의 판정 문맥은 혼합하지 않는다.
19. 위반만 제공된 답지는 알려진 위반 Recall 평가에만 사용한다. 미기재 규칙을 자동으로 충족·미해당·오탐으로 간주하지 않으며 신규 발견은 미채점 후보로 사람 검수한다.
20. 업무 템플릿·심의사례의 적정/부적정/확인필요 표는 `review-decision-guide-v1`로 정규화하고 활성 규제목록 v2의 기존 `item_id`에만 연결한다. 예시는 완전일치 정답이 아니며 v2 범위와 법적 근거를 변경할 수 없다.
21. 광고 전문 검사가 완료된 표시의무 항목에서 적용성이 확인되고 필수 구성요소의 부재가 확인되면, 다른 구성요소가 불명확하더라도 전체 판정을 `판단불가`로 후퇴시키지 않는다. 모델 출력이 이를 어기면 계약 오류로 거부하고 해당 규칙만 재처리한다.
22. `광고물(원본형식)` 입력은 파일 확장자 이름만으로 보류하지 않는다. 정확한 줄 분할·줄바꿈·스타일 등 해당 규칙에 필요한 파서 관측값이 있으면 텍스트 형식 규칙을 판정하고, 좌표·크기·색상·인접성처럼 실제 공간 정보가 필요한 규칙은 그 관측값이 없으면 계속 보류한다.
23. 등록자는 상위 상품군과 상세 상품군을 선택하며 내부 템플릿을 직접 선택하지 않는다. 서버는 활성 v2의 상세 상품군 목록으로 입력을 검증하고 내부 템플릿을 자동 연결하며, 사용자 선택값과 내부 파생값의 출처를 분리해 보존한다.
24. 모델 판정은 결정적 사실·라우팅·입력능력 가드레일을 통과해야만 최종 후보가 된다. 충돌하거나 출력 계약을 위반한 쌍은 의미를 임의 교정하지 않고 실패 쌍만 재호출한다.
25. 모든 최종 finding은 `rule_basis`로 템플릿 원문 또는 규제목록 v2 출처를 가져야 한다. 템플릿에 법령 조문이 없으면 출처 근거만 표시하며 법령 근거를 생성하지 않는다.
26. 결과의 `audit`에는 요청·응답 모델, 검색 방식·인덱스·질의 변형, 규칙 원본 SHA-256, 적용 가드레일과 validator 버전을 기록한다. 각 finding은 모델 응답과 사용 증거 ID를 `decision_trace`로 연결한다.
27. AI 실행 완료와 사람의 최종 승인·반려는 분리할 수 있다. 준법 담당자 결정은 AI 결과를 변경하지 않는 별도 불변 기록이며, 현재 PoC 기본 화면에서는 비노출로 둔다.
28. 모든 규칙은 판정 전에 `rule-applicability-contract-v1`로 컴파일한다. 모델은 점검문구·판정기준의 대상자·상품·상황·매체·절차 범위와 명시 적용조건을 같은 광고 문맥의 근거로 먼저 확인해야 한다. 조건이 불충족이면 미해당과 빈 의무 점검을, 확인할 수 없으면 판단불가를 반환하며 의무 충족·위반을 판정하지 않는다. 조건 ID 누락이나 순서 변경은 출력 계약 오류로 거부한다. 접속어·키워드는 구조화 보조일 뿐 최종 조건 게이트가 아니다.

본 기능명세서는 금융상품 광고심의 적정성 검토 AI 에이전트 PoC의 주요 기능을 광고물 등록, AI 분석, OCR/VLM 추출, 기준 DB 검색, Rule/RAG 기반 검토, 문구 추천, 화면 근거 매핑, 심의 의견 초안, 리포트 생성, PoC 성능 평가로 구분하여 정의하였다.


## 2026-09-16 선택 템플릿 전수 처리·텍스트/시각 분리 및 서버 실행

선택 템플릿의 모든 물리 원문 행은 택일 통합 후 항목에 정확히 연결되어야 한다. 요청 또는 명시적 보류 기록이 없는 항목은 실행 오류로 중단한다. 텍스트 의무와 배치·로고·중첩 구조의 사람 검토를 분리하고, 불명확한 머리글·필수 기호·교차 병합은 자동 해석하지 않는다. 텍스트 부분의 충족은 전체 시각 요건의 충족이 아니다. △ 기재요령의 생략·면제는 적용 조건과 반대 방향이며 미확정은 미해당으로 숨기지 않는다.

최초 광고 등록일(한국 날짜)을 review_date로 동결하여 RAG와 compact 모델 입력까지 전달한다. 광고에 인쇄된 금리 기준일과 구분하며 날짜 비교 의무는 원문 규칙에서만 가져온다. 예금성 적립식 원문22행→20항목, 대출성 상품명 노출26행→26항목의 텍스트 대상 전개를 확인했다. 별도 시각/구조 확인은 각각4/8항목이다. 기존 저장 판정은 수정하지 않으며 새 실행에 적용한다.

원문에 명시된 기준일의 기간 제한은 독립 의무로도 검사한다. 판독이 가능한 실제 인용 기준일과 심의일의 경과 일수를 전달하고, 기간 밖·미래·날짜 근거 없음 상태의 충족을 출력 계약에서 거부한다. 날짜나 기간을 광고별로 정하지 않는다. 텍스트 전용 의무에는 시각 기재요령을 섞지 않고 원문과 별도 사람 검토에 보존하며, 모델이 줄 배치·글자 크기·로고를 자동 확정하면 재검토한다. 원문 혼합 문단을 임의로 세분한 새 규정으로 만들지 않는다.

미리보기 OCR에서 정본 인용 ID가 없는 줄은 표시용 영역으로만 제공한다. 미리보기 처리 실패는 별도 오류 기록을 남기며 이미 검증한 본문을 이용하는 판정까지 중단시키지 않는다. 미리보기 좌표를 본문 정본 인용으로 임의 연결하지 않는다.

모델에 전달하는 축약 입력은 출처가 결합된 적용조건·의무 계약을 사용한다. 동결 요청의 보조 기재요령·표준 예시와 시각 원문은 감사 자료로 보존하지만 별도 경쟁 의무로 다시 전달하지 않는다. 원문이 따옴표로 특정 표현의 기재를 명시적으로 요구하면 독립 의무로 보존한다. 조건·대안·예외가 함께 있는 문단에서는 해당 표현만 떼어 의무화하지 않는다. 질문의 괄호 안에 명시된 “있는/없는 광고” 적용범위도 별도 조건으로 확인하며 최종 적용성은 광고 증거를 근거로 판정한다.

자동 확정 전 텍스트 전용 요건의 시각 판단, 계산 일치를 설명하면서 반환한 산술 위반, 명시적인 자체 정정과 반대인 판정값을 거부하고 기존 재시도 절차로 보낸다. 실제 인용 날짜로 결론을 낼 수 있는 기간 조건을 근거 없이 판단불가로 돌리지 않는다. 이 검사는 의미 정확도 전체에 대한 보증이 아니다.

산술 위반은 실제 인용 수치로 재현 가능한 합·차와 광고 표시값의 불일치를 제시해야 한다. 정합성을 확인하지 못했다는 설명만으로 위반을 허용하지 않는다. 공통 검사는 십진수로 계산하고 인용 밖 피연산자·결과값, 실제로 일치하는 부등식을 거부한다. 복잡한 산식이나 조건별 수치의 관계가 미확정이면 사람 검토하며, 이 검사가 원문에 없는 산식이나 우대조건 동시 적용을 만들지는 않는다.

설명에서 적용 여부를 판단할 수 없다고 명시하면서 미해당을 반환한 응답은 계약 모순이다. 새 실행에서는 거부·재검토하며, 저장 결과의 화면/다운로드 투영에서는 해당 항목을 판단불가로 드러낸다. 보류 전 모델 상태와 사유를 함께 표시하고 원저장 판정·실행물은 덮어쓰지 않는다. 근거로 채택하지 않은 인용의 bbox를 다시 활성화하지 않는다. 확인된 미적용 사유는 기존처럼 제외한다.

사용자 승인에 따라 웹/API·파서·HWP 변환·작업 실행·파일 상태를 Spark 서버에 복제하는 중간 배포 구성을 추가했다. H200은 같은 배포 정의와 별도 endpoint 설정을 사용하되 실기 검증 전 완료를 주장하지 않는다. 기존 모델/OCR/ES는 재시작하지 않는다.

## 최초 등록일과 원문 줄 인용 보강

일반 구현 오류로 분류한다. 심의일은 광고 최초 등록일의 한국 날짜이며 재심의해도 변경하지 않는다. 요청일과 별개인 출처를 입력 해시에 포함한다. 출처가 없는 독립 CLI 입력은 명시 날짜로 구분하고, 날짜가 없으면 날짜 출처만 제출할 수 없다.

정확한 원문 줄이 제공된 근거에서 OBSERVED 충족·위반을 주장하면 직접 줄 인용을 필수로 한다. 영역 ID만 반환하면 출력 계약 오류로 기존 선택 재시도에 보낸다. 레거시 영역 문맥에는 가짜 줄 정렬을 만들지 않는다. 이 검사는 원문 참조 누락 방지이며 인용한 문장에 대한 모든 의미 해석의 정확성을 보증하지 않는다.

## 템플릿 항목의 근거 검색과 인용 문구 검증

템플릿 항목의 기재 구분과 같은 기존 파서 라벨은 근거 후보의 순위 보조로 사용한다. 해당 후보 중 판독 가능한 원문을 먼저 고려하되 텍스트 검색·밀집 검색·기존 트리거를 보존하며, 무라벨 근거를 제외하지 않는다. 파서 라벨은 판정 근거나 참값이 아니며 별도 모델 재검사는 없다. 상품명·광고 ID·상품별 수치를 코드 조건에 넣지 않는다.

정확한 줄이 있는 후보는 모델 출력에서 L 별칭으로만 인용하며, 규칙별 evidence_refs와 line_refs는 같은 허용 줄을 명시한다. 허용 원문에 있다고 설명하는 직접 인용 문구는 실제 선택 줄에 있어야 한다. 숫자뿐 아니라 긍정적인 원문 인용의 불일치도 계약 오류로 재시도한다. 부재 설명과 규정 자체의 따옴표는 광고 내 문구 존재 주장으로 해석하지 않는다. 공백 정규화 외 유사도 치환이나 다른 줄 자동 선택은 하지 않는다.

날짜가 해당 규칙 허용 범위에서 하나로 확인되는 경우, 모델이 날짜 인용을 비워 이미 계산 가능한 기간 조건을 판단불가로 회피할 수 없다. 상충하는 복수 기준일·허용 범위 밖·불확실 판독은 이 보강으로 확정하지 않는다. 산술 검토는 원문에서 주장한 같은 조건의 합·차를 대상으로 하며 별도 표시값이 없는 조건부 가산에 대해 원문에 없는 최종 합계 표시 의무를 만들지 않는다.

기존 저장 결과의 긍정 인용 문구가 선택 원문에 없는 경우 화면/다운로드 공통 투영에서 판단불가로 보류하고 활성 인용과 bbox를 비운다. 원저장 판단은 변경하지 않고 model_assessment.status=WITHHELD_BY_GROUNDING_GUARD로 원래 상태/설명을 보존한다. 이 검사는 모든 의미 해석에 대한 정답 검증이 아니다.


### 존재·산술 요건의 원문 분리 검토

분리 요청은 기존 허용 원문 줄·판독 상태·규칙·등록 메타데이터를 유지한다. 비인용 광고 전문과 검색 보조 라벨은 분리 입력에서 제외하고, 실제 허용 줄을 먼저 확인하도록 지시한다. PARTIAL의 전체 부재 확인 제한과 독립적으로 읽힌 문구의 존재 확인을 구분한다. 원래 후보/라벨/전문은 동결 입력에 그대로 보존하며, 분리 입력 전체도 감사 응답에 남긴다.

분리 요청에도 기존 출력 계약 교정 재시도(단일 항목 총3회 이내)를 적용한다. 이는 같은 근거로 원하는 판정이 나올 때까지 반복하는 절차가 아니다. 직접 인용 검사는 문장이 인용부호로 시작하거나 임의의 기재 항목명이 앞에 오는 경우에도 적용하며, 규정·기준·예시 자체의 문구 설명 및 부재/의무 설명은 구분한다. 명시적 말줄임표는 실제 인용 줄에 순서대로 존재하는 조각만 허용하며 문구를 생성하거나 순서를 바꾸지 않는다.

공통 구현 오류 대응: 허용 원문이 제공됐으나 문맥 혼동으로 놓치는 보류를 줄인다. PRESENCE 또는 규정 원문에 산술·산식·합산 검산이 명시된 요건을 대상으로, 적용성이 확인됐고 UNCONDITIONAL/SOURCE_SCOPED이며 명시 A/U 조건과 외부 입력 의존성이 없고 판독 가능한 줄이 있는 판단불가만 한 번 원문을 분리해 확인한다. 단일 요청에도 적용하되 재귀적인 의미 재시도는 하지 않는다. 적용 범위는 규칙 계약과 원문 상태로 결정하며 광고명·ID·정답은 사용하지 않는다. 원래 판단이나 기대 판정을 모델에 보내지 않고 파서 라벨도 재검사하지 않는다.

분리 응답이 모든 기존 계약을 통과한 충족/위반일 때만 해당 항목에 적용한다. 여전히 판단불가, 미해당, 실패 또는 잘못된 인용이면 원래 보류를 유지한다. 다른 항목의 판정과 동결 입력은 보존한다. 원응답, 분리 응답, 적용 항목, 호출 시간/토큰은 source_focus_attempts/source_focus_applied/call_history에 기록한다. 판독 가드·조건부 의무·외부 자료 부족은 이 경로로 재검사하지 않는다.

합성 회귀는 올바른 분리 근거의 반영과 이웃 판정/원본 보존, 한 번 호출 제한, 실패/미해당/계속 보류 유지 및 판독 불확실/외부 입력/조건부 제외와 단일 요청 원본 보존를 검증한다. 이 동작은 의미 정확도 보장이 아니며 새 사람 정답 holdout이 없는 상태는 유지한다.


### 복구 결과의 템플릿 처리 기록 보존

미해당 사유가 “자료/근거/정보가 없거나 부족하므로 적용 제외”라고 명시한 경우도 적용성 미확정으로 처리한다. 확인된 매체 불일치나 완전한 원문에서 트리거 표현의 부재를 확인한 경우와 구분한다. 원응답은 보존하고 화면/다운로드에서 판단불가와 보류 사유를 표시하며, 신규 모델 응답은 같은 모순 검사로 검증한다.

명시 A 조건을 NOT_SATISFIED로 제외하면서 적용성 원문 인용과 확인된 메타데이터를 모두 비운 응답도 미확정으로 보류한다. 이는 조건이 실제로 거짓이라는 의미를 새로 추정하지 않고, 음성 적용 판단의 근거가 없음을 구분하는 계약이다.

출력 실패 항목 복구 후 결과를 재조립할 때 동일 동결 discovery의 template_coverage와 template_scope_deferred를 보존한다. 이미 저장된 복구 결과에서 이 필드가 빠졌다면 화면/다운로드 공통 투영은 같은 검토의 동일 scope discovery에서만 보충한다. 다른 광고·다른 scope나 현재 템플릿으로 처리 완료를 추정하지 않고 원저장도 변경하지 않는다. 복구 경로의 필드 보존과 구 결과의 범위 일치·원본 불변을 회귀 검증한다.

## 원문 수치의 결정론적 검산 — 2026-09-16

분류는 일반 구현 오류다. v2의 금리 산식·우대조건별 합계·계산 예시 정합성 기준과 계산 검증의 결정론적 확정 지시를 실행한다. 광고 ID·상품명·사례 수치를 런타임 조건으로 사용하지 않는다. 산술 전용 PROHIBIT 원문 계약에서 단일 O 의무, 명시 A/U 조건 없음, READY·전체 증거 범위·같은 자산/상품·판독 가능한 정본 줄을 전제로 한다. 복합 템플릿 금리 요건의 기준일·기재 의무까지 충족으로 치환하지 않는다.

현재 지원하는 일반 술어는 명시된 대출금리 행의 기준+가산=최고, 최고−우대=최저, 최대 우대의 조건별 합계 일치다. Decimal로 비교하고 피연산자 역할과 줄 참조를 함께 추출한다. 같은 우대항목 안의 명시적 금액 하위구간 대체율은 중복 합산하지 않는다. 다중 상품/자산·다른 기준일·모호한 중복/택일·추가율·별도 계산 예시·부분 판독·외부 입력 의존성은 이 계산기로 확정하지 않는다. 별도 표시 합계 없는 한도대출 가산에는 새 합계 기재 의무를 만들지 않는다. 인지세 고객 부담 예시가 있는 경우 명시 부담률과 금액이 맞는지도 충족 전 확인하고 미지원/불일치는 일반 검토로 남긴다. 복잡한 수취이자·환급액·일수/세율 계산은 아직 지원 범위가 아니다.

지원되는 항목은 모델 호출 전에 계산하며 남은 항목은 원래 한 배치로 유지한다. 일치/불일치에 따라 충족/위반과 실제 원문 줄·계산식을 반환한다. 응답 감사는 decision_source=DETERMINISTIC_SOURCE_ARITHMETIC, 모델 null·토큰0을 기록하고 최종/복구 결과도 해당 출처를 보존한다. 동결 원문으로 계산 가능한 과거 결과의 workspace/export는 같은 함수를 적용하되 원저장·원응답·source_results를 덮어쓰지 않는다. 이유에 규칙 기반 검산임을 명시하며 HWP 줄에 없는 bbox를 만들지 않는다. 일반화 성능을 측정한 것이 아니며 새 광고/사람 확정 정답은 여전히 필요하다.

## 사용자 결정: 결과 3종·사람 확인 통합·후보 실행 제한 제거 — 2026-09-16

메인 결과는 위반·판단불가·충족만 표시한다. 다른 템플릿 소속 항목은 목록·집계에서 제외하고 원저장 감사만 유지한다. 실제 NOT_APPLICABLE은 적용 제외 내역(excluded_rows)에 사유와 함께 보존하며 메인 카드·필터에 미해당을 두지 않는다. 적용성 미확정인 추가 v2 후보와 시인성/외부 자료/구조 확인은 모두 판단불가 목록·집계에 포함한다. 동일 scope/item의 보류는 중복 집계하지 않는다. 텍스트 충족에 필수 사람 확인이 남으면 전체 판단불가로 표시하고 자동 텍스트 결과를 automated_assessment에 보존한다. 이미 확인된 위반은 유지하며 남은 확인 사유를 함께 표시한다.

기존 추가 v2 후보의 최대30개 실행 제한을 제거한다. 검색·적용범위/입력 필터를 통과해 발견된 후보는 모두 처리하며 동시 실행 수·요청 배치 크기는 처리 순서와 자원 관리에만 사용한다. 기존 prohibition_max_candidates 설정/CLI는 호환성 입력으로만 남고 판정 후보를 잘라내지 않는다. reranker80개는 순위 보강 범위이며 기존에도 나머지 후보를 보존했다. 검색 top-k 자체와 응답 토큰/작업 제한시간은 별개이고 v2 모든 행 전수 판정으로 전환한 것은 아니다. 처리 실패를 충족/미해당/정상 완료로 숨기지 않는다.

workspace/export에 excluded_rows와 execution_omissions를 추가하며 review_candidate_rows/deferred_rules는 빈 호환 배열로 유지한다. 사람 확인은 manual_review_reasons와 실제 점검 제목/질문을 반환한다. 과거 파일에 제목이 없으면 검토 시 동결한 SHA와 동일한 규정 파일 및 저장 템플릿 카탈로그에서 표시 메타데이터만 보충한다. 버전 불일치면 현재 규정으로 바꾸지 않는다. 원저장·모델 판정·source_results는 변경하지 않는다. 과거 후보 실행 누락이 있다면 판단불가와 재처리 필요 경고로 드러내며 자동 완료로 표시하지 않는다.

양성/음성/경계 회귀는121개 검색 후보 보존, 미선택 제외, 사람 확인/적용성 미확정 통합, 위반 유지, 텍스트 충족 보류, 중복 제거, 상품별 scope 분리, 실제 미해당 별도 내역, 옛 실행 누락 경고, 원본 불변, 동결 출처 해시 일치/불일치를 포함한다. 광고 전체 재심의·모델 호출 없이 저장 결과를 대조한다.

## 결과 화면의 내부 식별자 비노출 — 2026-09-17

결과 카드 제목에는 상품·점검항목 이름만 표시하고 C/D/TPL 등 내부 규칙 ID를 붙이지 않는다. 처리 실패 목록은 항목 순번으로 표시한다. API/export의 원래 ID와 근거 좌표 연결·필터·집계는 유지한다.

## 판독 누락 확정 방지와 부분 정상 응답 보존 — 2026-09-17

일반 구현 오류를 수정한다. 근거는 기존 템플릿/v2의 원문 증거 계약과 판독 불확실성 정책이며 새 법적 의무를 추가하지 않는다. 적용 범위는 모든 규칙의 판독 미완료 입력과 여러 항목을 묶은 모델 응답이다.

- 판독이 불완전하면 finding_basis가 OBSERVED여도 MISSING 상태 또는 명시적인 기재·안내 누락 설명은 판단불가로 보류한다. 복수 의무에서는 해당 의무만 보류하고 독립적인 관찰 위반은 유지한다. 단일 의무일 때만 전체 사유를 함께 확인한다. 원문 인용 안의 없음 표현·누락 부정·실제 산술 불일치·완전 판독은 반례로 구분한다. 모델 원응답은 감사 기록에 남긴다. 이 좁은 검사는 모든 의미적 부재 표현을 탐지한다는 보장이 아니다.
- 여러 항목의 응답이 일부 실패하면 광고 ID·항목 순서·개수·중복 검증 후 항목별 전체 계약 검사를 통과한 응답을 보존한다. 틀린 항목만 기존 횟수/분할 정책으로 재호출한다. 허용 원문 범위·판정 기준은 넓히지 않고 기존 근거 추가 확인 정책도 유지한다. 광고ID 불일치·중복·미등록 항목·누락 결과는 이 보존 절차로 숨기지 않는다.
- 최종 결과는 원 요청 순서로 복원하고 checkpoint 완료 조건과 정확한 요청 쌍 수를 유지한다. 실패 부모 호출의 시간·토큰·오류 이력은 한 번만 집계한다. 외부입력은 파서 판독 상태, 규칙별 스캔 범위, 기존 요청/응답과 줄 인용이며 사례 이름이나 정답은 사용하지 않는다.

적용 여부를 확인할 수 없다는 미해당 응답은 해당 의미 오류만 있을 때 원응답을 보존하고 판단불가로 보류한다. 구조·ID·인용·전송 오류는 숨기지 않는다. CPU 산술과 모델 결과가 분리돼도 원 요청 순서를 복원하여 완료된 계산을 재호출하지 않는다. 저장 결과의 동일 판독 보호는 화면과 JSON 내보내기의 공통 projection에 적용하며 원 저장값은 불변이다.
