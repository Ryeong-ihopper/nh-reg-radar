## 9/9 사용자 확정 및 9/10 구현 반영

템플릿 HWPX 자체가 주 심의 기준이며 v2 매핑 없이 독립 항목을 가진다. 아래의 과거
v2 매핑 필수 표현은 이 결정으로 대체한다. v2는 세부 규칙과 법령 근거의 보완 출처다.
원본 카탈로그는 19섹션·271행이며, 15행은 이미지·중첩표 또는 빈 헤더 때문에 구조
검토가 필요하다. 상세 구현·현재 산출물·검증 경계는 [인수인계](handoff-current.md)를 따른다.
심의사례의 개별 판단과 판단근거는 운영 템플릿에 합치지 않는다.

## 1. 결론

- 접수자는 상세 상품군과 매체를 입력하고, 시스템은 상세 상품군 코드에 대응하는 내부 템플릿을 자동 연결한다.
- 내부 템플릿을 해당 광고의 주 체크리스트로 사용하고, `O`와 조건이 확인된 `△` 항목을 전개한다.
- 규제목록 v2는 일반 금지규칙의 누락 방지와 법적 근거 매핑에 사용한다.
- 템플릿에 없다는 이유로 v2 일반 규칙 검색을 막지 않는다.
- 원본 파일명은 반드시 저장하되 추적·표시·사용자 확인 보조용으로만 사용하고, 확정 필터로 사용하지 않는다.
- 다상품 광고는 광고 하나 아래 `products[]`를 두고 상품별 증거와 공통 증거를 분리한다.

## 2. 현재 사이트 흐름

1. 광고물 등록
   - 광고명
   - 상품군
   - 광고유형
   - 광고 원본
   - 현재 운영 화면에는 내부 템플릿 선택란이 있으나 제거 대상
2. 파일별 광고 레코드 생성
3. 등록값을 광고별 작업 입력으로 저장
4. 광고별 비동기 자동심의 요청
5. 파서 P1/P3 생성
6. RAG 결합·검색
7. Gemma 판정
8. 결과 화면에서 규칙·근거·판정 확인

### 현재 흐름의 한계

- 여러 파일이 동일 광고의 구성물인지, 서로 다른 광고인지 표현할 수 없음.
- 한 광고에 상품이 2개 이상 포함된 구조를 등록할 수 없음.
- 운영 화면에 내부 템플릿 선택값이 노출되어 고객 입력과 내부 판정 설정의 경계가 섞여 있음.
- 현재 광고유형 값만으로 실제 심의 매체 코드와 복수 매체를 충분히 표현하지 못함.
- 후속 광고 여부와 선행 광고를 명시적으로 연결할 수 없음.

## 3. 권장 사이트 흐름

1. 접수 단위 생성
   - 여러 독립 광고를 일괄 등록하는 배치인지 확인
   - 동일 광고를 구성하는 복수 파일은 하나의 광고 자산 묶음으로 그룹화
2. 광고 기본정보 입력
   - 광고명, 상세 상품군, 매체, 광고 원본
3. 상품 카드 입력
   - 상품 1개 이상 등록
   - 상품별 상세 상품군 선택
   - 상세 상품군 코드로 내부 템플릿 자동 연결
   - 상품명·상품 기준자료·해당 파일 또는 페이지 범위 연결
4. 관련 자료 연결
   - 상품설명서·약관은 참고자료로 첨부하되 광고와의 관계 판단은 사람 검토로 보냄
   - 후속 광고이면 광고명 검색으로 선행 광고를 선택하고 사용자가 연결을 확정
5. 접수값 확인 및 동결
   - 사용자가 제공한 값은 `provided`
   - 파일에서 관측한 값은 `observed`
   - 모델 추정값은 `inferred`
6. 자동심의
   - 내부 템플릿 체크리스트 전개
   - v2 일반 규칙 검색 및 근거 매핑
   - 상품별 판정 후 광고 단위로 묶어 표시
7. 확인이 필요한 조건은 준법감시부 사람 검토로 전달

### 4.4 매체값

실제 심의사례의 매체 코드 목록을 복수 선택으로 제공한다.

- 신문(A-1), 인터넷신문(A-2), 잡지(B-1)
- 텔레비전방송(C-1), 라디오방송(C-2)
- 홈페이지(D-1), 모바일앱·앱푸시(D-2), 유튜브(D-3), 블로그(D-4)
- 소셜미디어(D-5), 검색광고(D-6)
- 포스터(E-1), 간판(E-2), 현수막(E-3), 벽면 부착물(E-4), 전광판(E-5), 대중교통(E-6)
- 전단(F-1), 팸플릿(F-2), 리플릿(F-3), LMS(G-1), 기타

`광고유형`과 `매체`는 분리한다. 예를 들어 상세페이지·배너·영상은 광고 표현 형식이고, 모바일앱·유튜브·LMS는 게재 매체다.

매체값은 일반 규칙을 제거하는 강한 필터로 사용하지 않는다. LMS·앱푸시처럼 매체 전용 의무를 추가하거나 표시 곤란 면제 가능성을 검토하는 조건으로만 사용하고, 상품 공통 표시의무와 금지규칙은 계속 검사한다.

### 4.5 자동 관측 또는 사람 확인값

아래 값은 광고 제작부서의 등록 필드로 모두 요구하지 않는다. 광고·상품자료에서 먼저 관측하고, 확정할 수 없으면 `UNKNOWN`으로 남겨 준법감시부 사람 검토에 전달한다. 확인되지 않은 `NO`로 규칙을 제외하지 않는다.

- 우대금리 존재 여부
- 보증서·보증기관 관련 여부
- 한도대출·수시상환·마이너스통장 여부
- 전세대출 여부
- 부동산·기타 담보 여부
- 대출비교플랫폼 게시 여부
- 금리·수익 계산기 제공 여부
- 생성형 AI 제작·편집 여부
- 연회비·수수료·부대비용 존재 여부
- 혜택의 실적·한도 조건 존재 여부
- 후속 광고 여부와 선행 광고

`사전심의/사후심의`는 광고 제작부서의 등록 옵션으로 두지 않는다. 일반 광고 제작부서의 신규 심의 접수는 시스템 업무 경로로 사전심의 맥락을 부여하고, 사후심의·사후보고는 별도 업무 경로나 준법감시부 확인값으로 기록한다. 따라서 등록자가 해당 용어를 몰라도 접수할 수 있어야 한다.

랜딩페이지·상품설명서·약관과 광고의 법적 관계 및 적용 범위는 자동 필터링하지 않는다. 자료 자체는 첨부할 수 있지만 관계 판정은 사람 검토 대상으로 남긴다.

## 5. 심의 데이터 파일별 확인 결과

### 5.1 심의사례 1·2·3 HWPX

- 공통 구조: `구분 / 광고문구 / 판단 / 판단근거`
- 판단 상태: `적정 / 부적정 / 확인필요 / 판단하지 않음`
- 운영 결과 매핑:
  - 적정 → `COMPLIANT`
  - 부적정 → `VIOLATION`
  - 확인필요 → `UNDETERMINED`
  - 판단하지 않음 → `NOT_APPLICABLE`
- 사례 1: 대부분 적정이나 담보 제한사항처럼 외부 상품조건이 필요한 항목은 확인필요.
- 사례 2: 후취·연 표시 누락, 금리 산식·기준일 불일치, 보증·인지세·부대비용 누락, 심의필 형식 오류 등 복수 지적을 동시에 기록.
- 사례 3: 광고에 해당 조건이 없는 부대비용은 판단하지 않음, 상품조건을 모르면 확인필요, 표현 형식 누락은 부적정으로 구분.
- 시사점: 규칙별 판정뿐 아니라 각 템플릿 `구분`별 판정과 판단근거가 결과 화면의 기본 단위가 되어야 함.

### 5.2 `1. 대출성상품-상품명 노출.xlsx`

- 28개 구분 행에 대해 예시문구, 적정 조건, 부적정 조건, 안내문구, 확인필요 조건을 제공.
- 단순 필수문구 목록보다 상세한 일반 판정 가이드에 가까움.
- v2/T의 해당 item과 연결한 뒤 Gemma 판정 가이드로 사용 가능.
- 광고별 정답이 아니라 일반 조건표이지만, v2에 없는 새 규칙을 독자적으로 생성하는 출처로 사용하면 안 됨.

### 5.3 `광고 템플릿(근거규정x, 필수 여부).hwpx`

- 19개 상품 템플릿과 각 구분의 예시문구·필수 여부·기재요령 제공.
- `O`는 필수 체크, `△`는 접수값·상품자료·광고 증거로 조건이 확인될 때 체크.
- 템플릿 기반 주 체크리스트의 원본으로 사용.
- 근거규정이 없으므로 최종 법적 근거는 v2 item과 매핑해야 함.

### 5.4 `심의사례 NH농협은행 준법감시부 1.xlsx`

- 예금성 10건, 대출성 10건의 실제 지적 사례 제공.
- 주요 열: 광고명, 복수 매체, 사전/사후, 사전 사유, 체크리스트 항목, 근거규정, 지적사유, 추가 설명, 수정 전·후.
- 접수 화면에는 매체 복수 선택이 필요함을 확인. 사전/사후와 사전 사유는 실제 사례 데이터에는 보존하되 광고 제작부서의 필수 입력으로 요구하지 않음.
- 결과 화면에는 지적유형, 근거규정, 원문, 권고 수정안 구조가 필요함을 확인.

### 5.5 규제목록 v2

- 폴더의 v2 SHA-256은 기존 확정 해시 `6989270c348983aac0e43579c25df55110aef805dccd4a2bbe926ca1fa3a8d7e`와 일치.
- 현재 문서에 정본으로 지정된 Downloads 경로의 파일은 존재하지 않음.
- 정본 경로를 새 폴더로 변경 승인하거나 Downloads 경로에 동일 파일을 복원하기 전까지 런타임이 임의로 경로를 바꾸면 안 됨.

### 5.6 `중요_NH_광고심의_규칙리스트_v3.xlsx`

- 전체 규칙 약 1,749건과 판단 기준·원문 인용·근거·관련성 판정을 포함.
- 투자·카드·기타 상품군 확장의 참고자료로 유용함.
- `임시`, `AI 확장`, 근거 확인불가·정정필요 항목이 포함되어 있음.
- 현 불변 원칙상 v2 외 규칙을 운영 판정에 넣을 수 없으므로, v3는 gap 분석과 차기 승인본 후보로만 사용.

## 6. 권장 판정 순서

1. 접수자가 상세 상품군 선택
2. 시스템이 내부 템플릿을 자동 연결하고 모든 `O` 항목 전개
3. 접수 조건·상품자료·광고 증거가 확인된 `△` 항목 전개
4. 템플릿 구분별로 충족·위반·미해당·판단불가 판정
5. v2에서 상품군 공통 금지규칙과 템플릿 밖 세부 규칙 검색
6. 템플릿 항목을 v2 법적 근거와 매핑
7. 상품별 복수 위반과 공통 위반을 광고 결과로 병합
8. 위반·판단불가는 사람 검토 대상으로 표시

## 7. 구현 전 확인할 사항

- 복수 파일이 동일 광고인지 사용자가 직접 묶는지, 접수 시스템이 이미 묶음 ID를 제공하는지
- 상세 상품군 코드와 내부 템플릿 매핑의 최종 승인 주체와 버전 관리 방식
- 한 광고에 포함된 각 상품의 파일·페이지·카드 범위를 누가 확정하는지
- 후속 광고 연결을 등록자가 확정할지 준법감시부가 검토 단계에서 확정할지
- 투자·카드 템플릿을 현 PoC 판정 범위에 포함할 시점

## 8. 판단근거 출력 계약

템플릿은 누락과 광고 내부에서 계산 가능한 오기재 탐지에 우선 사용한다. 광고 밖 상품조건이 필요한 `확인필요`는 v2 입력요건과 결합하되, 사실을 추정해 위반이나 충족으로 확정하지 않는다.

각 판정은 아래 내용을 함께 저장한다.

- `template_section`: 회사명·대출금리·부대비용 등 검토한 구분
- `rule_item_id`: 연결된 v2/T item ID
- `applicability`: 왜 이 항목이 해당·미해당인지
- `observed_evidence`: 실제 광고에서 읽은 문구·수치
- `evidence_ids`와 `line_refs`: 판단에 사용한 정확한 위치
- `expected_condition`: 템플릿과 v2가 요구하는 조건
- `comparison`: 누락·형식 오류·산식 불일치 등 실제 비교 결과
- `missing_input`: 판단에 추가로 필요한 상품조건·외부자료
- `verdict`: `COMPLIANT / VIOLATION / NOT_APPLICABLE / UNDETERMINED`
- `reason`: 관측값과 기준을 연결한 최종 판단근거

판단근거 유형도 함께 코드화한다.

- `MISSING_REQUIRED_FIELD`: 템플릿 필수 구분 누락
- `FORMAT_ERROR`: `연`, `후취`, 심의필 형식 등 표시 형식 오류
- `VALUE_MISMATCH`: 금리 산식·기준일·합계 등 광고 내부 값 불일치
- `CONDITIONAL_INPUT_MISSING`: 외부 상품조건이 없어 확인 필요
- `CONDITION_NOT_TRIGGERED`: 조건부 항목의 적용 조건이 확인되지 않음

판정 원칙은 다음과 같다.

- 필수 문구가 광고 전문에 실제로 없으면 `VIOLATION`.
- 문구와 숫자가 있고 광고 내부 정보만으로 산식·날짜·형식 오류가 확인되면 `VIOLATION`.
- 조건 자체가 광고에 없고 상품설명서 등 외부 사실이 있어야 적용 여부를 알 수 있으면 `UNDETERMINED`.
- 조건이 없다는 사실이 광고 전문과 확정 접수값으로 확인되면 `NOT_APPLICABLE`.
- 판단근거에는 단순히 “누락”이라고만 쓰지 않고, 찾은 범위·요구 문구·실제 관측·부족 입력을 명시한다.
- 누락 판정에는 특정 검색 hit 대신 `complete_ad_scan=true`와 검사한 전체 페이지·영역 범위를 남긴다.
- `UNDETERMINED`에는 `우대금리 존재 여부`, `담보 제한조건`, `생성형 AI 활용 여부`처럼 사람이 확인해야 할 입력명을 구체적으로 남긴다.
- 후속 광고 연결은 선행 광고의 판정을 복사하는 근거로 사용하지 않고, 관련 자료를 사람이 함께 열어보는 탐색 정보로만 사용한다.
