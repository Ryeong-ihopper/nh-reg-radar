# 예금·대출·투자 규칙 실행 계약

## 정본 실행 순서 — 2026-09-21

`canonical-execution-plans-v2`는 예금·대출·투자271개 계획에 같은 순서를 적용한다.

1. 코드가 확정 메타데이터와 명시 조건으로 적용조건을 TRUE/FALSE/UNKNOWN으로 계산한다.
2. 적용되는 규칙만 원자 의무별로 Rule·LLM·외부자료·사람 입력을 수집한다.
3. 예시·기준·광고증거를 구분한다. 예시는 비구속 검색·해석 힌트, 기준은 의무 정의, 광고증거는 실제 광고에서 인용한 근거다.
4. 규칙군별 짧은 프롬프트는 사실 관찰만 요청한다. 모델이 최종 판정을 계산하지 않는다.
5. 같은 규칙군만 최대4항목·복잡도12로 묶는다. 근거는 plan별 namespace를 유지한다.
6. 코드가 원자 결과의 AND/OR/NOT을 계산하고 미확정 입력을 판단불가로 보존한다.

모든 근거는 동일한 광고 ID·상품 ID·개정 ID·검토범위 ID를 가져야 한다. 외부자료 비교는 검증된 외부자료 근거가 별도로 있어야 한다. 누락 판정은 관련 광고 범위 전체 판독이 확인된 경우에만 가능하다. 시각 속성은 자동 충족·위반으로 확정하지 않는다.

## 2026-09-21 로컬 계산 계획 추가(운영 미연결)

`build_methodology_execution_review.py`는 원본과 답지를 열지 않고 지정 추출본 다섯 개 및
기존273행 CSV만 읽는다. 해시가 바뀌면 기존 대응·계산식을 재사용하지 않는다. 신규77행의
대응과 예금16행→14계획을 생성한다. `evaluate_structured_plan.py`는 검증된 입력 JSON으로
단일 계획을 재생하며 새 출력 파일만 쓴다. 서비스의 저장 결과와 상태는 변경하지 않는다.

`structured_predicates.py`가 실제 3값 조건 계산과 Decimal 비교를 담당한다. 조건 미확정은
분기를 선택하지 않는다. ALL의 독립 미충족은 위반, ANY의 한 가지 완전 충족은 충족이다.
숫자는 동일 단위·광고·상품·버전·검토범위에서 비교하고 구성값 목록은 완전성을 요구한다.
모델은 사실 후보를 제시하고 독립 검증자가 evidence/scan 검증 플래그를 부여한다. 이 모듈이
LLM 인용의 의미적 정확성을 스스로 검증하거나 광고를 직접 판독하는 것은 아니다.

14개 계획 중5개에는 가입대상 예외의 버전 충돌, 한 달/30일, LMS+링크의 로고 처리,
예금 자료의 대출 줄바꿈 문구라는4종 쟁점이 남아 있다. 계산 가능한 나머지 원자는 유지한다.
필수 검색 질의는 의무 개념을 사용하며 예시가 없는 항목도 질의를 갖도록 설계했다. 해당 검색
계획과 새 판정 계획은 운영 미연결이고 실제 광고 재측정은 진행하지 않았다.

## 현재 실행에 연결한 부분

예금·대출·투자를 먼저 안정화한다. 원문 조건을 코드가 임의로 해석하지 않으며, 원문에 명시된 검사 구조와 LLM이 반환한 요소별 판정을 분리한다. 이 변경은 ADR-0013의 Rule/RAG/LLM 역할 분리를 실행하는 공통 구현이다.

2026-09-21 신규 심의방법 추출본77행은 별도 `structured-review-methodology-v1` 산출물로
구조화했지만 이 절의 현재 실행 범위에는 아직 포함하지 않는다. 대출 회사명 확인필요 전환,
대출 유의사항 공통 줄 구조 규칙, 퇴직연금 기본+운용상품 추가 템플릿 결합과 복합 광고의
비보호 로고 면제를 먼저 표현했다. 기존 템플릿/v2와 의무 단위 중복을 대조하고 필요한 비교
입력을 확정한 뒤에만 실행 후보로 승격한다.

물리 규칙305개에 대한 실행 전 라우팅 계약도 작성했다. 모든 항목의 적용조건은 Rule 3값
게이트가 담당하고, 내용 판정은 정형 Rule·LLM 의미판단·사람 시각검토로 분리한다. 이는 전수
구조 감사이며 현재 실행 후보를305개로 확대하지 않는다. 추가 후보29개는 원자 의무 승인 전,
시각 항목은 사람 검토 연결 확인 전 자동 판정하지 않는다.

1. `compile_condition_contract`가 각 원문 의무에 O 참조와 `obligation_logic`를 부여한다. `all`은 모두 충족, `any`는 한 가지 완전한 방식 충족이다. 표현에 모든 O가 포함되어야 하며 모델도 모든 O의 결과를 원문 순서대로 반환해야 한다.
2. 일반 템플릿의 명시적 `[방식 N]` 묶음만 택일식으로 만든다. 각 구성 항목이 필수 O이고 원문 위치·내용이 있으며 별도 적용조건·사람 확인·가이드 의무가 없는 경우에 한정한다. 조건부 △, 미확정 해석, 일반 문장의 접속사는 자동 분해하지 않는다.
3. 각 방식의 전체 문언을 보존하고, 기존 추출기가 식별하는 명시적 기준일 요건·인용 표시 요건은 그 방식 안에 묶는다. `any(all(O1,O2),all(O3,O4))`에서 O1과 O4만 충족하는 것은 전체 충족이 아니다. 예시 문구·금액의 완전일치를 의무로 만들지 않는다.
4. 원문 범위·발동조건·검토조건을 먼저 확인한다. LLM은 각 의무의 의미와 증거를 판정하며, 코드는 원문 줄 인용·증거 범위·판독 상태·전체 판독에 근거한 누락 주장과 논리 결합을 검증한다. 결합식과 전체 판정이 다르면 계약 오류로 재시도/확인 필요 처리한다. 코드가 LLM의 의미 판단 정확성까지 보장하는 것은 아니다.
5. 프롬프트는 공통 ALL/ANY 지침과 합성 논리 예시 4개를 전달한다. 고객 광고·정답 예시는 사용하지 않는다. 긴 사고 과정 대신 의무별 짧은 직접 인용과 사유를 요청한다.
6. 명시 규칙 관계는 의존 순서대로 계산한다. 순환·없는 대상을 거절하고 적용성 미확정/제외 결과로 충족을 승계하지 않는다. 현재 `SATISFIED_IF`에는 의무별 부분 포함 정보가 없으므로 여러 독립 O를 한 번에 O1로 치환하지 않는다. 이 경우 자체 판정을 보존한다.

| 요소별 판정 | 결합 | 전체 판정 |
| --- | --- | --- |
| 충족 + 미확정 | ALL | 판단불가 |
| 확정 미충족 + 미확정 | ALL | 위반 |
| 충족 + 미확정 | ANY | 충족 |
| 확정 미충족 + 미확정 | ANY | 판단불가 |

표는 적용·예외 게이트와 증거 검증을 통과했을 때의 논리다. 검색 실패는 누락 근거가 아니며, 미확정 발동조건을 적용 제외로 처리하지 않는다. 기존 동결 계약에 결합식이 없으면 기존 검증을 유지한다. 기존 결과·상태·원본은 변경하지 않는다.

## 후보 수와 실행 범위

추가 후보 42개를 업권·대상 템플릿 범위로 재검토한 결과는 **유지 29개 + 근거 분리 6개 + 카드 한정 2개 + 확인 보류 5개**다. 29개는 42개 안의 관련성 부분집합이며 전체 검색·검토 후보 수가 아니다. 42개 바깥의 세부상품 조건부 규칙과 사람 검토 규칙도 각 발동조건이 맞으면 후보로 유지한다. `C-046`·`D-184`는 상품·내용 조건부, `D-240`은 사람 시각 검토 후보로 분리한다. C-018은 유지 후보에 포함한다. 29개도 개별 조건·직접 근거·중복 대조가 남아 있어 전체를 활성화하지 않았다.

정식 후보 정책은 `TEMPLATE_PRIMARY + MEDIA_CONDITIONED_V2 + PRODUCT_CONTENT_CONDITIONED_V2 + 명시 관계 의존 규칙`이다. 내용 조건부 티어는 승인 정책에 등록된 원문 행이 광고 근거 검색에서 발견됐을 때만 진입한다. 현재 등록 항목은 `C-046`, `D-184` 두 개다. `D-240`은 같은 검색 경로를 사용하지만 자동 판정 없이 검색 근거 위치와 함께 사람 검토로 보낸다. 정책 파일은 규제 원문 SHA와 원문 구절을 함께 검증하며 불일치하면 실행을 중단한다. 이 변경으로 29개 또는 42개를 일괄 실행하지 않는다. 템플릿 매핑 자체는 추가 판정 행을 만드는 조건이 아니다. 카드 확대는 세 상품군의 검증 이후에 진행한다.

## 원문 감사와 검증 범위

일반 HWPX와 지정된 기존 v2 파일을 오프라인으로 읽은 감사는 462항목(운영 어댑터의 템플릿 206 + v2 256)을 포함했다. **이는 후보 실행 수가 아니다.** 템플릿은 예금 78·대출 55·투자 73이며 물리 셀 수와 다르다. 카드는 운영 어댑터에서 제외된다.

| 구조 | 수 | 해석 |
| --- | ---: | --- |
| 원문 문단 유지 | 456 | 세부 조건·의무가 모두 독립 계산된다는 보장 없음 |
| 원문 + 명시 요구 | 3 | 기존 추출 가능한 요구를 별도 확인 |
| 원문에 명시된 택일 방식 | 3 | 예금 금리 표시 방법의 세 방식·방식별 요건을 결합 |

감사 도구는 `rag-pipeline/tools/audit_rule_execution.py`다. 예측·정답을 읽거나 외부 모델을 호출하지 않으며 이미 있는 출력 경로에는 쓰지 않는다. 운영 진입점도 `00_compiled_obligation_audit.json`을 남긴다. 원문 SHA·규칙별 구조·O 개수·결합식이 기록되며 표현식 검사 통과와 원문 전체 의미 분해 완료를 구분한다.

로컬 산출물은 `temp/rule-execution-design-20260921/source-execution-audit-v2.json`이다. 감사에 쓴 템플릿 SHA는 `292ddb87daf596a55d47d69b3bb6519c546dee9f5b4bbd9d90d4459220d98f3f`, v2 SHA는 `6989270c348983aac0e43579c25df55110aef805dccd4a2bbe926ca1fa3a8d7e`다. 후자는 C-008 등 해석 개정 전 파일이므로 현재 승인 규정의 효과나 운영 활성 목록을 측정한 것으로 해석하지 않는다.

RAG 전체 494개 테스트가 통과했다. 이 중 신규 결합식 테스트 18개와 규칙 관계 테스트 6개는 합성 논리, 조건·의무 누락 거절, 방식별 날짜 요건, 모델 입력 축약→응답 복원→실제 검증기 재생, 관계 순서·순환·부분 의무 보존을 확인한다. 조건부 정책의 원문 해시·구절 드리프트 차단, 검색과 원문 발동표현을 모두 통과한 정책 항목만 승격, 시인성 후보의 검색 근거 보존도 확인한다. 이 수치는 실제 규정 해석이나 광고 판정 정확도가 아니다.

변경 Python 파일 Ruff와 `doc_guard impact/validate --scope working`도 통과했다. `check-doc-consistency.sh`는 WSL Bash의 `E_ACCESSDENIED`, 전체 governance는 Docker 설정 접근 거부 및 실행 엔진 부재로 완료하지 못했다. 환경 검사를 생략해 전체 통과로 보고하지 않는다. 외부 전송·서비스 재시작·커밋·푸시는 수행하지 않았다.

## 남은 적용 작업

1. 현재 승인 원문 버전을 고정하고 템플릿과 유지 후보 29개를 항목별로 분해한다. 조건·예외·의무·권고·비교 입력·근거 위치·미확정 해석을 기록한다. 원문 문단을 O1 하나로 전달한 항목은 분해 완료로 세지 않는다.
2. 추가 후보는 상품·업무·매체·광고 내용의 객관적 발동조건과 템플릿 의무 대조를 갖춘 뒤 실행에 연결한다. 부분 중복은 남은 의무를 특정할 수 있을 때만 별도 검사한다. 근거 분리 6개는 은행에 적용되는 문언부터 분리한다.
3. 비교형 의무의 양쪽 자료를 상품·기간·버전·단위·출처와 함께 연결한다. 자료가 없거나 서로 다른 상품이면 추정 비교하지 않는다. 해당 슬롯 계약은 이전 로컬 시제품에만 있으며 운영 연결은 남아 있다.
4. 예측·원문·실행 버전을 먼저 고정한 새 회차를 별도 평가한다. 템플릿과 추가 규칙의 적용성·충족·위반을 함께 채점하고 미채점 출처를 드러낸다. 기존 사례는 DEV_REGRESSION이며 일반화 성능은 별도 holdout에서만 측정한다.
