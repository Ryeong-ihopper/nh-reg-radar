# 예금·대출·투자 규칙 실행 계약

## 현재 정본과 운영 범위 — 2026-09-29

[ADR-0086](adr/ADR-0086-source-bound-review-program-runtime.md)과
[ADR-0087](adr/ADR-0087-product-composition-and-evidence-policy.md)의 승인 계약을 따른다.
`canonical-execution-plans-v2.json`은 템플릿239·보완32의271계획이며 운영은
`template-only`의 템플릿239·보완0이다. `review-worklist-v1.json`의305행은
템플릿239·보완32·추가34의 검토 대장으로, 자동 실행 수나 의미 검증 완료 수가 아니다.
보완32·추가34와 물리 줄 미인증33원자의 자동 활성화는 하지 않는다.

## 실제 실행과 검증 순서

1. 승인 원문·정본 계획·migration·disposition·정책의 출처 및 결합 해시를 확인한다.
   선택 템플릿의 필수 항목은 검색 발견 여부와 무관하게 전개한다.
2. 확정 상품·매체와 원문에 명시된 조건·예외를 TRUE/FALSE/UNKNOWN으로 계산한다.
   확인된 미해당은 판정에서 제외하되 이유를 감사 기록에 남긴다. 미확정은 숨기지 않는다.
3. 원자 의무·담당·AND/OR 분기와 역할별 근거 검색을 동결 요청에 연결한다.
   Rule은 검증된 구조·수치, LLM은 의미 관찰, 사람은 시각·해석 미확정 검토를 담당한다.
4. 모델 입력 압축은 원문 기준·조건·의무·예외·허용 결과·출처를 보존한다.
   원자별 관찰과 직접 인용을 받아 원자·증거 ID를 복원하고 출력 계약을 검사한다.
5. 코드는 원자별 결과와 인용·판독·범위 계약을 확인하고 원문 결합식을 계산한다.
   정본 gate나 코드 종합을 우회해 모델의 전체 적정을 그대로 확정하지 않는다.
6. 요청·예측·최종 결과·추적을 저장한다. 결과 화면은 해당 동결 요청의 근거를 표시하며
   현재 자료를 과거 판단에 소급 연결하거나 조회 중 재심의하지 않는다.

`operational_catalog.py`, `condition_contracts.py`, `family_prompts.py`,
`run_operational_e2e.py`, `run_gemma_exhaustive_dgx.py`, `review_program.py` 및
`validate.py`가 위 경계를 연결한다. 독립 계획 계산기 `execution_plan_runtime.py`는
생성 결과와 논리의 참고 평가에 사용하며 실제 운영 실행을 대신하지 않는다.
이 계산기를 사용하던 별도 시제품 요청 생성 경로는 참조 대조 후 제거했다.

## 원문·광고·외부 입력의 경계

예시 표현·숫자는 비구속 해석 힌트이며 완전일치 의무나 광고 증거가 아니다.
연락처 마스킹은 기재 존재로 인정한다. 퇴직연금의16.5%·1억원은 고정 의무로 만들지
않고 원문 관계와 상품·기간·단위·판본을 확인한다. 선입 원문을 임의로 고치지 않는다.
조건 없는 항목에 조건을 추가하거나 확인전용 항목을 자동 적정으로 만들지 않는다.

원자 근거는 동일 광고·상품·판본·검토범위에 대응해야 한다. 숫자 비교는 양쪽 자료의
단위·기간·출처가 확인될 때만 수행한다. 외부자료가 없거나 금융 해석이 미확정이면
추측하지 않고 원문·반례와 함께 확인필요로 남긴다. 검색 실패는 누락 증거가 아니다.
관련 범위의 전체 판독이 확인되지 않으면 누락 위반을 확정하지 않는다.

심의필 번호의 마스킹 존재, 연결 유효기간 범위, 전체 적정은 별도 검사다.
실제 승인·발급 조회와 달력 날짜 대조는 미구현이다. 미구현 외부 대조를 수행한 것으로
표시하지 않는다.

## 결합식과 계산 근거

각 방식 안의 독립 의무는 AND, 완전한 대체 방식 사이에는 OR를 적용한다.
서로 다른 방식의 일부 의무를 섞어 전체 충족으로 만들지 않는다. 원문 조건을 충족한
대안만 계산하고 확인되지 않은 발동조건을 적용 제외로 바꾸지 않는다.

| 원자 결과 | 결합 | 전체 결과 |
| --- | --- | --- |
| 충족 + 미확정 | AND | 확인필요 |
| 확정 미충족 + 미확정 | AND | 부적정 |
| 충족 + 미확정 | OR | 적정 |
| 확정 미충족 + 미확정 | OR | 확인필요 |

표는 적용·예외·증거 검증을 통과한 원자의 논리다. 실제 금융 해석의 정확도 인증은 아니다.
우대금리 합산은 확인된 표 셀·머리글·각주와 같은 범위의 연 % 또는 연 %p를 사용한다.
전체 조건 개수·최대값·피연산자의 직접 인용이 필요하며 단위 혼합·중복 제한·택일·
불명확한 각주·반올림은 확인필요로 남긴다. 합산이 가능해도 외부자료 적용성과 시각 검사를
자동 확정하지 않는다. 별도 n개 이상 대안의 수치 검증은 구현 범위와 구별한다.

## 판독·좌표·화면

P1v4/P3v9와 실제 원문 줄·문자·bbox·출처를 보존한다. 영역 라벨은 의미 힌트이고
물리 줄 증거가 아니다. 물리 줄 미인증33원자는 사람 담당으로 유지한다.
HWP의 기본 보기는 심의 이미지, HTML은 격리 본문 읽기다. HTML에 이미지 bbox를
겹치지 않는다. 추출 실패·부분 누락·불확실 판독·미검증 복구·좌표 없음·기록 없음을
구별하며 좌표 없는 판독 경고도 확인필요로 남긴다. EXTRACTED는 정확도 보장이 아니다.
confidence를 신뢰도 백분율로 표시하지 않는다.

## 생성·평가·운영의 구분

정본 컴파일러·심의방법 구조화 생성기·독립 계산기·평가기·현재 회귀 테스트·DB 이행은
저장소에 보존한다. 운영 직접 호출이 없다는 이유로 삭제하지 않는다. 생성기의 원문·
출처 해시와 대응 관계 검사는 유지하며 새 판본의 해석 미확정은 승인 전 활성화하지 않는다.
gold와 사례 O/X·사유는 예측 해시 동결 후 별도 평가에서만 읽는다. 개발 사례는
DEV_REGRESSION이며 일반화는 별도 holdout으로 확인한다. 운영 판정 경로는 gold를 읽지 않는다.

최종 운영 `/app`은 `infra/operational/runtime-files.json`의125파일과 현재 화면 산출물,
출처 manifest로 제한한다. requirements는 설치 단계에서만 쓰며 예시 설정·제안 schema·
오프라인 생성·평가·테스트·CI·DB 이행 파일과 대체된 화면 산출물은 넣지 않는다.
공유 요청 생성·운영 복구·정본 config/schema는 실행 목록에 남긴다.

## 확인 범위와 미완료 작업

구조의 존재·정적 도달 가능성·단위 테스트 통과를 원문 의미 전수검증이나239항목의
판정 정확도로 해석하지 않는다. 항목별 적용조건·원자·담당·실행·인용·양성/음성/경계
반례를 계속 확인한다. 추천 AI 생성·채택 DB 저장, 법령 전체 조문 검색·개정 이력,
사용자 수정·재추출 작업대는 미연동이다.

현재 적용 이미지와 검사 영수증은 [인수인계](handoff-current.md), 기능 계약과
검사 항목은 [기능명세](functional-specification.md)·[테스트케이스](test-cases.md)를 따른다.
대체된 설계·정적 감사·옛 배포 보고서는 활성 문서에서 제거했으며 Git 이력과
무시되는 정리 사본으로 보존한다. Accepted ADR·원문 계보·동결 결과는 유지한다.
