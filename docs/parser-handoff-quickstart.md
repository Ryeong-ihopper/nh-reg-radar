## 현행 시인성·판독 불확실성 처리 범위

2026-09-15 사용자 결정: 현재 파서는 원문 위치를 위한 bbox만 제공하는 범위로 진행한다. 색상·폰트·글자 크기·대비·가독성·시인성·레이아웃 판정은 사람 검토로 넘기며 측정 기능 개발을 선행조건으로 요구하지 않는다. 기존 style 값이나 bbox가 있더라도 자동 시인성 판정을 재활성화하지 않는다. 좌표는 원문 위치 확인용이며 글자 크기나 색상을 추정하는 근거가 아니다.

현재 필수 전달 범위는 전체 원문, 원문 위치 bbox와 페이지/이미지 좌표 기준, 파일 대응, 읽기 실패/불확실성이다. 글자 크기·굵기·색상·대비는 신규 추출 요청에서 제외한다. 기존 원시값이 있으면 보존할 수 있지만 자동 판정에는 사용하지 않는다. 표 구조는 있으면 보존하고 없거나 불명확하면 사람 검토한다.


## 1. 목적과 확인 범위

코덱스에게 전달할 때는 [독립 인수인계 패킷](parser-agent-handoff.md) 하나를 전달한다. 확인한 commit·책임 경계·필요 정보와 이유·합성 데이터 형태·수용 테스트·회신 형식을 포함하며 다른 로컬 파일 없이 읽을 수 있다. 새 운영 API 계약은 아니다.

**광고 원문과 위치·읽기 상태를 손실 없이 받으면, 심의용 스키마 변환과 판정은 저희가 합니다.**

확인 저장소: [nh-custon-parser main](https://github.com/cg-wnsdud/nh-custon-parser/tree/23d1dcc25fd4c70f4ad1cc1bc6ba0a3214306a4e).
최신 커밋은 `23d1dcc`로 이전 점검과 같습니다. 소스·모의 테스트15개를 확인했으며 실제 ETL/OCR 실행 결과를 검수한 것은 아닙니다. 아래는 OCR 오독을 단정하는 목록이 아니라 **심의에 필요한 정보의 전달 요청**입니다.

현재 HRC에는 본문·일부 페이지 정보만 전달되고, 내부에서 읽은 줄·bbox·신뢰도는 빠집니다. 따라서 **HRC만 받는 것은 부족합니다. 원시 ETL Default JSON을 보존·제공하는 경로를 먼저 협의해 주세요.** 원시 결과에 이미 있는 값은 재파싱 없이 전달만 보완하면 됩니다.

## 2. 파서/ETL 쪽에 요청하는 것

| 요청 | 이미 원시 결과에 있으면 | 원시 결과에도 없거나 잘못 읽었으면 |
| --- | --- | --- |
| **전체 원문**: 모든 페이지·영역·줄, 작은 글씨, 표 셀 내용 | 선택·요약 과정에서 버리지 말고 전달 | 누락/오독 범위를 표시하고 재판독 또는 추출 보강 |
| **원본 위치**: 페이지·영역·줄 bbox, 기준 이미지 크기·좌표 단위·회전/크롭 정보 | 그대로 전달. 페이지 번호 0/1 시작 기준 명시 | 원본 위치 추출 보강. 없는 좌표를 임의 생성하지 않음 |
| **읽기 상태**: 실패/미처리/빈 페이지 구분, 불확실한 영역·사유, 제공 가능한 신뢰도 | 경고·오류를 HRC 변환 과정에서 버리지 않음 | 검출 불가 범위를 명시. 프로세스 성공을 전체 판독 완료로 간주하지 않음 |
| **표 구조**: 행·열·병합·셀 내용·위치 | HTML 또는 원시 셀 구조 보존. 본문이 빈 표도 셀을 버리지 않음 | 표 추출 보강 또는 구조 미확정 표시 |
| **시인성 원시값**: 글자 크기·굵기·색상 등 실제 제공 가능한 관측 | 값·단위·출처와 함께 전달 | 지원 여부부터 회신. 미지원 값은 null/unknown; 이미지 px를 pt로 추정하지 않음 |

**후보 텍스트를 선택하는 기능이 있을 때만:** OCR/VLM 원문 후보를 보존하고, 선택 결과가 실제 포함하는 줄/영역과 `needs_review`를 전달해 주세요. 한 영역의 일부 표만 읽고 영역 전체를 읽었다고 표시하면 안 됩니다. 후보 선택 기능이나 P1/P3 출력을 새로 만드는 것 자체는 필수 요청이 아닙니다.

## 3. 저희가 후처리하는 것 — 파서에 구현 요청하지 않음

- 광고/파일 ID·해시와 사용자 확정 상세 상품군·매체 관리 및 주입. 반환 결과를 업로드 파일과 확실히 대응시킬 키만 있으면 됩니다.
- 줄·영역 원시 구조가 있으면 일관된 내부 ID 부여, 파일별 페이지 정규화, 광고 묶음/상품 범위 결합.
- 심의용 스키마 변환, 청킹, 검색, 템플릿/v2 연결, 규칙 적용·판정·사람 검토 라우팅.
- 제공된 좌표의 화면 변환과 bbox 강조. 원본 위치나 변환 기준 자체가 없으면 복원 불가.
- 표 제목·각주 관계의 연결/검색 활용. 파서가 관찰 관계를 이미 제공하면 활용하고, 저희가 추론한 관계는 관측 사실과 구분.
- 광고 의미 라벨은 선택 사항. 라벨이 없어도 심의를 막지 않으며, 라벨 설명을 광고 원문으로 사용하지 않음.

`needs_review`를 확정 차단에 반영하지 못한 문제, 부모 영역 스타일 전달, 충족 수치/조건 인용 검사 등은 **우리 연결부 수정 대상**이며 파서 담당자에게 넘기지 않습니다.

## 4. 우선 회신·납품 요청

1. **같은 원본 1건 + 실제 ETL Default JSON + 최종 HRC ZIP**을 내부 승인 경로로 제공해 주세요. 어려운 작은 글씨·표가 있는 자료부터 원문과 단계별 결과를 대조하겠습니다.
2. 위 표의 각 항목에 대해 **현재 필드 경로 / 전달만 수정 / 추가 추출 필요 / 제공 불가**를 표시해 주세요. 확인한 실제 배포 커밋도 함께 알려 주세요.
3. 원시 JSON을 받을 방법을 정해 주세요. **KL ZIP 허용 형식은 유지**하고, 승인된 별도 파일·저장소 참조·API 또는 허용 메타데이터 경로를 사용합니다.
4. 일부 판독 실패가 있어도 성공한 본문은 보존하고, 실패 위치와 사유를 함께 반환해 주세요.

[심의용 JSON 예시](../rag-pipeline/schemas/proposals/parser-handoff.example.json)는 **우리 최종 입력 모양을 설명하는 참고 자료**입니다. 파서가 모든 필드를 직접 생성하거나 이 모양으로 전면 교체해야 한다는 요구가 아닙니다. 사용자 입력·내부 ID는 우리가 보완하며, 예시에 없는 이미지 대비 측정은 지원 방식을 별도 협의합니다.

**최소 수용 기준:** 원문 누락 없이 대조 가능 / bbox가 같은 파일·페이지의 문구를 가리킴 / 부분 읽기를 전체 완료로 승격하지 않음 / 원시 결과와 최종 결과의 파일 대응 가능.
