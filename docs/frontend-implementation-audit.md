## 감사 결과

`docs/screen-specification.md`의 S-002~S-008, S-014~S-016과 구현 route를 대조했다. 각 화면의 API 호출, loading/empty/error/권한 상태 및 핵심 action은 구현되어 있다. 다만 화면기획서 3.1의 **좌측 메뉴 + 상단 헤더 + 콘텐츠 영역** 기본 레이아웃은 기존 구현에서 상단 링크만 제공되어 있었고, 공통 UI도 화면별 카드·표·입력 상태의 위계가 약했다.

| 영역 | 구현 상태 | 개편 기준 |
| --- | --- | --- |
| 공통 레이아웃 | 부분 구현 | 역할 기반 좌측 탐색, 상단 사용자 컨텍스트, 넓은 업무 콘텐츠 영역을 제공 |
| S-002/S-014/S-015 | 기능 구현 | 검색·표·관리 패널의 밀도와 행/행동 위계를 정리 |
| S-003/S-004 | 기능 구현 | 폼을 명확한 필드 그룹과 primary action 중심으로 표현 |
| S-005 | 기능 구현 | 진행률·단계·terminal 상태를 구분 가능한 timeline surface로 표현 |
| S-006/S-016 | 기능 구현 | KPI 카드·위험도·다음 행동의 우선순위를 강화 |
| S-007/S-008 | 기능 구현 | 원본/목록/세부 패널 경계와 선택 상태를 강화 |
| 반응형·접근성 | 기본 구현 | 768px 이하 탐색 전환, 명확한 focus 및 reduced motion 지원 |

## 로컬 사용자 화면 캡처 검증

실제 로컬 계정으로 로그인한 브라우저 흐름을 재현하기 위해 `apps/frontend`에 개발 의존성 Playwright와 `npm run visual:local`을 둔다. 인증 정보는 저장소에 기록하지 않고 아래 환경변수로만 주입한다. 캡처 산출물은 기본적으로 `/tmp/nh-ad-compliance-visual`에 저장되며 Git 추적에서 제외한다.

```bash
cd apps/frontend
LOCAL_UI_EMAIL='...' LOCAL_UI_PASSWORD='...' npm run visual:local
```

검증 대상은 1440px viewport의 로그인(S-001), 역할 기반 업무공간·광고물 목록(S-002), 광고물 등록(S-003)이다. 기준 디자인 이미지가 아직 없으므로 현재 검증은 화면기획서의 구조·레이블·권한 메뉴와 실제 렌더링 품질 확인까지이며, 픽셀 baseline 비교는 디자인 시안 제공 후 추가한다.

## 개편 범위와 비범위

- 범위: 구조, 공통 디자인 토큰, navigation, 표·폼·상태·결과 surface, 반응형과 focus 상태
- 비범위: API 계약, route, 권한 규칙, AI 검토 정책, 화면기획서의 업무 action 추가/삭제

상세 디자인 결정은 루트 `DESIGN.md`를 따른다.
