# 화면설계서

## 금리 근거 분리와 기재 방식 집계 — 2026-09-30

동결 요청의 logical_group_id와 전체 구성원이 일치하는 기재 방식은 하나의 카드로 집계하고 원래 검사들은 상세에 보존한다. 구성원 누락·결론 충돌은 확인필요로 표시한다. 광고 문구는 원문 줄별로 나누고 각 문구의 위치 버튼은 그 줄의 좌표만 표시한다. 확정 사유와 별도 확인필요를 줄을 나누어 표시한다. 기존 저장 결과를 새 판단식으로 재심의하지 않는다.

원문 위치 안내는 확정된 문구 누락, 근거 검증 실패, 판독 불확실성, 좌표 미연결을 구분한다. 확인필요나 인용 부재를 누락으로 단정하지 않는다.

판정 필터는 같은 폭·높이와 글자/건수 수직 정렬을 사용한다. 전체는 회색, 적정은 녹색, 부적정은 붉은색, 확인필요는 황갈색으로 구분한다. 선택 상태는 배경·테두리·글자 색상만 바꾸며 하단 강조선은 사용하지 않는다. 판정명과 건수는 고정된 두 열과 같은 글자 크기·줄 높이로 정렬하고 밝은 배경에 흰 글자를 사용하지 않는다.

## 운영 심의 결과의 항목별 보기와 원문 이동 — 2026-09-30

결과 화면은 광고 원문과 항목별 판정을 같은 화면에 고정한다. 오른쪽 목록에는 전체·적정·부적정·확인필요 필터를 두고 해당없음 판정이 있으면 해당없음도 표시한다. 각 선택 버튼은 항목명과 저장된 판정 사유의 간략한 내용을 함께 표시하며 번호·본문·판정 표시를 정렬한다. 좌표가 연결된 항목에 커서를 올리거나 상세의 원문 위치 보기를 누르면 해당 원문 bbox로 이동한다. 좌표가 없으면 임의 위치를 만들지 않고 버튼을 비활성화하고 이유를 표시한다. 상단 내보내기 버튼은 제거하고 추천 문구·수정 초안과 PDF 저장·인쇄 버튼의 크기와 색을 통일한다. 저장 결과와 JSON API는 변경하지 않는다.

## 광고 등록의 심의 흐름 안내 제거 — 2026-09-30

광고 등록 화면에서 접이식 `심의 흐름과 적용 기준 보기` 안내와 그 안의 구조화 작업대장 링크를 표시하지 않는다. 별도 구조화 작업대장 화면과 등록·심의 동작은 유지한다.

## 광고 형식·매체 선택 축약 — 2026-09-30

운영 등록의 매체 선택은 19개 개별 코드 대신 11개 대표 선택지로 표시하고 `기타`는 제거한다. 단문 문자·장문 문자(LMS)·멀티미디어 문자(MMS)·앱 푸시·이메일·알림톡은 전송 형식에 따른 판정 차이를 위해 구별한다. 배너와 팝업, 웹·앱 상세와 이벤트 페이지, SNS와 검색 광고, 문서·인쇄·현장·옥외 광고는 각각 한 선택지로 묶는다. 영상은 별도로 둔다. 기존 저장값과 API 코드 목록은 유지한다. 아래 2026-09-30의 19개 선택지·기타 안내보다 이 결정이 우선한다.

## IRP 펀드 광고의 추가 운용상품 — 2026-09-30

IRP 펀드상품 노출을 선택하면 펀드는 기본 분류에 포함된 것으로 표시하고 ETF·ELB만 추가 복수 체크한다. 두 상품 모두 언급 없음과 기타 운용상품 확인필요를 구분하며 선택값 변경 시 기존 체크를 지운다. IRP 금융투자상품 미노출에는 이 선택칸을 표시하지 않는다. 결과 표·상세·원문 표시의 중복된 단순 재수출 파일은 제거하고 실제 구현 파일을 진입점으로 사용한다. 개발용 비운영 등록·결과 경로는 여전히 호출되므로 보존한다.

## IRP 선택지 구분과 등록 안내 축약 — 2026-09-30

투자성 상세 상품군은 일반 심의방법과 IRP 전용 심의방법을 별도 묶음으로 표시한다. IRP의 금융투자상품 미노출·펀드상품 노출은 원문이 다른 독립 템플릿이므로 퇴직연금 일반의 운용상품 복수 체크로 바꾸거나 숨기지 않는다. 매체·상품군·상세 상품군 선택 아래 도움말, 운용상품 선택 아래 설명, 파일 선택 아래 안내와 광고 추가 버튼 아래 안내는 제거한다. 필수 선택지·확인 필요 표기·파일 오류 검사는 유지한다.

## 광고 매체·퇴직연금 운용상품 선택 — 2026-09-30

등록 화면의 광고 형식·매체는 기존 코드를 유지하고 문자·직접 전송, 웹·앱, 문서·인쇄·현장·영상으로 묶어 보여준다. 실제 템플릿의 LMS 조건을 선택할 수 있도록 LMS를 추가하고 MMS·검색 광고·팝업 광고도 별도 매체 코드로 제공한다. 기준자료 관리의 매체 필터에도 같은 코드를 표시한다. 매체 코드는 광고 등록과 운영 입력에 같은 값으로 저장한다. 새 코드만으로 비활성 보완·추가 규칙을 활성화하지 않는다. 나열되지 않은 매체는 기타를 사용하며 목록을 법정 완결 목록으로 안내하지 않는다.

일반 퇴직연금의 상세 상품군은 공통 하나로 표시하고 IRP 전용 두 분류는 별도로 유지한다. 퇴직연금 일반을 고르면 아래에 펀드·ETF·ELB 복수 체크와 세 상품 언급 없음, 기타 운용상품 확인 필요 선택이 나타난다. 정기예금 등은 퇴직연금 운용이 가능하지만 현재 연결된 별도 정본 기준이 없으므로 자동 적용 상품으로 취급하지 않는다. 기타를 고르면 범위를 미확정으로 보존하고 사람 검토로 보낸다. 지원되는 상품과 기타가 함께 나온 경우에도 전체 운용상품 범위는 확인 필요다.

## 선택 배경과 글자 대비 — 2026-09-29

진한 녹색 버튼은 흰색 글자를, 연두색·연한 녹색 선택 배경은 검정 계열 글자를 사용한다.
심의 기준 목록·법령 근거 목록·광고 선택 목록·결과 집계 카드에서 선택·마우스 올림·
키보드 포커스 상태의 배경과 글자색을 함께 지정한다. 공통 버튼의 흰색 호버 글자색이
연한 배경에 남지 않도록 하며, 목록의 보조 설명도 같은 상태의 어두운 글자색을 따른다.
글자 대비는 일반 텍스트 기준4.5:1 이상을 확인하고 키보드 포커스 윤곽선을 유지한다.

## 체크박스 표시와 운용상품 안내 — 2026-09-29

모든 체크박스와 라디오 선택칸을 일반 텍스트 입력 스타일에서 제외한다. 작은 기본 선택칸, 여백0, 투명 배경, 그림자 없음으로 표시해 선택칸 위아래의 희미한 직사각형을 제거한다. 키보드 포커스 표시는 유지한다. 퇴직연금 직접 선택은 아래 운용상품 체크에 자동 반영하며 같은 상품을 다시 고르지 않는다. 아래 선택칸은 한 광고에 여러 운용상품이 함께 있을 때 추가 선택하는 용도다. 등록 화면 안내는 이 선택 관계로 줄이고 예금자 비보호 문구/로고의 판정 설명은 기준표에서 확인한다.

## 파일·페이지별 추출 상태 표시 — 2026-09-29

저장된 파서 관찰에서 파일·페이지별 추출 상태를 읽기 전용으로 표시한다. 처리 완료와 추출 정확성을 구별하며 confidence를 신뢰도 백분율로 변환하지 않는다. 완전 실패/파일 실패, 부분 판독·빈 영역, 불확실 판독, 좌표 없음, 미검증 복구 후보, 기록 없음과 모델 출력 실패를 구분한다. 좌표 없는 판독 확인 대상도 숨기지 않고 파일·페이지의 원본 대조 대상으로 남긴다. 원본 P1/P3·저장 예측·법령 판본·상태는 변경하지 않는다.

진행 화면은 작업 종료 후 추출 상태를 조회하고 결과 화면과 같은 컴포넌트로 표시한다. 확인 필요/실패는 파일과 원본 페이지 번호를 기본 펼침으로 보여주며 정상 추출은 접힌 상세로 제공한다. 페이지 기록이 없으면 성공으로 표시하지 않는다. 새 분석은 기존 재분석/선명한 원본 등록 흐름으로 진행하며 이 표시는 수동 OCR 수정이나 자동 복구 채택 기능이 아니다.


## 심의 결과·문구 수정·근거 탐색 화면 — 2026-09-29

사용자가 제공한 Showcase PPT의 화면 이미지를 참고하되 기존 진한 녹색 테마와 흰색 로고를 유지한다. 운영 모드에도 접기/펼치기 가능한 사이드바를 제공하며 광고물 목록·등록, 심의 결과, 추천 문구, 심의 기준표, 법령·규정 검색으로 이동한다. 모바일은 메뉴를 위로 배치한다.

결과는 광고 정보와 네 집계 → 항목별 표 → 선택 항목 상세 순서로 읽는다. 내부 저장값 위반/판단불가/충족/미해당을 표시에서만 부적정/확인필요/적정/해당없음으로 바꾼다. 전체 기본과 네 필터·항목 검색을 유지하며 우선 검토/규제목록 출처 버튼은 다시 만들지 않는다. 선택 상세에서 광고 원문 인용, 판정 사유, 동결 기준표 조건/원자 점검, 안내문구, 저장 근거 법령을 구분한다. 모델이 관찰했으나 검증 가드로 보류된 의견과 실행 조건은 접힌 상세 영역에 둔다. 원문·위치 보기는 같은 선택 항목의 실제 파서 인용 좌표로 이동한다. 검색 영역은 별도 표시 옵션이며 직접 인용과 구별한다. HWP 표시 정책은 ADR-0088을 유지한다.

추천 문구는 부적정·확인필요 항목의 원문/기준표를 옆에 둔 초안 편집 공간이다. AI 자동 생성은 연결 예정이라고 표시한다. 기준표 참고 예시를 사용자가 명시적으로 가져와 편집·복사할 수 있고 작성 중 초안이 있으면 교체를 확인한다. 페이지 이탈 전 복사를 안내하고 검토 전환 시 초안을 초기화한다. 자동 채택·승인·판정 변경·DB 저장을 가장하지 않는다. ADR-0039의 복사는 채택이 아니라는 경계를 유지한다.

법령·규정 화면은 현재 TEMPLATE 행의 statute/association 매핑만 검색한다. 기준명·적용 템플릿·연결 항목을 찾고 기준표 원문으로 이동한다. 법령명은 국가법령정보센터 공식 명칭 검색으로 연결하며 특정 판본/조문 직접 링크라고 표시하지 않는다. URL이 없는 협회·내부 기준은 원문 링크 미등록으로 표시한다. 결과의 근거는 동결 요청에 저장된 매핑을 사용하고 현재 자료를 과거 판단에 소급 주입하지 않는다. 전체 법령 조문 검색·개정 이력·AI 추천 생성/채택 저장은 운영 연동 전이다.

## HWP HTML 원문 보기 — 2026-09-28

[ADR-0088](adr/ADR-0088-hwp-html-review-display.md)에 따라 HWP/HWPX 결과의 기본 원문 보기는 심의에 사용한 파서 이미지이며 정적 HTML 본문 읽기를 함께 제공한다. 사용자에게는 “심의 화면 · 근거 위치”와 “본문 읽기 · HTML”로 안내한다. 2026-09-28 사용자가 표시 방식 결정을 위임했고, 심의와 근거 좌표의 일치를 우선했다. 인증된 GET `/operational/reviews/{review_id}/hwp-html/{asset_id}`는 해당 심의·광고 파일 소유권과 원본 체크섬·HTML 해시를 확인한다. 저장된 파서 HTML을 우선 사용하고 과거 결과에 없으면 동일 원본에서 HTML만 생성·보관한다. 이 조회는 파싱·검색·판정을 재실행하지 않는다. HTML은 스크립트·외부 요청을 차단한 격리 iframe으로 표시하며 실제 원문에 유일하게 대응하는 인용만 문구 강조한다. 반복 문구·위치 불명은 임의로 강조하지 않는다. HTML 위에 P1 bbox를 그리지 않고 별도 파서 이미지 보기에서 기존 좌표를 확인한다. 이미지·이미지 PDF 경로와 기존 저장 판단은 유지한다.

기간 합산 고지에 잘못 적용된 산술 증명 검증으로 응답이 거부된 경우, 공통 검증 수정 후 전체 계약을 통과한 저장 응답만 복구 대상으로 삼는다. 복구된 결과와 원문 근거를 기존 결과 화면에 표시하고 해당 항목의 출력 실패 경고를 해제한다. 다른 판정과 원응답·이전 실패 기록은 보존한다. 재검증을 통과하지 않은 항목을 임의로 충족·위반·판단불가로 바꾸지 않는다.

## 검색·모델 연결 복구와 재시작 이어하기 — 2026-09-16

운영 검토는 Elasticsearch뿐 아니라 BGE와 Gemma가 준비되지 않은 경우에도 현재 단계명에 해당 서비스의 `연결 복구 대기`를 표시한다. 복구되면 원래 단계명으로 돌아가며 대기 중 취소할 수 있다. 일시 연결 장애로 자동 재시도되거나 서버 재시작 뒤 같은 검토에 다시 연결된 경우 중간 상태를 최종 실패로 표시하지 않는다. 재시도 한도 초과, 설정 불일치, 입력 오류는 기존 실패 안내를 유지한다.

## 저장 결과의 제목 단독 인용 보류 — 2026-09-16

본문의 의미요소가 필요한 템플릿 항목에서 제목 한 줄만 근거로 삼은 옛 충족 결과는 판단불가로 표시한다. 원래 모델 결과는 보류 전 판단으로 보존하고, 잘못 선택한 위치를 정상 근거로 강조하지 않는다. 안내는 실제 본문 확인이 필요하다는 사유를 표시한다. 통계 집계 실패는 저장 완료한 AI 판정 전체의 검색/모델 실패로 표시하지 않는다.

## 검색 서비스 연결 복구 대기 — 2026-09-16

운영 검토의 검색 서버 사전 확인에서 일시적으로 연결할 수 없으면 현재 단계명에 `검색 서버 연결 복구 대기`를 표시한다. 복구되면 원래 단계명으로 돌아가며 사용자는 대기 중에도 검토를 취소할 수 있다. 최대 5분 후에도 복구되지 않으면 검색 터널·서비스 확인이 필요하다는 오류를 표시한다.

## 검토 실행·진행 화면의 구분선 여백 — 2026-09-16

자동심의 실행과 AI 검토 진행 상태 화면은 제목 아래 구분선과 본문 카드 사이에 1.25rem 여백을 둔다. 왼쪽 첫 카드의 상단 마진을 제거하여 광고 원본 카드와 같은 높이에서 시작하며, 좁은 화면에서도 구분선과 카드 사이 여백을 유지한다.

## 버튼 호버 글자 대비 — 2026-09-16

진한 초록 배경으로 바뀌는 활성 버튼과 버튼형 링크는 커서를 올리는 즉시 글자색도 흰색으로 바뀐다. 클릭 또는 선택 상태를 기다리지 않으며 글자색에는 전환 지연을 두지 않는다. 다른 광고 추가·취소·미리보기·이동 등의 보조 버튼과 위반/판단불가 판정 필터에 공통 적용한다. 연한 선택·호버 배경에는 검정 계열 글자색을 함께 지정한다. 비활성 버튼은 기존 상태를 유지하고 키보드 포커스 표시를 보존한다.

## 판독 가드 이후 활성 근거 — 2026-09-16

판독 가드가 철회한 판단의 인용은 활성 근거의 텍스트·ID·줄·bbox에서 함께 제외한다. 적용성 게이트 보류는 해당 결론의 인용을 제거하고, 일부 요건 보류는 나머지 독립 관찰 근거를 유지한다. 가드 없는 판단불가의 인용을 일괄 숨기거나 검색 후보로 대체하지 않는다. 기존 저장 판정·원응답·가드 이전 결과는 그대로 보존하고 조회 시 비변경 투영을 적용한다.

철회된 인용만 남았던 행은 “판독 불확실성으로 근거 인용 보류 · 원본 확인 필요”를 표시한다. 규정 카드·판단불가 사유·원본 페이지는 유지하며 빈 authoritative 위치를 유사도 매칭으로 복원하지 않는다.

## 현행 시인성·판독 불확실성 처리 범위

운영 결과의 기존 추가 확인 영역에 시인성 사람 검토 사유를 표시한다. 위치 좌표만 보존하고 폰트·글자 크기·색상·배치 자동 판정은 제공하지 않는다. 확정 위반/판단불가 행이 없더라도 실제 사람 검토 후보 또는 템플릿 범위 밖이 아닌 미판정 항목이 있으면 상태 요약을 “사람 검토 항목 확인 필요”로 표시한다. 새 큐 화면·색상 측정 화면은 만들지 않는다.

일부 지역의 판독 불확실성은 광고 전체 미판독으로 표시하지 않는다. 판정에 귀속되지 않은 빈 영역·불확실 영역은 광고별 `원문 판독 확인` 판단불가 카드 하나로 묶는다. 판독 확인 대상 좌표는 `원본 확인 필요 위치 N곳`, 판정 근거 좌표는 `광고 원본 근거 위치 N곳`으로 구분한다. 여러 줄의 합집합으로 페이지 대부분을 덮는 사각형을 만들지 않고, 유효한 줄 좌표가 있으면 넓은 영역 대신 줄별 좌표를 각각 표시한다.


## 운영 결과 화면 연결 보완

- 원본/규정 목록 독립 스크롤, 원본 폭 맞춤/100~200% 확대·새 탭·이전/다음 페이지·근거 자동이동 토글 제공.
- 동명 템플릿의 참고 문구를 구분해 표시한다. 미기재 주장은 원본 대조 필요를 안내하며 전문 관찰 완료를 보증하지 않는다.

- 규정 카드 hover는 저장된 원문 ID의 좌표를 사용한다. 영역 연결은 정확 줄 미확정임을 함께 표시한다.
- 복수 파일 광고의 페이지 이동은 전역 순서로 표시하되, 원본 파일 조회에는 해당 파일의 로컬 페이지 번호를 사용한다.
- 미실행 항목은 다른 템플릿, 입력/구조 확인, 보완검색 실행 한도로 구분해 펼쳐 본다. 전부 입력 부족으로 표시하지 않는다.
- JSON 다운로드의 결과 행과 화면 판정 행은 동일한 저장본 투영이다. 출력 처리 실패는 판단불가 집계와 분리한다.

# 1. 화면설계 작성 기준

## 1.1 작성 원칙

본 화면설계서는 실제 디자인 시안 또는 와이어프레임 작성 전 단계의 문서로, 다음 항목을 중심으로 정의한다.

| 구분 | 정의 내용 |
| --- | --- |
| 화면 목적 | 해당 화면에서 사용자가 수행하는 업무 |
| 사용자 | 화면을 사용하는 주요 권한 |
| 진입 경로 | 이전 화면 또는 메뉴 경로 |
| 주요 영역 | 화면을 구성하는 주요 정보 영역 |
| 입력 항목 | 사용자가 입력하거나 선택하는 값 |
| 출력 항목 | 시스템이 표시해야 하는 정보 |
| 주요 버튼 | 저장, 조회, 분석 요청, 리포트 생성 등 사용자 액션 |

## 3.4 PoC 핵심 화면 UI 상세화 기준

ADR-0060 기준으로 PoC 1차 구현은 핵심 화면만 상세 레이아웃, 컬럼, 필터, 팝업, 권한별 노출, 반응형 기준을 우선 확정한다. 보조 화면은 핵심 업무 흐름을 막지 않는 최소 조회/입력/이동 기준으로 구현한다.

| 구분 | 기준 |
| --- | --- |
| 기준 화면 | S-003, S-004, S-005, S-006, S-007, S-008, S-012, S-014, S-015, S-016 |
| 기본 레이아웃 | PC 우선. 좌측 메뉴, 상단 헤더, 본문 Content Area를 기본으로 한다. 상단 헤더에는 제공된 NH농협은행 로고를 비율 유지의 흰색 단색·투명 배경으로 표시하고 이미지 대체 텍스트는 `NH농협은행`으로 한다. |
| 복합 업무 화면 | 목록/미리보기/상세 패널 중 2~3영역 구성을 사용한다. |
| 목록 컬럼 | 필수 컬럼, 상태/위험도 컬럼, 기본 정렬 기준을 우선 정의한다. 컬럼 개인화는 PoC 필수 범위에서 제외한다. |
| 필터 | 화면별 기본 조회 조건과 초기 정렬을 둔다. 사용자별 필터 preset은 PoC 필수 범위에서 제외한다. |
| 팝업 | destructive action은 확인 팝업을 사용하고, 상세 조회 팝업은 닫기 중심으로 단순화한다. |
| 권한별 화면 차이 | 권한 없는 메뉴는 숨김, 권한 없는 action은 비활성화 또는 숨김, 직접 접근은 ADR-0055 기준 403 처리한다. |
| 상태 처리 | loading, empty, error, forbidden, retry pending, final failed 상태를 핵심 화면에서 표시한다. |
| 모바일 대응 | PC/노트북 사용을 기본으로 하며, tablet/mobile은 깨지지 않는 조회와 상태 확인 수준의 fallback으로 제한한다. |

## 3.6 반응형 범위

| 구분 | 기준 |
| --- | --- |
| Desktop | 1280px 이상. 핵심 업무 화면의 기본 검증 기준 |
| Tablet | 768px 이상. 메뉴 축소, 2열 영역의 세로 적층 등 깨지지 않는 수준 |
| Mobile | 375px 이상. 조회와 상태 확인은 가능해야 하나, Annotation 정밀 검토와 대량 입력은 PC 권장 |

모바일에서 텍스트 겹침, 버튼 잘림, 필수 상태 확인 불가, 주요 안내가 화면 밖으로 사라지는 문제는 결함으로 본다. 다만 PC와 동일한 업무 효율을 제공하는 것은 PoC 필수 범위가 아니다.

## 3.7 M2 공통 로그인 진입

| 항목 | M2 구현 기준 |
| --- | --- |
| 경로 | `/login` |
| 표시 | 사용자용 제목 `로그인`만 표시한다. `M2` 등 내부 마일스톤·개발 단계 명칭과 NH농협은행 로고는 로그인 카드에 노출하지 않는다. 로고는 인증 후 공통 업무 헤더에만 표시한다. |
| 입력 | 이메일, 비밀번호. 빈 값과 10자 미만 비밀번호는 API 요청 전에 사용자 안내를 표시한다. |
| 성공 | `POST /api/v1/auth/login` 성공 후 access token은 브라우저 메모리에만 두고 역할별 기본 경로로 이동한다. 상품부서 담당자·준법감시 담당자와 복수 기능 권한 사용자는 `/advertisements`, `STANDARD_MANAGER` 단일 기능 사용자는 `/standards`가 기본 경로다. refresh token은 서버의 `refreshToken` httpOnly cookie를 사용하며 화면 코드가 읽거나 저장하지 않는다. |
| 진행 상태 | 요청 중 버튼을 비활성화하고 `로그인 중...` 상태를 표시한다. |
| 실패 상태 | 로그인 실패·비활성·잠금 여부를 구분하지 않는 일반화 문구를 표시하고, 서버 내부 원인·token·경로를 노출하지 않는다. |
| 권한 | 미인증 사용자의 광고물 경로 직접 접근은 `/login`으로 이동한다. |

### 5) M2 1차 구현 상태와 기본 상세

| 상태/경로 | 처리 기준 |
| --- | --- |
| `/advertisements` loading | 목록 조회 중임을 명시한다. |
| empty | 권한 범위 내 결과가 0건이면 `등록된 광고물이 없습니다.`를 표시한다. |
| error | ADR-0045의 안전한 기본 문구와 `traceId`만 표시하며 raw API message나 저장소 경로는 표시하지 않는다. |
| permission | `PRODUCT_DEPARTMENT_USER`, `COMPLIANCE_REVIEWER`, `SYSTEM_ADMIN`만 목록에 진입한다. 목록 결과 자체는 서버의 부서 scope filter를 신뢰하되 클라이언트에서 타 부서 결과를 별도로 합성하지 않는다. |
| `/advertisements/{advertisementId}` | 기본 상세는 원본 문서 작업 영역과 메타데이터 보조 패널로 구성한다. 원본 미리보기는 desktop에서 주요 폭과 충분한 세로 높이를 차지하고, 파일 메타데이터·검토 요청·다운로드는 보조 패널에 둔다. 기존 검토 이력은 최근 회차부터 상태·위험도·요청일을 표시하며 진행 중 검토는 S-005, 완료·확인 필요 검토는 S-006으로 복귀시킨다. 각 파일은 Bearer 인증이 적용되는 backend proxy의 미리보기 descriptor/content와 다운로드 action만 사용한다. `SYSTEM_ADMIN`에게만 확인 대화상자를 거친 `광고물 삭제` action을 표시하며, 삭제 후 목록으로 이동한다. 삭제된 광고물은 원본과 연결 검토 결과를 포함해 조회하지 않는다. 권한 밖 단건·파일은 전용 403 안내를 표시하고 object key·bucket·presigned URL·내부 사유를 표시하지 않는다. |
| 후속 화면 경계 | AI 검토 결과·위험도·리포트 action은 M3 이후가 아니라 각 소유 capability가 구현될 때 연결하며 M2에서 임시 응답을 만들지 않는다. |

광고 등록·원본 확인·AI 검토 화면은 `광고 등록 → 원본 확인 → AI 검토 → 결과 확인`의 공통 업무 단계를 표시한다. 현재 단계는 텍스트와 시각 상태를 함께 제공하고, 완료된 단계만 유효한 식별자가 있을 때 이동 링크를 제공한다. 완료된 운영 결과 화면은 원본/판정 작업 영역을 확보하기 위해 큰 단계 표시를 생략하고 작은 결과 상태와 진행 기록 링크를 사용한다. 표준 S-006~S-010은 `결과 요약`, `항목별 검토`, `광고 화면`, `광고 규정 Q&A`, `검토 및 리포트`의 공통 하위 탐색을 유지한다. 검토 식별자가 바뀌면 다른 검토의 화면이므로, 검토 단위로 열리는 화면은 이전 검토의 입력 내용, 선택 항목, 검색·페이지 조건, 생성한 리포트, 활성 Q&A 세션을 이어받지 않는다. 서버에서 받는 값은 검토 식별자를 포함한 조회 조건으로 갱신하고, 화면 안에서만 유지하는 상태는 검토 전환 시 초기 상태로 되돌린다. 공통 하위 탐색은 모든 탭에서 페이지 제목 블록 다음의 독립 블록으로 두고 같은 위치·같은 폭으로 표시하며, 특정 탭에서만 제목과 같은 행에 배치하지 않는다. 탭 진입과 화면 내 목록 갱신은 해당 목록 영역 안에서만 스크롤하고 문서 전체 스크롤 위치를 이동하지 않는다. 이를 위해 목록을 담는 패널은 모든 화면 폭 구간에서 유한한 높이 상한을 유지한다.

| 복구 | `RETRY_PENDING`은 OCR/Parser·저장소·AI 응답의 일시 오류에 적용하며 retry 횟수·최대 횟수·다음 시각을 표시한다. `STALE`은 복구 지연 상태를 표시한다. |
| 실패 | `FAILED`/`FAILED_FINAL`을 구분하고 `isRetryable=true`인 실패 또는 stale 상태에서만 재분석 action을 제공한다. |
| 품질 확인 | `OCR_UNREADABLE`은 판독 불가와 원본 품질 개선 후 재분석 안내를 표시한다. 그 외 `CHECK_REQUIRED`은 텍스트 품질·상품 조건·기준자료 확인 필요를 안내하며, 판독 불가로 오표시하지 않는다. |
| permission/redaction | 타 부서·권한 부족 403을 전용 상태로 표시하고 raw artifact reference, object key, presigned URL은 화면에 노출하지 않는다. |

| 질문 | Y | 광고 규정 관련 질문. 입력줄은 대화형으로 제공하고 내용에 따라 높이를 자동 조절하되 상한을 유지한다. `Enter`로 전송하고 `Shift+Enter`로 줄을 바꾸며, IME 조합 중의 `Enter`는 조합 확정으로 처리해 전송하지 않는다. 내용이 없으면 전송할 수 없고, 검토 맥락과 이전 질의응답을 불러오지 못한 동안에는 전송을 막고 그 이유를 함께 표시한다. |
| 상품군 | 자동 | 현재 검토의 광고물 상품군을 질문 범위에 적용하고 화면에 표시한다. |
| 광고유형 | 자동 | 현재 검토의 광고유형을 질문 범위에 적용하고 화면에 표시한다. |
| 기준 적용일 | 자동 | 현재 검토 완료에 사용한 기준 적용일을 질문 범위에 적용하고 화면에 표시한다. |

### 3) 출력 항목

| 항목 | 설명 |
| --- | --- |
| 답변 요약 | 질문에 대한 요약 답변 |
| 상세 설명 | 판단 사유 |

| 대화 이력 | 같은 검토의 질문과 답변을 시간순으로 표시하고, 다른 검토의 이력은 표시하지 않는다. 각 메시지에 시각을 표시한다. |

### 5) M3 구현 흐름

| 영역 | 구현 기준 |
| --- | --- |
| 계약 client | `openapi/openapi.yaml` 0.3.0의 frozen Standards/Evidence/Reindex/Chunk schema에서 생성한 TypeScript 타입만 API 경계에 사용한다. |
| 목록/검색 | `/standards` 진입 시 `activeOnly=true`, `page=1`, `size=20`으로 조회하고 기준명, 기준 유형, 상품군, 광고유형, 기준 성격 필터를 query에 반영한다. |
| 등록 | 등록 폼은 적용 범위→문서 정보→검토 기준 내용 순서로 구성한다. 내부 기준 등록은 소관 부서, 문서명, 조항·섹션 위치, 적용 시작일, 문서 버전, 상품군을 필수 입력으로 수집하며 적용 시작일의 기본값은 로컬 오늘이다. `multipart/form-data`의 `metadata` JSON에 `owningDepartment`, `documentName`, `sectionPath`, `effectiveDate`, `version`, `productGroup`와 `inputBoundary=DIRECT_TEXT_ONLY`를 전송하고 상품군·적용일은 상위 필드에도 동일하게 전송한다. 직접 입력 본문은 필수이며 원문 파일은 보관용 선택 항목이다. |
| 수정/버전 | `/standards/{standardId}` 상세를 먼저 조회하고 PATCH로 기존 version을 덮어쓰지 않는 새 불변 version과 변경 사유를 등록한다. |
| 검토 적용 중지 | 사유를 필수 입력하고 soft-deactivate하여 연결 청크가 검색 대상에서 제외되도록 요청한다. 재적용 API가 없으므로 on/off 토글로 표현하지 않는다. |

| Loading | 목록과 관리 action 요청 중 별도 진행 문구를 표시하고 중복 요청 button을 비활성화한다. |
| Empty | 목록, version 이력, Chunk, 근거 검색 결과가 0건이면 각 영역별 빈 상태 문구를 표시한다. |

| Metadata validation | 필수 내부 기준 메타데이터가 누락되거나 유효하지 않아 `REFERENCE_METADATA_INVALID`가 반환되면 입력 확인 문구와 안전한 traceId만 표시하고 backend 원문 message는 표시하지 않는다. |
| Search unavailable | 503은 “검색 인프라를 사용할 수 없습니다”로 표시하고 근거 없음이나 정상 Hybrid 결과처럼 표시하지 않는다. |
| Permission | `STANDARD_MANAGER`, `SYSTEM_ADMIN`만 route와 navigation action에 접근한다. 그 밖의 role은 API 요청 전에 접근 제한 상태를 표시한다. |
| Responsive | PC/노트북에서 전체 관리 action을 제공하고 작은 화면에서는 filter/form을 1열로, table은 가로 scroll로 유지한다. |

# 9. 결론

본 화면설계서는 AI 기반 금융상품 광고심의 적정성 검토 에이전트 PoC의 주요 화면 구성을 정의한 1차 틀이다.

현재 단계에서는 상세 UI 디자인보다 화면의 목적, 사용자, 입력값, 출력값, 버튼, 화면 이동 흐름을 우선 정의하는 것이 중요하다.

이 문서를 기준으로 다음 단계에서는 각 화면별 와이어프레임, 상세 화면정의서, API 연계 항목, 데이터 매핑표를 추가 작성한다.

## 로컬 자동심의 실행 모드 (2026-09-06)

사용자가 요청한 로컬 시연 연결은 `VITE_OPERATIONAL_REVIEW=true` 빌드와
`serve-operational-review.py --execution-config`를 함께 사용한다. 일반 제품 빌드에는
이 모드를 적용하지 않으며 PostgreSQL/Redis 운영 워커 교체나 배포 승인을 의미하지 않는다.

- S-004: 전체 범위·v2 고정본으로 실행한다. 템플릿은 사용자가 v2 섹션 목록에서 확인하며,
  미확정이면 파서 추정을 승격하지 않는다. 미지원 문구 추천·의견 초안·기준일 변경은 비활성화한다.
- 서로 다른 광고 원본은 최대 20개까지 한 번에 선택해 각 파일을 독립 광고·독립 job으로
  등록하고 자동심의 대기열에 넣는다. 한 광고를 여러 파일로 나눈 경우는 배치 등록이 아니라

## 2026-09-16 판정 기준·시스템 보류·좌표 미연결 표시 구분

결과 카드의 판정 기준은 법령/규정/기준명과 조문번호를 출처별 줄바꿈으로 표시한다. 내부 ID·원문 XML 위치는 표시하지 않는다. 판독 가드의 문구에는 시스템 자동 확정 보류 사유임을 표시하고, 저장된 가드 감사가 있으면 보류 전 모델 사유를 미채택 판단으로 펼쳐본다. 이를 확정 판정이나 활성 근거로 복원하지 않는다.

좌표 없음은 광고 전체 판정이라는 뜻이 아니다. 원문 geometry 없음, 인용 연결 미완료, 판독 보류, 인용 자체 없음, 미기재 판정을 구분한다. 새 실행은 선택 템플릿 원문 행 수·통합 항목 수·판정 요청·사람 확인·처리 기록 누락을 표시한다. 텍스트 전용 판정은 시각/구조 확인이 남았음을 명시한다.

적용 여부를 판단할 수 없다고 설명한 미해당은 판단불가 카드로 드러낸다. 시스템의 보류 사유와 원래 모델의 미해당 설명을 구분해서 보여 주고, 채택하지 않은 인용 위치는 활성화하지 않는다. 원저장 판정은 변경하지 않는다.

## 원문 근거 확인 경계

새 검토의 충족·위반 직접 관찰은 원문 줄이 제공되면 그 줄을 인용한다. 판독 불확실 자료를 다른 정상 근거보다 먼저 인용해 전체 항목이 보류되는 경로를 차단한다. 좌표가 없다는 사실은 광고 전체에 대한 심의라는 뜻이 아니며, 텍스트 인용과 원문 기하 좌표 보유 여부는 구분한다. HWP 정본에 좌표가 없는 경우 미리보기 OCR의 다른 줄 ID를 정본 ID로 추정 연결하지 않는다. 심의일은 최초 광고 등록일로 유지한다.

## 템플릿 설명과 저장 인용 불일치 표시

기준 출처에 일반 심의 템플릿명·상품 구분을 표시하고 기재 구분은 필수/조건에 따라 필수로 풀어 쓴다. 템플릿 작성 예시는 접어서 표시하며 예시 문구를 그대로 사용할 의무가 없음을 설명한다. XML 내부 위치는 화면에 표시하지 않고 원본 API/export에 보존한다. 조문 미연결은 “이 항목에는 개별 법 조문을 연결하지 않았습니다.”로 표현한다.

## 연구원 피드백: 판정 기준 출처 표시 — 2026-09-16

판정 기준에는 내부 C/D/R/T/TPL ID·규제목록 버전·XML 위치를 표시하지 않고 법령/규정/기준명 및 조문번호를 출처별 줄바꿈으로 표시한다. 세미콜론/줄바꿈으로 묶인 출처를 분리하고 조문 뒤 괄호 설명을 제외한 표시 문자열이 같은 경우에만 중복 제거한다. 제16조 제1항 제4호와 제16조 제1항 4처럼 표기가 다른 출처는 동일 조항으로 추측해 통합하지 않고 병렬 표시한다. 명칭 내부 괄호와 서로 다른 조문은 보존한다. 내부 템플릿의 이름·상품 구분·필수 여부와 조문 미연결 안내는 유지한다. 항목 카드 제목과 처리 실패 안내에서도 내부 규칙 ID를 표시하지 않는다. 제목에는 상품·점검항목 이름을 표시하고 실패 안내에는 항목 순번을 사용한다. 원본 API/export의 item_id·rule_basis와 내부 근거 연결 키는 보존한다.

## 사용자 결정: 결과 3종·사람 확인 통합·후보 실행 제한 제거 — 2026-09-16

메인 결과는 위반·판단불가·충족만 표시한다. 다른 템플릿 소속 항목은 목록·집계에서 제외하고 원저장 감사만 유지한다. 실제 NOT_APPLICABLE은 적용 제외 내역(excluded_rows)에 사유와 함께 보존하며 메인 카드·필터에 미해당을 두지 않는다. 적용성 미확정인 추가 v2 후보와 시인성/외부 자료/구조 확인은 모두 판단불가 목록·집계에 포함한다. 동일 scope/item의 보류는 중복 집계하지 않는다. 텍스트 충족에 필수 사람 확인이 남으면 전체 판단불가로 표시하고 자동 텍스트 결과를 automated_assessment에 보존한다. 이미 확인된 위반은 유지하며 남은 확인 사유를 함께 표시한다.

후보 개수 상한으로 규칙을 자르던 과거 방식은 사용하지 않는다. 현행 실행기는 출처 승인 티어로 정식 범위를 먼저 정해 `TEMPLATE_PRIMARY`, `MEDIA_CONDITIONED_V2`, 원문 결합·검색 발동형 `PRODUCT_CONTENT_CONDITIONED_V2`와 관계 의존 규칙을 판정한다. 시인성 규칙은 검색 후보와 근거를 유지하되 사람 검토로 보낸다. 나머지 `MAPPED_V2`, `GENERAL_V2_PRESENCE`, `SUPPLEMENTAL_V2`는 기존 역할에 따라 보강·평가 또는 발견 감사 후보로 보존한다. 용도가 사라진 `prohibition_max_candidates` 설정과 CLI는 제거했으며, 동시 실행 수·요청 배치 크기·reranker 범위는 처리 순서와 자원 관리에만 사용한다. 처리 실패를 충족·미해당·정상 완료로 숨기지 않는다.

workspace/export에 excluded_rows와 execution_omissions를 추가하며 review_candidate_rows/deferred_rules는 빈 호환 배열로 유지한다. 사람 확인은 manual_review_reasons와 실제 점검 제목/질문을 반환한다. 과거 파일에 제목이 없으면 검토 시 동결한 SHA와 동일한 규정 파일 및 저장 템플릿 카탈로그에서 표시 메타데이터만 보충한다. 버전 불일치면 현재 규정으로 바꾸지 않는다. 원저장·모델 판정·source_results는 변경하지 않는다. 과거 후보 실행 누락이 있다면 판단불가와 재처리 필요 경고로 드러내며 자동 완료로 표시하지 않는다.

양성/음성/경계 회귀는121개 검색 후보 보존, 미선택 제외, 사람 확인/적용성 미확정 통합, 위반 유지, 텍스트 충족 보류, 중복 제거, 상품별 scope 분리, 실제 미해당 별도 내역, 옛 실행 누락 경고, 원본 불변, 동결 출처 해시 일치/불일치를 포함한다. 광고 전체 재심의·모델 호출 없이 저장 결과를 대조한다.

## 저장 결과의 판독 불확실성 재검증 — 2026-09-17

workspace와 JSON 다운로드는 같은 saved_workspace 경로에서 저장된 요청의 판독 상태와 규칙별 원문 범위를 사용한다. OBSERVED로 잘못 분류된 명시적인 누락 주장도 판독이 불완전하면 판단불가로 보류하며, 철회한 근거 좌표는 표시하지 않는다. 기존 보류 전 모델 판단에 원래 판정·사유를 남긴다. 원본 결과 파일·상태 데이터와 API 스키마는 변경하지 않는다. 독립적으로 검증되는 산술 위반은 유지한다.
