## 2026-09-14 청킹 결함 수정과 재현성 확보

### 배경 — 사용자가 발견한 오판정

운영 화면에서 `D-163`(수치 산술 불일치 금지)이 위반으로 나왔고 사용자가 오판정으로

  수치와 무관했다. 실제 우대금리는 `L021~L036`에 있다.
- 이유문 자체가 모순이었다. 「합계 3.0%p는 최대 3.0%p와 **일치하나**」라고 써놓고
  위반을 냈다.
- 비교 대상이 서로 다른 파일이었다. 우대금리 3.0%p는 1쪽, 「최고 연 2.0%」는 2~6쪽의

### 수정 1 — 불릿 정규식이 소수를 말머리로 오인

`BULLET_START`의 `\d+[.)]`가 `0.7`을 `"0."`+`"7"`로 읽어 번호 목록으로 취급했다.
우대금리 표에서 조건과 이자율이 매번 다른 청크로 갈렸다.

- 수정: `\d+[.)](?!\d)`
- 측정: 광고 전체 고유 라인 484개 중 판정이 달라지는 것은 14개이고 **전부 숫자**다
  (`1.0` `0.7` `3.0%p` `94.4%` `2026.6.22.` 등). 진짜 번호 목록은 영향 0.
- 가운뎃점 `·`는 원래 말머리 목록에 없다. 표에서 값의 일부로 쓰여 그대로 둔다.

### 수정 2 — 표 행 복원과 항목 경계

파서가 `layout=table`로 인식하면서 `table` 구조 필드는 **전 영역에서 비어 있다**.
셀 구조를 주지 않아 청커가 표를 산문으로 취급했다.

- 라인 bbox의 세로 겹침으로 표 행을 복원한다(`_same_visual_row`, 겹침 비율 0.5).
  74줄 영역이 51행으로 복원되고 라벨 셀과 값 셀이 한 묶음이 된다.
- 행을 항목 단위로 묶는다. 우선순위는 **파서 라벨 → 좌표** 순이다.

### 수정 3 — 파서 라벨을 청크 경계로 (좌표는 폴백)

파서가 이미 라인마다 템플릿 항목 라벨을 붙여 준다(`예금성상품-적립식:우대금리` 등).
좌표로 같은 경계를 다시 추론하던 것을 라벨로 바꿨다.

- 라벨이 **2종 이상**을 구분해 줄 때만 경계로 쓴다. 1종뿐이면 경계 정보가 없어
  표 전체가 한 덩어리가 된다(`p1_r006`이 26줄 → 1청크로 거칠어져 이 조건을 넣었다).
- 라벨이 없는 행은 직전 항목에 붙인다. 주석이 본문에서 떨어지지 않게 하려는 것이다.
- 이미지 영역에는 적용하지 않는다. 항목이 가로로 배치돼 라벨이 줄마다 교대하므로
  적용하면 2~4자 파편이 대량 발생한다(시뮬레이션에서 1청크 → 10청크).
- 라벨 커버리지는 673줄 중 203줄(30%)이다. 나머지는 좌표·불릿 폴백이 담당한다.

결과는 fine 청크 58 → 49개, 10자 미만 파편 11 → 6개다. 우대금리 항목이 696자
한 청크가 되어 최대 우대금리와 6개 항목값이 같은 근거 창에 들어온다. 종전에는
원리적으로 불가능했다.

### 한계 — 큰 표 4개는 라벨을 못 쓴다

`p2_r003`·`p3_r003`·`p5_r004`·`p6_r004`는 라벨이 12~22줄씩 붙어 있는데도 각 1청크다.

### 수정 4 — 벡터 캐시 정밀도 불일치

`load_or_encode`가 캐시는 float16으로 저장하면서 첫 실행에는 float32 원본을 반환했다.

- 수정: 저장할 정밀도를 그대로 반환한다.
- 검증: 캐시를 지우고 2회 연속 실행해 `02_judgment_requests.jsonl` 해시가 일치함을
  확인했다. **검색·근거 선택 계층은 완전히 재현된다.**

```text

                ↓ 동일성 검증·통합
```

### 3.1 파서 경계

- P1은 원문 텍스트, 줄 참조, 좌표·스타일·시인성 관측값의 근거다.
- P3은 병합되지 않은 region 단위 최종 문구와 라벨 span을 제공한다.
- P2라는 별도 단계는 사용하지 않는다.
- `integrated/*.json`이 심의 입력 정본이고 coarse/fine은 재생성 가능한 검색 투영본이다.
- OCR/VLM 내부 후보 여러 개를 RAG가 선택하지 않는다. 파서가 region별 최종 판독문 하나를
  넘겨야 한다.
- 8pt, A4 이상 크기, 대비, bbox 등 시인성 수치 계산은 파서/OCR 책임이다. RAG는 받은
  관측값을 재계산하거나 파일명·본문으로 추정하지 않는다.

### 3.2 라우팅과 라벨

- `product_group`은 접수자·수요사·검증 시스템이 `provided|verified|confirmed`로 준 값만
  하드 필터로 쓴다.
- 파일명과 파서 추정은 provenance/약한 힌트로 남길 수 있지만 확정 필터가 아니다.
- 파서의 template/gubun/label은 추적과 순위 보조값이며 후보 배제 게이트가 아니다.
- 확인된 `template_id` 또는 `product_subtype`이 있을 때만 해당 T 섹션을 정확히 전개한다.
- 템플릿 미확정이면 T 규칙을 억지 적용하지 않고 보류하되 C/D 일반 검색은 계속한다.

### 3.3 규칙 유형별 처리

- 표시의무·양식: 확인된 상품군에서 적용 가능한 규칙을 전개하고 광고 전체에서 존재·형식
  요건을 검사한다.
- 금지: 광고 fine 청크에서 규제목록 v2 규칙을 BM25+BGE-M3로 찾고 RRF로 결합한다.
- 시인성: 파서가 제공한 수치·좌표가 있을 때만 판정한다. 없으면 입력 부족이다.
- 외부자료·사전심의·매체 의존 규칙: 접수 메타데이터나 대조자료가 없으면 보류한다.
- 규칙별 근거 검색은 최초 후보를 만든 청크를 버리지 않고, 해당 규칙 판정에 충분한 광고
  문맥을 다시 구성하기 위한 단계다.

### 3.4 판정 계약

- 출력은 적용성 `APPLICABLE|NOT_APPLICABLE|UNDETERMINED`와 판정
  `COMPLIANT|VIOLATION|UNDETERMINED`을 분리한다.
- 운영에서는 확인된 미해당을 화면 본판정에서 제외하되 `excluded_candidates`에 원출력을
  보존한다.
- 짧은 광고는 fine 근거와 coarse 전문을 함께 주며, 불완전 파싱·좁은 창으로 부재를
  확정하지 않는다.
- 반대로 전체 광고 검사가 완료됐고 표시의무의 필수 구성요소가 실제 `MISSING`이면
  `UNDETERMINED`로 물러날 수 없다. 계약 위반으로 재처리한다.
- 모델 confidence는 보정 확률이 아니다. 모든 위반·판단불가는 연구원 검토 대상이다.
- 모델 JSON 구문·계약 오류는 유효 결과를 보존하고 실패한 규칙만 소배치로 재호출한다.

## 6. 평가 데이터 현황

상세 구분은 `docs/evaluation-splits-current.md`를 따른다. 핵심만 요약하면 다음과 같다.

- 19건 draft는 v2 snapshot binding이 없어 19/19 `UNBOUND`, 평가 준비 안 됨.
- 기존 workset19 평가는 자동 결론 3건만 비교한 tiny smoke이며 최종 정확도가 아니다.
- 검색 `gold7`이라는 파일은 실제 8사례·15근거 그룹 smoke다. 알려진 사례 회귀용이다.

- 신규 광고 10건 표는 1,095 규칙 검사 silver이며 연구원 확정 gold가 아니다.
- 현재 독립 holdout은 없다. 따라서 최종 검색·판정 성능을 보고할 수 없다.

## 7. 알려진 정확도 결함과 해석 대기

### 7.1 일반 구현으로 처리된 것

- C-018 같은 표시의무 규칙은 광고 전문이 완전하고 적용성이 확인됐으며 필수요건이
  MISSING이면 위반이어야 한다. 모델이 판단불가로 후퇴하면 계약 위반으로 재처리한다.
- 이 계약은 사례 ID 하드코딩이 아니라 모든 완전한 PRESENCE 규칙에 적용된다.
- 단위테스트는 통과했지만 최신 전체 코드를 DGX에 다시 연결한 대표 광고 E2E는 아직
  재실행하지 않았다.

### 7.2 코드로 즉시 고치면 안 되는 것

- D-175 계열: 광고에 `복리`라는 단어가 없다는 이유만으로 미해당 처리하면 안 된다.
  단리·복리는 수치, 기간, 지급주기, 산식으로 판별해야 한다. 일반 계산 입력·술어가 먼저다.
- D-242 계열: 연구원은 `~` 같은 기호·특정 날짜 표기 형식이 필수는 아니라고 확인했다.
  표현 동등성의 일반 범위를 v2 또는 승인 가이드에 반영하기 전 사례별 조건을 만들지 않는다.
- C-069 계열: `후취`라는 단어가 없어도 일정 주기 후 납입 표현으로 충족할 수 있다는
  연구원 피드백이 있다. 일반 의미 기준과 반례를 승인받아야 한다.
- 심의사례의 규칙 ID가 넓거나 틀린 경우 해당 gold를 더 직접적인 T 규칙으로 고칠 수는
  있지만, C/D 규칙을 전역 치환하지 않는다.

## 8. 수요사 회의에서 확인된 방향

- 접수값 후보: 상품군, 템플릿/세부유형, 실제 매체, 심의 단계, 광고 묶음,
  외부 대조자료 유무.
- 어느 값을 접수자가 입력하고 어느 값을 기존 시스템에서 자동 제공하는지는 미확정이다.
- 사전심의에서는 최종 심의필 번호가 아직 없으므로 `0000-0000` 같은 자리표시 형식도
  번호 형식 존재로 인정한다.
- 여러 파일이 같은 광고라면 한 `ad_id` 아래 asset/page로 묶는다.
- 다상품 광고는 `products[]`, 상품별 evidence, `shared_evidence_ids`로 나누고 결과 키를
  `(ad_id, product_id, item_id)`로 유지한다.
- 여러 광고는 하나의 프롬프트로 섞지 않고 광고별 비동기 job으로 등록한다. DGX 중간
  프로필과 H200 최종 프로필 모두 worker/동적 배치로 병렬 처리할 수 있다.
- 연관 광고·랜딩페이지를 함께 보는 정확한 업무 의미와 관계 종류는 아직 수요사 확인이
  필요하다. 앞 광고 판정을 뒤 광고 정답으로 복사하지 않는다.
- 위반/충족/확인필요 조건과 안내문구가 있는 업무 템플릿을 추가 제공받을 수 있다.
  규제목록 v2와 결합하되 새 법적 규칙을 만드는 자료로 쓰지 않는다.
