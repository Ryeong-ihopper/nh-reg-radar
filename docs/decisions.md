2026-09-15 사용자 결정: 현재 파서는 원문 위치를 위한 bbox만 제공하는 범위로 진행한다. 색상·폰트·글자 크기·대비·가독성·시인성·레이아웃 판정은 사람 검토로 넘기며 측정 기능 개발을 선행조건으로 요구하지 않는다. 기존 style 값이나 bbox가 있더라도 자동 시인성 판정을 재활성화하지 않는다. 좌표는 원문 위치 확인용이며 글자 크기나 색상을 추정하는 근거가 아니다.

파서 needs_review/부분 읽기와 명확한 디코딩 손상(대체문자·NUL)에 의존하는 결론은 UNDETERMINED와 사람 검토로 보낸다. 독립적으로 읽을 수 있는 다른 근거의 판단은 유지한다. 모든 OCR 오독을 자동 탐지한다는 보장은 없으며 미확인 전체 범위로 미기재를 확정하지 않는다.

## 2026-09-11 적용조건 선행 판정

- 모든 규칙은 점검문구·판정기준의 대상자·상품·상황·매체·절차 범위를 의무보다 먼저 확인한다.
- 승인된 가이드나 템플릿에 명시된 조건은 `A1..An`, 사람 검토 조건은 `U1..Un`, 의무는 `O1`로 분리하며 모델 응답의 생략·순서 변경을 허용하지 않는다.
- 조건 불충족은 미해당, 조건 확인 불가는 판단불가이며 이 상태에서 의무의 충족·위반을 판정할 수 없다.
- `단` 같은 접속어와 키워드는 원문 구조화 보조일 뿐 참·거짓의 최종 게이트가 아니다.
- 규제목록 v2의 전체 원본 행은 실행마다 계약 생성 가능 여부를 감사하고, 현재 광고의 상품·템플릿 범위에 포함된 후보만 실제 판정한다.

## 2026-09-14 상품 범위·출력·평가 봉인

- 규칙의 근거를 제공한 협회·매뉴얼 이름은 상품 적용 범위를 넓히거나 줄이는 필터가 아니다. 확인된 상품군은 v2 `적용상품`과 템플릿 섹션으로 먼저 제한하고, `전체` 규칙은 원문 SCOPE의 대상·상황·매체·절차를 다시 검사한다.
- 모델은 SCOPE/A/U 상태와 직접 근거, O 판정만 생성한다. 중복되던 `applicability`, basis, 최상위 evidence와 사람 검토 여부는 실행기가 게이트 결과에서 파생한다.
- 예측 계약 실패를 의미 판정으로 임의 교정하지 않는다. 유효 쌍은 보존하고 실패 쌍만 선택 재호출하며 선택된 request ID도 실행 기록에 남긴다.
- 독립 성능 평가는 `예측 봉인 → 모델 필드가 제거된 검수 패킷 → 복수 사람 판정과 최종 결정 봉인 → 별도 조인 평가` 순서만 허용한다.
- 기존 19건과 반복 확인 광고는 `DEV_REGRESSION`이며 `BLIND_HOLDOUT`으로 승격하지 않는다. holdout은 미관찰 확인자와 확인 시각을 기록해야 한다.

## 2026-09-11 판정 통제·사람 최종 결정

- LLM 출력은 결정적 관측값·라우팅·입력능력 검증을 통과한 경우에만 최종 후보로 저장한다.
- 계약 충돌을 코드가 의미상 교정하지 않으며 유효 쌍을 보존하고 실패 쌍만 재호출한다.
- 모든 finding은 템플릿 원문 또는 규제목록 v2 출처를 필수로 가진다. 템플릿에 없는 법령 조문을 생성하지 않는다.
- 최종 결과는 모델, 검색 방식·인덱스, 규칙 원본 SHA, 근거 ID, 가드레일·validator 버전을 감사 가능하게 기록한다.
- 광고 접수에 초안/최종 단계를 추가하지 않는다. 시인성 판단은 실제 파서 관측값이 있을 때만 실행한다.
- AI 실행 완료는 광고 승인과 다르다. 준법 담당자의 승인·반려는 AI 결과를 변경하지 않는 별도 불변 기록으로 유지하되, 현재 PoC 화면에서는 기본 비노출이다.
- 같은 광고 자산 묶음은 최초에 함께 파싱하되 일부 P1/P3 산출물이 누락되면 완성 자산은 보존하고 실패 자산만 단독으로 한 번 재시도한다. 실패 자산이 남으면 광고 전체 판정은 시작하지 않는다.

## 2026-09-16 검색·모델 전송 장애 복구

- Elasticsearch, BGE, Gemma의 연결 가능성과 서비스 계약을 파싱 전과 RAG 제출 전에 확인한다. 연결 거부와 기동 지연은 최대 5분 동안 취소 가능한 상태로 기다리며 파싱·판정 비용을 먼저 소비하지 않는다.
- Gemma 전송 실패는 JSON·의미 계약 실패와 구분한다. 같은 논리 요청만 제한 재시도하며 요청 분할로 호출 수를 늘리지 않는다.
- 일시적인 의존 서비스 장애나 프로세스 재시작은 동일 job의 다음 attempt로 자동 연결한다. 이전 체크포인트는 입력·모델·runner·판정 코드 해시가 모두 같을 때만 재사용한다.
- 웹 프로세스 재시작 시 같은 review ID에 다시 연결하고, 파서 산출물은 광고 ID·선택 템플릿·원본 체크섬이 모두 일치할 때만 재사용한다.
- 저장된 최종 결과는 결과 계약이 유효하고 요청 쌍 전체가 빠짐없이 판정됐을 때만 후속 통계·보고 장애에서 보존한다. 입력 오류와 출력 누락은 자동 성공으로 바꾸지 않는다.

## 2026-09-11 Gemma 내부 판정 계약 경량화

- 모델은 긴 정본 ID를 재생성하지 않고 `R1`/`E1`/`L1` 별칭을 사용한다.
- 실행기가 검증된 별칭을 정본 item/evidence/line ID로 복원하며 최종 저장 계약은 유지한다.

## 2026-09-11 파서 커버리지 차원 분리

- `complete_ad_scan`은 정본 텍스트 라인의 전문 스캔 완료 여부를 뜻한다.
- page-sweep의 미검증 복구 후보는 감사 정보로 보존하지만, 그 존재만으로 모든 텍스트 부재 판정을 금지하지 않는다.
- 페이지 파싱 실패·미독 영역·빈 영역·라인 분할 불일치는 계속 전문 `PARTIAL`의 사유다.
- bbox·글자 크기·색상·대비·인접성 등은 규칙별 `automated_input_ready`에서 독립적으로 판정하며, 없으면 해당 규칙만 사람 검토로 보낸다.
- `MISSING` 부재 판정은 `complete_ad_scan=true`일 때만 허용하고, `VIOLATED`는 직접 관찰 근거를 필수로 한다.
- 기존 `gemma-judgment-v1` 저장물은 보존하고 신규 결과는 v2를 사용하며 운영 결과 스키마는 둘 다 읽는다.

## 2026-09-09 템플릿 중심 전환 결정

사용자는 템플릿 파일 자체를 시스템의 일부이자 주 심의 기준으로 사용하도록 확정했다.
아래 기존 v2 단일 출처·v2 item ID 매핑 필수 제한은 이 결정으로 대체된다.

- 일반 템플릿 HWPX의 상품군·구분·필수 여부·기재 요령을 독립 카탈로그로 적재한다.
- 템플릿 항목 ID와 원본 SHA·XML 문서·표·셀 참조를 보존한다. v2 매핑은 선택적 보강이다.
- 템플릿 예시의 숫자·상품명·표현을 모든 광고의 완전일치 기준으로 만들지 않는다.
- 규제목록은 템플릿 밖 쟁점 검색, 세부 적용조건, 정확한 법령 근거를 보완한다.
- 템플릿의 내부 업무 기준과 법령 위반 근거는 구분한다. 법령 근거 미연결이면 그대로 표시한다.
- 심의사례의 광고문구·판단·판단근거를 운영 템플릿으로 적재하지 않는다.

## 1. 규정과 사례

1. 일반 템플릿 HWPX는 주 점검 정본이고 v2는 세부 조건·법령 근거의 보완 정본이다.
2. v2 `신규규칙후보`의 T 항목도 판정 규칙 후보로 사용할 수 있다.
3. 일반 템플릿은 독립 `TPL-` 규칙의 출처다. 심의사례는 운영 규칙의 출처가 아니다.
4. 특정 사례의 잘못된 item ID 수정은 그 사례 gold에만 적용한다.
5. 연구원 피드백은 정답 매핑 오류, 규정 해석 보완, 일반 구현 오류, 해석 불명의 네 종류로
   먼저 분류한다.
6. 규정 해석 보완은 v2 또는 승인된 일반 가이드가 갱신되기 전 런타임 코드에 넣지 않는다.
7. 사례별 숫자·문장·광고 ID·파일명·정답을 검색 또는 판정 코드에 하드코딩하지 않는다.

## 2. 파서와 입력 계약

1. P1 `nh-ad-review-evidence-v6`와 P3 `nh-ad-review-region-input-v1`을 결합한다.
2. P2라는 별도 산출물은 사용하지 않는다.
3. RAG 직전 정본은 `nh-ad-review-integrated-input-v1`이다.
4. coarse/fine은 정본 입력이 아니라 검색용 투영본이다.
5. 파서는 region별 최종 판독문 하나를 제공한다. OCR/VLM 복수 후보 선택을 RAG로 넘기지 않는다.
6. P1/P3 텍스트 동일성과 line partition을 검증하고 불일치하면 조용히 진행하지 않는다.
7. 시인성·bbox·글자 크기·대비 계산은 파서 책임이며 RAG는 값을 전달받아 사용한다.

## 3. 라우팅과 템플릿

1. 상품군 하드 필터는 `provided|verified|confirmed` 값만 사용한다.
2. 파일명은 provenance와 약한 추정값으로만 보존하며 확정 필터가 아니다.
3. 파서 template/gubun/label은 추적·순위 보조값이며 검색 제외 게이트가 아니다.
4. 확인된 template 또는 subtype과 정확히 일치할 때만 해당 T 규칙을 전개한다.
5. 템플릿 미확정이면 T 규칙은 보류하지만 상품군에 맞는 일반 C/D 검색은 수행한다.
6. 템플릿 필수여부 `O`와 조건부 `△`를 구분한다.

## 4. 검색과 청킹

1. 광고 원문 region 전체를 coarse로 보존한다.
2. 불릿·하위 불릿·길이 경계의 fine 청크를 검색에 함께 사용한다.
3. parent-child 관계와 원본 line_ref를 보존한다.
4. 규칙 발견은 BM25와 BGE-M3 결과를 RRF로 결합한다.
5. 금지 후보의 리랭커는 순위만 바꾸며 점수 임계치로 후보를 삭제하지 않는다.
6. 광고 라벨이 미배정이어도 광고 전체 영역은 검색 가능해야 한다.
7. 규칙별 근거 재검색은 최초 hit를 버리는 단계가 아니라 충분한 판정 문맥을 구성하는 단계다.

## 5. 판정

1. 적용성과 최종 판정을 분리해 출력한다.
2. 규제목록 v2 입력요건으로 TEXT, PARTIAL, EXTERNAL을 구분한다.
3. PARTIAL은 확인 가능한 부분만 판단하고 전체 충족으로 확정하지 않는다.
4. EXTERNAL은 필요한 입력이 없으면 사람 검토로 보낸다.
5. 좁은 검색 창이나 불완전 파싱으로 부재를 확정하지 않는다.
6. 완전한 광고 전문에서 적용 가능한 표시의무가 실제 누락되면 판단불가로 후퇴하지 않는다.
7. 심의필 자리표시 값은 사전심의 맥락에서 형식 존재로 인정할 수 있다.
8. 불릿 기호·날짜 표기 등 표현 형식은 의미가 같으면 특정 문자 완전일치를 강제하지 않는다.
9. 위반과 판단불가는 자동 확정하지 않고 연구원 검토 대상으로 남긴다.
10. 모델 출력 오류는 정상 쌍을 보존하고 실패 쌍만 재호출한다.

## 6. 다상품·다광고

1. 같은 광고의 분할 파일은 한 `ad_id` 아래 여러 asset/page로 묶는다.
2. 서로 다른 광고는 각각 독립 job으로 실행한다.
3. 다상품 광고는 `products[]`, 상품별 evidence, shared evidence를 분리한다.
4. 결과 키는 `(ad_id, product_id, item_id)`다.
5. 상품마다 다른 template을 가질 수 있다.
6. 여러 광고를 한 프롬프트에 섞지 않고 GPU worker와 동적 배치로 병렬화한다.
7. 연관 광고는 `review_case_id`와 관계 종류가 업무적으로 확정된 경우에만 연결한다.
8. 앞 광고의 판정을 뒤 광고의 정답으로 복사하지 않는다.

## 7. 평가

1. 운영은 item ID 정답을 받지 않고 규칙을 발견해야 한다.
2. 답지 생성의 전수 규칙 전개와 운영 검색 Recall을 혼동하지 않는다.
3. 예측을 먼저 고정하고 별도 평가기가 gold와 조인한다.

5. 피드백을 본 데이터는 dev/regression이고 최종 성능은 새 holdout에서만 잰다.
6. 출력 계약 통과율, 모델 confidence, 시연 화면 숫자는 성능지표가 아니다.

## 사용자 결정: 결과 3종·사람 확인 통합·후보 실행 제한 제거 — 2026-09-16

메인 결과는 위반·판단불가·충족만 표시한다. 다른 템플릿 소속 항목은 목록·집계에서 제외하고 원저장 감사만 유지한다. 실제 NOT_APPLICABLE은 적용 제외 내역(excluded_rows)에 사유와 함께 보존하며 메인 카드·필터에 미해당을 두지 않는다. 적용성 미확정인 추가 v2 후보와 시인성/외부 자료/구조 확인은 모두 판단불가 목록·집계에 포함한다. 동일 scope/item의 보류는 중복 집계하지 않는다. 텍스트 충족에 필수 사람 확인이 남으면 전체 판단불가로 표시하고 자동 텍스트 결과를 automated_assessment에 보존한다. 이미 확인된 위반은 유지하며 남은 확인 사유를 함께 표시한다.

후보 개수 상한으로 규칙을 자르던 과거 방식은 사용하지 않는다. 현행 실행기는 출처 승인 티어로 정식 범위를 먼저 정해 `TEMPLATE_PRIMARY`, `MEDIA_CONDITIONED_V2`, 원문 결합·검색 발동형 `PRODUCT_CONTENT_CONDITIONED_V2`와 관계 의존 규칙을 판정한다. 시인성 규칙은 검색 후보와 근거를 유지하되 사람 검토로 보낸다. 나머지 `MAPPED_V2`, `GENERAL_V2_PRESENCE`, `SUPPLEMENTAL_V2`는 기존 역할에 따라 보강·평가 또는 발견 감사 후보로 보존한다. 용도가 사라진 `prohibition_max_candidates` 설정과 CLI는 제거했으며, 동시 실행 수·요청 배치 크기·reranker 범위는 처리 순서와 자원 관리에만 사용한다. 처리 실패를 충족·미해당·정상 완료로 숨기지 않는다.

workspace/export에 excluded_rows와 execution_omissions를 추가하며 review_candidate_rows/deferred_rules는 빈 호환 배열로 유지한다. 사람 확인은 manual_review_reasons와 실제 점검 제목/질문을 반환한다. 과거 파일에 제목이 없으면 검토 시 동결한 SHA와 동일한 규정 파일 및 저장 템플릿 카탈로그에서 표시 메타데이터만 보충한다. 버전 불일치면 현재 규정으로 바꾸지 않는다. 원저장·모델 판정·source_results는 변경하지 않는다. 과거 후보 실행 누락이 있다면 판단불가와 재처리 필요 경고로 드러내며 자동 완료로 표시하지 않는다.

양성/음성/경계 회귀는121개 검색 후보 보존, 미선택 제외, 사람 확인/적용성 미확정 통합, 위반 유지, 텍스트 충족 보류, 중복 제거, 상품별 scope 분리, 실제 미해당 별도 내역, 옛 실행 누락 경고, 원본 불변, 동결 출처 해시 일치/불일치를 포함한다. 광고 전체 재심의·모델 호출 없이 저장 결과를 대조한다.

## spark-1118 및 nh-parser-fin 계약 — 2026-09-22

- fc87 검색 볼륨을 복제하지 않고 spark-1118에서 같은 모델과 정본 규칙으로 임베딩 인덱스를
  재생성한다. 인덱스명에는 카탈로그·벡터 입력 해시를 포함한다.
- 웹/RAG Python 3.11과 nh-parser-fin Python 3.13은 같은 환경에 설치하지 않는다. 운영 이미지에
  두 런타임을 분리하고 파서는 명시된 3.13 실행 파일로 호출한다.
- nh-parser-fin P1 v3/P3 v6에서 P3는 심의용 텍스트·region 선택, P1은 원문 line·bbox 정본이다.
  두 산출물은 `(doc_id, page_no, region_id)`로만 결합한다.
- bbox는 PaddleX layout 또는 OCR/PDF line이 만든 원본 페이지 픽셀 좌표만 신뢰한다. VLM은
  bbox를 생성하거나 교정하지 않는다. selected_text가 P1 line 결합과 다르면 region-level
  provenance로 표시한다.
- parser-fin이 추론한 상품/템플릿 라벨은 운영 접수에서 사용자가 확정한 템플릿을 덮어쓰지
  않는다. P1/P3 내부 관찰이 서로 다르면 실패시키고, 같더라도 검색·판정의 하드 게이트로
  승격하지 않는다.
- 다상품 문서의 상품별 템플릿 보조 추론은 문서 전체 파일명이 아니라 해당 상품명과 그 상품에
  소유된 region만 사용한다. 다른 상품의 세부유형 문자열을 현재 상품의 조건으로 섞지 않는다.
- 실제 광고 스모크, 컨테이너 이미지 빌드, 상태 사본 해시 대조가 끝나기 전에는 기존 운영
  설정과 주소를 1118로 전환하지 않는다.
- 활성 추가규제32건의 범위 분류는 상품조건, 매체조건, 상품+매체, 전상품 내용조건, 시각
  사람검토를 별도 열로 유지한다. `전상품`은 무조건 실행이 아니라 광고 내용 발동조건을
  먼저 검사한다.
