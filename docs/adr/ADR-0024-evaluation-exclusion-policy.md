# ADR-0024: 평가 제외 기준

## 상태

Accepted

## 배경

PoC KPI는 항목 단위로 산출한다. 그러나 OCR 판독 불가, 상품조건 불명확, 기준자료 미제공처럼 AI 성능과 무관하게 정답 판정 자체가 어려운 샘플 또는 항목이 포함되면 KPI가 왜곡될 수 있다.

반대로 제외 기준이 느슨하면 AI 오답이나 구현 미흡을 평가 제외로 처리해 성능을 과대평가할 위험이 있다. 따라서 평가 제외는 사전 정의된 사유 코드와 담당자 확인을 기준으로 제한한다.

## 결정

OCR 판독 불가, 상품조건 불명확, 기준자료 미제공 같은 정답 판정 불가능 항목은 KPI 분모에서 제외한다.

평가 제외는 다음 원칙을 따른다.

1. 평가 제외 항목은 KPI 분자와 분모에서 모두 제외한다.
2. 제외 사유는 사전 정의된 코드로 기록한다.
3. 제외 여부와 제외 사유는 평가 결과와 PoC 결과보고서에 표시한다.
4. AI가 놓친 항목, 잘못 판단한 항목, 근거를 잘못 매칭한 항목은 평가 제외가 아니라 오답으로 처리한다.
5. 제외 여부가 애매하면 기본값은 평가 포함이며, 담당자 확인 후 제외할 수 있다.

상세 제외 기준은 `docs/poc-evaluation-exclusion-criteria.md`를 기준으로 한다.

## 제외 사유 코드

| 코드 | 의미 | KPI 처리 |
| --- | --- | --- |
| `OCR_UNREADABLE` | ADR-0053 기준 OCR/Parser confidence `< 0.50`이고 판정에 필요한 텍스트를 식별할 수 없음 | 분모 제외 |
| `PRODUCT_CONDITION_AMBIGUOUS` | 상품조건, 약관, 금리, 수수료 등 판단 기준이 불명확 | 분모 제외 |
| `REFERENCE_NOT_PROVIDED` | 관련 법령, 내규, 내부 가이드라인, 매뉴얼이 제공되지 않아 근거 판정 불가 | 분모 제외 |
| `SOURCE_FILE_CORRUPTED` | 원본 파일 손상, 암호화, 페이지 누락 등으로 분석 불가 | 분모 제외 |
| `LABEL_UNCLEAR` | 담당자 정답지 또는 판단 기준이 상충하거나 불명확 | 분모 제외 |
| `DUPLICATE_SAMPLE` | 동일 광고물 또는 동일 평가 항목이 중복 등록되어 대표 샘플만 평가 | 분모 제외 |
| `OUT_OF_SCOPE` | PoC 합의 범위를 벗어난 상품군, 광고유형, 매체 | 분모 제외 |

## 제외하지 않는 항목

다음은 평가 제외 사유가 아니다.

| 항목 | 처리 |
| --- | --- |
| AI가 위험 표현을 탐지하지 못함 | 오답 |
| AI가 필수 문구 누락을 놓침 | 오답 |
| AI가 무관한 근거를 제시함 | 오답 |
| AI가 위험도를 과대 또는 과소 산정함 | 오답 또는 부분 정답 |
| 문서 형식이 불규칙하지만 사람이 판정 가능함 | 평가 포함 |
| 내부 가이드라인 형식이 엄격하지 않음 | 평가 포함, 필요 시 부분 정답 또는 확인 필요 |

## 제외 승인 기준

평가 제외는 다음 방식으로 처리한다.

| 단계 | 처리 |
| --- | --- |
| 1 | 시스템 또는 평가자가 제외 후보를 표시한다. |
| 2 | 제외 사유 코드를 선택하고 상세 사유를 입력한다. |
| 3 | 고객사 담당자 또는 PoC 평가 책임자가 제외 여부를 확정한다. |
| 4 | 평가 실행 시 `excludeInvalidSamples=true`이면 확정 제외 항목을 분모에서 제외한다. |
| 5 | 평가 결과에는 제외 건수와 사유별 집계를 표시한다. |

PoC에서는 고객사 담당자를 제외 승인권자로 둔다. 내부 사전 점검 단계에서는 프로젝트 평가 책임자가 후보를 표시할 수 있다.

단순 Annotation 위치 신뢰도 부족은 평가 제외가 아니라 ADR-0051/ADR-0053 기준 화면 표시 상태로 처리한다.

## 대안

| 대안 | 판단 |
| --- | --- |
| 제외 없음 | 산식은 단순하지만 OCR 불가나 기준자료 미제공처럼 판정 불가능한 샘플이 KPI를 왜곡한다. |
| 사전 정의 기준으로 제외 | 일관성과 추적성이 높지만 사유 코드 관리가 필요하다. |
| 담당자 협의 후 제외 | 실무 판단을 반영할 수 있지만 기준이 없으면 임의성이 커진다. |
| 사전 정의 기준 + 담당자 확정 | 기준과 실무 판단의 균형이 좋다. |

## 결정 근거

- PoC KPI는 AI 성능을 평가해야 하며, 자료 품질이나 기준자료 미제공 문제를 AI 오답으로만 처리하면 평가가 왜곡된다.
- 제외 사유를 코드화해야 평가 결과에서 제외 비중을 투명하게 설명할 수 있다.
- 제외 기준이 없으면 샘플 수가 줄어들 때 KPI 신뢰도가 낮아진다.
- AI 오답을 제외 처리하지 않는 원칙을 명시해야 성능 과대평가를 방지할 수 있다.

## 영향

- 검증 데이터셋과 판단 결과에는 제외 여부, 제외 사유 코드, 제외 상세 사유, 제외 승인자를 저장해야 한다.
- 평가 API와 DB는 제외 사유별 집계를 포함한다.
- PoC 결과보고서는 KPI 점수와 함께 평가 대상 수, 제외 수, 제외 사유별 건수를 표시해야 한다.
- 테스트케이스는 제외되는 항목과 제외되지 않는 오답 항목을 모두 검증해야 한다.

## 후속 조치

- `docs/poc-evaluation-exclusion-criteria.md`를 구현 기준으로 유지한다.
- API 명세에 제외 사유 코드와 사유별 집계 필드를 유지한다.
- DB 명세에 제외 사유 코드와 승인자 필드를 유지한다.
- 테스트케이스에 제외 사유별 처리와 오답/제외 구분 검증을 유지한다.
- 평가 제외 여부와 사유는 ADR-0074 기준 평가 실행 snapshot에 포함해 과거 평가 결과를 불변으로 유지한다.
