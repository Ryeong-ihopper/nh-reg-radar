# ADR-0004: Git, Notion, Wiki 역할 분리

## 상태

Accepted

## 배경

프로젝트 문서는 개발자, 기획자, 고객사 담당자, AI 도구가 함께 참조한다. 문서 위치가 분산되면 어느 문서가 최신 기준인지 혼란이 생길 수 있다.

특히 요구사항, 기능, 화면, API, DB, 테스트 명세는 구현과 직접 연결되므로 변경 이력과 리뷰가 가능한 저장소에서 관리되어야 한다.

## 결정

Git으로 관리되는 `docs/` 하위 명세 문서를 개발자들이 공유하는 Source of Truth로 사용한다.

역할은 다음과 같이 분리한다.

| 도구 | 역할 |
| --- | --- |
| Git `docs/` | 개발 기준 명세 원본. 요구사항, 기능, 화면, API, DB, 테스트, ADR 관리 |
| Notion | 칸반, 일정, 회의록, 작업 상태 공유 |
| Wiki | 운영 가이드, 배포 절차, 장애 대응, 사용자 안내가 필요할 때 선택적으로 운영 |

Notion이나 Wiki에 명세와 유사한 내용이 있더라도 개발 판단 기준은 Git `docs/`를 우선한다.

## 대안

| 대안 | 판단 |
| --- | --- |
| Git `docs/`를 기준 문서 원본으로 사용 | 개발 변경과 문서 변경을 함께 추적할 수 있다. |
| Notion을 기준 문서 원본으로 사용 | 비개발자 협업은 쉽지만 코드 변경과 문서 변경이 분리된다. |
| Git, Notion, Wiki에 동일 문서를 병행 관리 | 중복과 불일치 위험이 크다. |

## 결정 근거

- 개발자는 저장소 안의 문서를 바로 참조하고 변경할 수 있다.
- 코드 변경과 명세 변경을 같은 작업 단위로 리뷰할 수 있다.
- AI 개발 도구가 로컬 문서를 기준으로 맥락을 파악하기 쉽다.
- Notion은 칸반과 회의록에 집중하는 편이 역할이 명확하다.

## 영향

- 개발자가 참조해야 하는 최신 명세는 Git `docs/`에 있어야 한다.
- Notion에서 결정된 내용은 필요한 경우 Git 문서로 옮겨야 개발 기준이 된다.
- 고객사 공유본을 Notion 또는 PDF로 만들더라도 개발 기준본과 동기화 책임이 필요하다.
- Wiki는 필수 운영 대상이 아니며, 운영/배포 문서가 필요해질 때 사용한다.

## 후속 조치

- README에 `docs/`가 개발 Source of Truth임을 명시한다.
- Notion 칸반 항목에는 관련 Git 문서 링크를 연결한다.
- 회의에서 결정된 요구사항 변경은 `docs/` 문서와 ADR에 반영한다.
