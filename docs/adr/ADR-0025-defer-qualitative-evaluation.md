# ADR-0025: 정성 평가 보류 및 담당자 피드백 대체

## 상태

Accepted

## 배경

PoC 검증은 정량 KPI와 함께 업무 적용 가능성, 설명 이해도, 문구 추천 유용성 같은 정성 요소를 확인할 필요가 있다. 다만 설문, 인터뷰, 시스템 내 피드백 기능을 모두 정식 평가 체계로 구현하면 PoC 범위와 운영 부담이 커진다.

현재 우선순위는 정량 KPI 산식, 평가 제외 기준, 검증 데이터셋 정합성 확정에 있다. 따라서 정성 평가는 이번 PoC 필수 평가 체계로 두지 않고, 담당자 피드백 요약으로 대체한다.

## 결정

정성 평가는 일단 보류한다. PoC 단계에서는 상품부서 및 준법감시 담당자의 피드백을 수집해 결과보고서의 참고 의견과 개선 과제로 반영한다.

| 항목 | 결정 |
| --- | --- |
| 설문 기반 정성 평가 | 보류 |
| 인터뷰 기반 정성 평가 | 보류 |
| 시스템 내 피드백 버튼 | PoC 필수 구현에서 제외 |
| 담당자 피드백 | 결과보고서 참고 의견으로 반영 |
| KPI 점수 반영 | 반영하지 않음 |
| 추후 재검토 | 본사업 전환 또는 PoC 후속 단계에서 재검토 |

담당자 피드백은 정량 KPI를 대체하지 않는다. PoC의 공식 성능 판단은 ADR-0023의 KPI 산식과 ADR-0024의 평가 제외 기준을 따른다.

## 담당자 피드백 범위

PoC 결과보고서에는 다음 수준의 피드백만 요약한다.

| 항목 | 내용 |
| --- | --- |
| 업무 적용 가능성 | 실제 심의 업무에 도움이 되는지에 대한 담당자 의견 |
| 설명 이해도 | AI 판단 사유와 근거가 이해 가능한지에 대한 의견 |
| 문구 추천 유용성 | 추천 문구가 실무 검토에 참고 가능한지에 대한 의견 |
| 화면 사용성 | 문제 위치, 근거, 리포트 확인 흐름에 대한 의견 |
| 개선 필요사항 | 본사업 전환 또는 후속 PoC에서 보완할 과제 |

피드백은 정량 점수화하지 않고 주요 의견, 반복적으로 나온 이슈, 후속 개선 과제로 정리한다.

## 대안

| 대안 | 판단 |
| --- | --- |
| 설문 단독 | 수집은 쉽지만 응답 맥락이 부족하고 문항 설계 부담이 있다. |
| 인터뷰 단독 | 맥락 파악은 좋지만 비교 가능성과 일정 부담이 있다. |
| 설문 + 인터뷰 | 가장 충실하지만 PoC 우선순위 대비 부담이 크다. |
| 시스템 내 피드백 기능 | 운영 데이터 수집에는 좋지만 추가 화면/API/DB 구현 범위가 생긴다. |
| 담당자 피드백 요약 | 구현 부담이 낮고 결과보고서 개선 과제 도출에는 충분하다. |

## 결정 근거

- 현재 PoC의 핵심 검증 축은 정량 KPI와 평가 제외 기준이다.
- 정성 평가를 공식 체계로 만들면 설문 문항, 응답자 모집, 인터뷰 운영, 집계 기준이 추가로 필요하다.
- 담당자 피드백은 본사업 전환 판단과 개선 과제 도출에는 충분한 참고 자료가 될 수 있다.
- 피드백을 KPI에 합산하지 않아 정량 성능 평가의 해석을 흐리지 않는다.

## 영향

- PoC 필수 구현 범위에 별도 정성 평가 API, 설문 화면, 인터뷰 관리 기능을 포함하지 않는다.
- 결과보고서에는 담당자 피드백 요약과 개선 과제를 포함한다.
- 요구사항과 기능명세에서 “정성 평가 결과”를 필수 산출물로 표현하지 않는다.
- 본사업 전환 또는 후속 PoC에서 정식 정성 평가 체계 도입 여부를 재검토한다.

## 후속 조치

- 기능명세서와 요구사항 정의서의 정성 평가 표현을 담당자 피드백 수준으로 낮춘다.
- 화면설계서의 성능 평가 화면은 담당자 피드백 요약 영역만 둔다.
- 정식 설문/인터뷰/피드백 버튼 도입은 추후 별도 ADR로 재검토한다.
