# ADR-0084: Python 3.11 및 DGX·H200 이중 GPU 실행 프로필

| 항목 | 내용 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-09-10 |
| 관련 문서 | 프로젝트 규칙, 기능명세서, RAG 파이프라인, 인수인계 |
| 관련 ADR | ADR-0014, ADR-0061, ADR-0079, ADR-0080, ADR-0081 |

## 배경

고객사 DAP는 Python 3.11로 고정되어 있고 제공 라이브러리도 항상 최신 버전이 아니다.
최종 모델 실행 장비는 H200이지만 중간 개발·보고는 DGX Spark에서 계속 수행해야 한다.
기존 애플리케이션은 Python 3.12, `document-processor`는 Python 3.13으로 나뉘었고 독립
RAG의 환경변수와 도구 이름은 DGX 장비에 결합되어 있었다.

## 결정

1. 백엔드, 워커, 공용 Python 패키지, 독립 RAG, CI 및 Python 기반 파서 서비스의
   기준 런타임을 `>=3.11,<3.12`로 통일한다.
   Python minor version은 같게 하되 PaddleOCR처럼 의존성 충돌이 있는 엔진은 별도
   3.11 서비스 환경을 유지하며 애플리케이션 환경에 합쳐 설치하지 않는다.
2. DAP에 이미 제공되는 공통 라이브러리는 제공 목록의 검증 대상 버전으로 고정한다.
   DAP에 없는 `openpyxl`, `pypdfium2`, `alembic`, `psycopg`, `pypdf`는 별도 제공을
   요청한다. `pytest`와 Ruff는 검증 전용이며 운영 설치 목록에서 분리한다.
3. 중간 실행은 `dgx-interim`, 최종 반입은 `h200-final` 프로필을 사용한다. 두 프로필은
   동일한 입력·검색·판정·출력 계약을 사용하고 주소·인증·동시성만 설정으로 바꾼다.
4. 모델 호출은 `NH_GPU_BGE_ENDPOINT`, `NH_GPU_GEMMA_ENDPOINT`,
   `NH_GPU_GEMMA_MODEL`을 우선 사용한다. 기존 `DGX_*`와 SSH fallback은 중간 보고
   호환을 위해 유지하며 H200에서는 직접 내부 endpoint를 사용한다.
5. GPU 서비스 장애 시 CPU 모델로 조용히 후퇴하지 않는다. 장비 종류는 판정 규칙이나
   평가 결과를 바꾸는 입력으로 사용하지 않는다.
6. LangGraph는 현행 정본 파이프라인이 import하지 않으므로 운영 필수 의존성에 넣지 않는다.
7. ADR-0079의 hybrid parser 구성과 원문 보존 원칙은 유지하되, 그 ADR의 Python
   3.12/3.13 런타임 분리 결정은 본 ADR의 Python 3.11 기준으로 개정한다.

## 검증 및 미검증 경계

- Python 3.11 문법 검사, 잠금 파일 생성, RAG 결정론 게이트, 워커·공용 패키지 및 운영
  웹 테스트를 통과해야 한다.
- DGX와 H200은 동일 합성 요청에 대해 스키마·규칙 쌍·근거 ID 보존 계약을 각각 확인한다.
- PaddleOCR와 `document-processor`의 Python 3.11 이미지 build, health 및 실제 파일 E2E가
  통과하기 전에는 파서 서비스 전환을 완료로 표시하지 않는다.
- PaddleOCR 2.9.1/PaddlePaddle 2.6.2의 Python 3.11 의존성 해석은 가능하지만 NumPy
  1.26.4를 요구하므로 DAP 애플리케이션 환경과 분리한다. `document-processor` 고정
  GitHub source는 접근 가능한 내부 mirror 또는 패키지 제공 후 다시 검증한다.
- H200 endpoint·모델 이름·동시성 값은 고객사 비공개 설정으로 주입하고 저장소에 실제
  내부 주소나 인증정보를 기록하지 않는다.

## 영향

- Python 버전 차이로 인한 DAP 반입 오류를 줄이고 DGX 중간 결과와 H200 최종 결과를
  같은 계약으로 비교할 수 있다.
- 기존 3.12/3.13 이미지와 잠금 파일은 더 이상 현행 기준이 아니다.
- 외부 파서 패키지가 Python 3.11을 지원하지 않으면 해당 엔진 버전 교체 또는 서비스
  계약을 유지한 별도 대체 구현이 필요하며, 검증 없이 성공으로 간주하지 않는다.

## 검토 대안

| 대안 | 판단 |
| --- | --- |
| 기존 Python 3.12/3.13 분리 유지 | DAP Python 3.11 고정 환경과 달라 제외 |
| H200 전용 코드를 별도 복제 | 중간 DGX 결과와 최종 결과의 계약 drift 위험으로 제외 |
| Python 3.11 공통 코드와 장비별 설정 프로필 | 동일 계약을 유지하면서 두 환경을 지원하므로 채택 |

## 후속 조치

- DGX에서 3.11 프로필 대표 광고 운영형 E2E를 다시 실행한다.
- 고객사 H200 endpoint가 확정되면 같은 입력 snapshot으로 계약 비교를 수행한다.
- PaddleOCR와 `document-processor` 이미지를 빌드하고 health·실파일 E2E를 기록한다.
- DAP에 없는 운영 패키지의 반입 버전과 checksum을 고객사와 확정한다.
