# ADR-0031: AI 활용 개발 및 검증 책임

## 상태

Accepted

## 배경

본 프로젝트는 명세 기반 개발을 원칙으로 하며, 문서 작성, API/DB 설계, 백엔드, 프론트엔드, 테스트, 리팩토링 과정에서 AI를 활용할 수 있다. AI를 활용하면 PoC 구현 속도를 높일 수 있지만, AI 산출물을 검증 없이 병합하면 보안, 권한, 데이터 정합성, 평가 산식, 고객사 자료 처리에서 리스크가 커질 수 있다.

기존 개발 방침은 AI를 적극 활용하되 최종 책임은 개발자에게 둔다고 정의하고 있다. 이를 ADR로 확정해 AI 활용 범위와 검증 책임을 명확히 한다.

## 결정

AI를 풀스택 개발에 적극 활용한다. 단, AI가 생성한 산출물은 초안으로 간주하며 최종 품질, 보안, 정합성 책임은 담당 개발자에게 있다.

AI 생성 코드와 문서는 사람이 작성한 산출물과 동일한 검증 기준을 통과해야 한다.

| 구분 | 결정 |
| --- | --- |
| AI 활용 수준 | 적극 활용 |
| AI 산출물 지위 | 초안 |
| 최종 책임 | 담당 개발자 |
| 병합 기준 | AI 사용 여부가 아니라 검증 완료 여부 |
| 고객사 자료 입력 | ADR-0002의 외부 AI 입력 정책 준수 |

## 허용 범위

AI는 다음 작업에 활용할 수 있다.

| 영역 | 허용 작업 |
| --- | --- |
| 문서 | 요구사항 정리, 기능명세/API/DB/테스트 문서 초안, ADR 초안 |
| 백엔드 | API handler, schema, service, repository, migration 초안 |
| 프론트엔드 | 화면 skeleton, 컴포넌트 초안, API 연동 초안, 테스트 초안 |
| AI/RAG | parser/OCR adapter 초안, prompt/config 초안, 평가 fixture 초안 |
| 테스트 | unit/API contract/e2e 테스트 초안, edge case 제안 |
| 품질 | 리팩토링 제안, 코드 리뷰 보조, 오류 원인 분석 |

## 필수 검증 기준

AI가 생성했거나 AI 도움을 받은 산출물은 다음 기준을 통과해야 한다.

| 검증 | 기준 |
| --- | --- |
| 명세 정합성 | 요구사항, 기능명세, API 명세, DB 명세, 테스트케이스와 불일치하지 않아야 함 |
| 코드 품질 | lint, type check, formatting 기준 통과 |
| 테스트 | 변경 범위에 맞는 unit, API contract, e2e 또는 수동 검증 수행 |
| 보안 | secret, token, 개인정보, 승인되지 않은 고객사 원문 자료 포함 금지 |
| 문서 동기화 | API/DB/화면/테스트 계약 변경 시 관련 문서 함께 갱신 |
| 리뷰 | 담당 개발자가 변경 내용을 이해하고 설명할 수 있어야 함 |

## 고위험 영역

다음 영역은 AI 산출물을 그대로 병합하지 않고 담당 개발자 리뷰를 필수로 한다.

| 영역 | 필수 확인 |
| --- | --- |
| 인증/권한 | 권한 우회, 타 부서 데이터 접근, 관리자 기능 보호 |
| 감사 로그 | 기록 범위, 민감정보 저장 여부, 추적 ID |
| 파일 접근 | 다운로드 권한, presigned URL, object key 노출 |
| DB migration | schema, FK, unique constraint, data migration, rollback 가능성 |
| KPI/평가 산식 | 분모/분자, 제외 기준, 오답 처리 |
| 위험도 산정 | rule priority, HIGH/MEDIUM/LOW 판단 기준 |
| 외부 AI 입력 | 고객사 승인 샘플 범위, 개인정보/비밀값 포함 여부 |
| prompt/config | 출력 schema, fallback, safety rule, version 기록 |

## PR 기준

PR은 AI 활용 여부만으로 승인하거나 거절하지 않는다. 다음을 기준으로 판단한다.

- 변경자가 산출물 내용을 이해하고 설명할 수 있다.
- 필요한 테스트와 수동 검증을 수행했다.
- API, DB, 화면, 테스트 문서가 동기화되어 있다.
- 고객사 자료와 secret이 외부 AI 또는 repository에 잘못 포함되지 않았다.
- 고위험 영역은 담당 개발자 또는 리뷰어가 명시적으로 확인했다.

## 대안

| 대안 | 판단 |
| --- | --- |
| AI 적극 활용 + 개발자 최종 책임 | PoC 속도를 확보하면서 검증 책임을 명확히 할 수 있다. |
| 문서/테스트 초안까지만 AI 활용 | 통제는 쉽지만 개발 속도 이점이 크게 줄어든다. |
| 코드 생성은 허용하되 핵심 도메인은 제한 | 위험 영역 통제는 가능하지만 핵심 범위 판단이 애매해질 수 있다. |
| AI 코드 생성 제한 | 보수적이지만 현재 PoC의 생산성 목표와 맞지 않는다. |

## 결정 근거

- 본 프로젝트는 문서와 ADR을 Git에서 source of truth로 관리하므로 AI 산출물을 명세에 맞춰 검증할 수 있다.
- FastAPI, OpenAPI, TypeScript, 테스트 자동화 기준을 이미 정했으므로 AI 생성 코드도 동일한 품질 게이트에 태울 수 있다.
- 고객사 샘플 데이터 외부 AI 입력 정책은 ADR-0002에서 별도로 통제한다.
- 생산성 이점을 얻으려면 AI 코드 초안 활용을 허용하되, 병합 책임을 사람에게 명확히 두어야 한다.

## 영향

- PR 작성자는 AI 도움을 받은 변경도 일반 변경과 동일하게 검증해야 한다.
- 리뷰어는 AI 사용 여부보다 명세 정합성, 테스트, 보안, 문서 동기화를 확인한다.
- 고위험 영역 변경은 담당 개발자 리뷰와 검증 기록이 필요하다.
- AI 활용으로 생성된 문서/코드도 ADR과 명세의 우선순위를 따른다.

## 후속 조치

- PR 템플릿에 AI 산출물 검증 체크 항목을 추가한다.
- 개발 방침 문서에 ADR-0031 링크와 고위험 영역 검증 기준을 연결한다.
- 구현 단계에서 lint/type/test/API contract 검증 명령을 CI에 반영한다.
